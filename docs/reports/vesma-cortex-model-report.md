# vesma-cortex-v1: обучение и калибровка — от брифинга до ADOPT

- **Статус:** вердикт ADOPT по замороженному препрегу v2 + аддендум 2; прогон A5 — 2026-10-01 06:38 UTC
- **Окно работ:** 2026-09-29 … 2026-10-01 (два дня от брифинга владельца до вердикта)
- **Тип документа:** продуктовый пруф — накапливает доказательства для продвижения; каждое число проверено прогонами и фингерпринтами

## Executive summary

**Вердикт ADOPT.** Локальная модель решений vesma-cortex-v1 решает одну задачу — `is-duplicate(a, b)`: пара записей памяти → типизированный вердикт `Noul` {question, probability} + Score-плейсхолдер. Это не LLM и не генерация текста: узкая специализированная модель класса «System One» (как Jev, но своя). Модель обучена только на train-700; holdout из 300 пар запечатан до обучения и ей не показывался ни разу; single-shot оценка превзошла действующую эвристику движка по всем шести замороженным критериям одновременно.

| Показатель (holdout 300, single-shot) | Значение |
|---|---|
| Условия замороженного decision rule | **6 из 6 выполнены → ADOPT** |
| Sensitivity (recall по дубликатам) | **1.0** (150/150) |
| Specificity | **0.98** (3 ошибки из 150) |
| Balanced accuracy | **0.99** — против 0.81 у baseline движка |
| Brier | **0.0053** (требование ≤ 0.25) |
| Типизированность / record-quality полнота | 1.0 / 1.0 (NO-DATA-плейсхолдер) |
| Артефакт | одиночный ONNX **97 738 байт**, ноль сети, Δdeps движка = 0 |

Отрыв от baseline строгий: на тяжёлых template-twin-негативах (косинус до 0.97) действующая эвристика зовёт дубликатами десятки пар, модель ошибается на трёх. Прегистрация (canon main `8b24212`) запушена ДО прогона — порядок доказан коммит-датами.

## Задача и роль в продукте

Движку нужен советник дедупликации: при добавлении записи подсказывать, что входящее дублирует уже существующую. Решение о слиянии всегда остаётся за движком/владельцем — модель не автономный исполнитель.

Контракт задачи:

- вход — пара записей (canon-state: конверт + тело, собранный по правилу 2 ADR 0004 движка);
- выход — типизированный вердикт `Noul` {question, probability} + Score-плейсхолдер; совместим с интерфейсом decision-провайдера (ADR 0004 канона);
- класс — «System One»: калиброванные типизированные решения без генерации текста, тот же класс, что Jev.

Продуктовая рамка из чартера: инференс локальный, ноль сети, веса на машине владельца; записи не покидают машину.

## Архитектурное решение

### Двухкандидатная лестница (АрхКом A1, ADR 0001)

Отбор внутренний; на оценку A5 едет лучший кандидат, при сомнении — D.

| Кандидат | Архитектура |
|---|---|
| **D** | градиентный бустинг (LightGBM) над 13 замороженными фичами пары: целевой косинус, char 3–5-грамм jaccard/containment RU+EN, tag-jaccard, дельты метаданных; Platt-калибровка в графе |
| **N** | MLP ≤ 0.5M параметров над `[a, b, \|a−b\|, a⊙b]` (4×384) + скаляры; опциональный corruption-претрейн |

Протокол отбора: stratified 5-fold × 20 фиксированных сидов; метрики — balanced accuracy и Brier (mean±std). N едет дальше только при превосходстве больше 1 std repeat-spread по ОБЕИМ метрикам (BA выше, Brier ниже).

### Почему бустинг победил

- Статистика данных: 140–700 пар — объём, требующий низкой дисперсии, а не выразительности; деревья — родная среда для такого объёма.
- Фиче-семейство «локальная расходимость при глобальной близости» бьёт точно в главный урок калибровки W4c: близнецы со сломанным полем — высокий косинус при семантической разнице.
- Отвергнутые альтернативы: cross-encoder (без своего энкодера вырождается в лёгкую голову, с внешним — противоречит «архитектуре с нуля»), transformer с нуля (корпус не тянет LM-претрейн), GNN-подобные подходы — все по одной причине: статистика данных.

Отбор подтвердил расчёт: D лидировал на всех трёх стадиях данных, на финальной его отрыв от лучшего N достиг 5.4 п.п.

## Данные: структурное открытие и три стадии

### Открытие: в живом сторе нет семантических дубликатов

Исходный дизайн корпуса (косинус-страты по живому стору) дал 196 пар not_duplicate и **0 позитивов**: движок уже вычистил дубликаты собственной дедупликацией. Это структурный NO-DATA по этажам препрега — позитивы пришлось строить, а не искать. Разметка зафиксирована трёхпроходно (GLM-писатель + jev-router + чистый Jev) с единогласием 192/192 и спот-чеком владельца.

### Три стадии корпуса

| Стадия | Объём | Состав | CV: D (BA / Brier) | CV: N (BA / Brier) |
|---|---|---|---|---|
| 1. Синтетика | 1350 пар | LLM-генерация с метками-по-построению, 4 стратегии | 0.9774 / 0.0165 | 0.9690 / 0.0176 (с претрейном) |
| 2. Реальные пары | 276 | 196 ратифицированных владельцем негативов + 80 конструктивных дубликатов | 0.9922 / 0.0057 | 0.9915 / 0.0090 |
| 3. dataset1000 | 1000 | 500 позитивов + 500 негативов из реальных гигиеничных записей | 0.9844±0.0027 / 0.0149 | 0.9301 / 0.0482 (лучший) |

Конструктивные дубликаты стадии 2 созданы специалистом-агентом и верифицированы обоими Jev'ами 80/80 (native mean noul 0.976). Фингерпринты корпусов зафиксированы: синтетика `621cb23f…`, ds1000 `7252b2f5…` (train-700 — `beea9355…`).

Траектория corruption-претрейна N — честная, без ретуши:

- на синтетике претрейн дал N **+2.65 п.п.**;
- на реальных 276 парах абляция инвертировалась — претрейн перестал помогать;
- на train-700 вклад исчез: 0.9301 (с претрейном) против 0.9286 (с нуля) — в пределах шума.

Всё — из реальных гигиеничных записей стора; в репу не попало ни одной сырой строки.

### Валидация двойным референсом

Каждую из 1000 пар оценили два независимых верификатора. Чистый Jev оценил все 1000/1000 и разнёс классы 515/485 — почти ровно проектные 500/500. Jev-роутер согласился с разметкой на 870/1000.

Семь конфликтов решил арбитраж TL с дифф-доказательствами:

- **6 broken-field подмен подтверждены** — роутер попался в текстовую ловушку «одинаковый текст = дубликат», калиброванный Jev распознал подмены;
- **1 ложный негатив обоих верификаторов исправлен** — sim 0.955, чистый перефраз.

Все 1000 пар удержаны в корпусе. Сплит выполнен ДО обучения: 700 train (350/350) / 300 holdout; holdout запечатан id-манифестом (seed 7) — модель его никогда не видела.

## Сравнение с Jev: три измерения

### 1. Jev-роутер как decision-провайдер — DECLINE

Внешний Jev-роутер занимал ту же роль в волне W4c канона и получил вердикт DECLINE: согласие с разметкой 3/17 на позитивах, Brier 0.70, в одном прогоне роутер ротировал 3 апстрима (непредсказуемость), требует сеть и API-ключ. vesma-cortex на своей задаче: ADOPT (1.0 / 0.98 / 0.0053) — локально, детерминированно, ноль сети.

### 2. Чистый Jev как независимый верификатор

Чистый Jev (typesafe/jev-1.13, нативный decisions API) использовался не как провайдер решений, а как независимый верификатор разметки:

- подтвердил 80/80 конструктивных дубликатов стадии 2 (mean noul 0.976);
- дал калиброванные оценки на всех 1000 парах dataset1000;
- в 6 broken-field конфликтах оказался прав против роутера — распознал семантические подмены;
- но не всесилен: один light-перефраз оценен 0.30 при истинном duplicate — поэтому финальный судья разметки = консенсус верификаторов + арбитраж.

Стоимость верификации 1000 пар: **$0.0157**.

### 3. Системная позиция: «как Jev, но своя»

| Свойство | Jev | vesma-cortex-v1 |
|---|---|---|
| Класс | типизированные решения с калиброванной вероятностью, без генерации текста | тот же класс |
| Сеть | внешняя (роутер, апстримы) | ноль сети |
| Стоимость | API-ключ, тарификация | локальный, бесплатный |
| Детерминизм | ротация апстримов (урок W4c) | детерминированный |
| Приватность | записи покидают машину | записи не покидают машину |
| Калибровка | на чужих данных | калиброван на СВОИХ данных |

## Артефакт и провенанс

- Формат: одиночный self-contained ONNX **97 738 байт**; feature-логика в графе; sklearn-pickle исключён.
- Зависимости движка: **ноль новых** — onnxruntime уже в core; загрузка паттерном NanoProvider (eager load + smoke-inference).
- Fingerprint весов: sha256 `281bd0fd39bf9935c86a8b32fed68191fa9b7da95a83b53eb10844a5fd100ac7`.
- Fingerprint-цепочка данных: ds1000 `7252b2f5…` → train-700 `beea9355…`; holdout `71d471ca…` и метки `7fe8e617…` побайтово совпали с запечатанными до обучения.
- Дисциплина (ADR-0021 движка): смена весов или эмбеддера = событие перекалибровки по этому же протоколу; провайдер падает громко при смене пина эмбеддера.

## Ограничения

Честный раздел; каждый пункт — граница применимости, а не скрытый дефект.

1. Конструктивные дубликаты легче «диких»: они построены как парафразы существующих записей; «дикие» дубликаты живого стора модель не встречала — их там структурно нет.
2. Корпус доминирован RU/EN сессионно-инженерным контентом; перенос на другие домены не измерялся.
3. Specificity 0.98 — это 3 пропущенных негатива из 150, все на тяжёлых template-twin.
4. Порог применения вердикта выбирает продуктовая волна W5d, не артефакт: модель отдаёт калиброванную вероятность, продуктовое правило — за движком.
5. Смена весов/эмбеддера = событие перекалибровки (fingerprint-дисциплина).
6. record-quality — плейсхолдер: полнота 1.0 зафиксирована, содержательный скоринг — NO-DATA, раскрыто честно.
