# ADR 0003: Реестр артефактов модели, релизный цикл и методология оценки

- **Status:** Accepted (АрхКом MR0, 2026-10-03; директива владельца о весах
  в репе — 2026-10-03)
- **Date:** 2026-10-03
- **Протокол:** Архитектурный комитет — фаза MR0 (model release), 2026-10-03
  (team-local)

## Контекст

Директива владельца (2026-10-03): веса модели живут в репе как готовый
артефакт (HF-style); к ним — релизный цикл, методология оценки, CI-конвейер
и документация. До этого дня веса были gitignored (`*.onnx`,
`/artifacts/weights/`), артефакт существовал в двух точках вне контроля
репы: локальные экспорты (`data/stage2/artifact-*/`) и вендоренная копия
в движке (прецедент W5d) — без тегов, без CI, без процедуры допуска/отзыва.

В тот же день методология получила свой основатель-кейс. Sanity-сьют
(#480, main `58885f9`) воспроизвёл инверсию прод-артефакта B2
(`71f0572d…`): **P(dup | запись против самой себя) = 0.0108** при пороге
≥ 0.9 — holdout-метрики ADOPT (sens 0.989) этого не видели, потому что на
поверхности оценки не было ни одной точной self-пары. B2 отозван из всех
трёх точек деплоя, прод переведён на B1 (`beb0a65d…`, sanity-PASS) —
[протокол отзыва](../experiments/b0-escalation.md). Инцидент закрыт без
вреда, но вскрыл отсутствие инфраструктуры, на которой такой отзыв должен
быть рутиной, а не импровизацией.

Сопутствующие факты, проверенные при подготовке ADR:

- бандл весит ~98 КБ — LFS не нужен, git справляется напрямую;
- движок (5.3.0/5.4.0) проверяет `feature_set_sha256`/`embedder_pin`
  вендоренного артефакта, но **байты весов не верифицирует**;
- поле манифеста `sha256` в вендоренном бандле B2 содержит sha256 байтов
  (проверено `sha256sum`: `71f0572d…` совпадает) — предпосылка комитета
  «там уже лежит blake2b-256» не подтвердилась (см. R4).

## Решение

### R1. Реестр артефактов: `models/vesma-cortex-v1/` в git

Канонический дом модели — **эта репа**, каталог
`models/vesma-cortex-v1/` коммитится целиком (`.gitignore` переучивается,
исключение — только тренировочные веса). Состав бандла:

| Файл | Назначение | Размер |
|---|---|---|
| `model.onnx` | веса, self-contained граф (≤ 5 МБ, [inference-v1](../specs/inference-v1.md) §4) | ~98 КБ |
| `manifest.json` | машинные метаданные бандла (§R4, schema 2) | < 1 КБ |
| `MODEL_CARD.md` | человекочитаемая карта — **генерируется** из `eval-results.json` ([model-registry](../specs/model-registry.md)) | — |
| `eval-results.json` | машинный отчёт всех слоёв оценки + вердикт (схема — [model-registry](../specs/model-registry.md)) | — |

`main` держит **один канонический путь** — текущую прод-ревизию. Директории
по фингерпринтам в репе не копятся: история ревизий = git-теги
(`model-v1-<fp8>`, §R3) + GitHub Releases с ассетами `model.onnx`,
`model.manifest.json`, `SHA256SUMS.txt`.

Вендоринг в движок — по фингерпринту при релизе движка (прецедент W5d);
эта репа остаётся домом, движок — потребителем. В CI движка добавляется
тест «sha256 вендоренного `model.onnx` == дайджесту манифеста»: сейчас
движок проверяет `feature_set_sha256`/`embedder_pin`, но байты не
верифицирует. Межрепо-хвост: issue в репу движка (file TL), до его
закрытия байт-верификация живёт на стороне этой репы (release-model.yml).

### R2. Граница приватности (поправка к charter §6)

Граница [чартера](../charter.md) §6 уточняется без послабления ядра:

- **Сырой контент стора — НИКОГДА** (без изменений: ни строки, ни
  фрагмента).
- **МОЖНО в публичную репу:** веса (деревянный бустинг над 13 абстрактными
  фичами пары — инверсия модели ничтожна, она не хранит текст), синтетические
  датасеты на шаблонах, фингерпринты, метрики и отчёты — при гигиена-гейтах:
  секрет-скан, запрет сырых стор-строк, no-federate по дисциплине
  [data-contract](../specs/data-contract.md) §6.
- **Вне репы остаются** реальные стора-корпуса (`data/train-real-full`,
  датасеты B1/B2) — локальные данные владельца, как и прежде.

Этим снимается конфликт «публичная репа (README, решение владельца
2026-09-29) vs веса вне репы»: веса — артефакт, а не данные стора.

### R3. Версионирование: три независимых идентификатора

| Идентификатор | Где живёт | Когда меняется |
|---|---|---|
| semver пакета | `pyproject.toml` (`vesma-cortex`) | API/поведение библиотеки разработки |
| weights fingerprint | sha256 байтов `model.onnx`; короткая форма — первые 8 hex | любое изменение весов = событие перекалибровки (дисциплина ADR-0021 движка) |
| git-теги | `py-vX.Y.Z` (пакет) и `model-v1-<fp8>` (модель, fp8 = 8 hex фингерпринта) | релизный поезд, §R5 |

Линия `model-vN` растёт при **ломающих изменениях**: состав
`feature_set`, схема манифеста, `embedder_pin`. Освежение весов внутри v1
(перекалибровка) остаётся `1.<n>` в метаданных при неизменном каталоге —
[inference-v1](../specs/inference-v1.md) §8.

**Freeze:** ни одного тега `model-v*` до 2026-10-16 (конец B0-окна).
Отзыв B2 на следующий день после его ADOPT подтвердил разумность заморозки:
теги режутся только после P0-фикса экспортного desync и зелёного окна
телеметрии. Короткие id весов — префиксы **sha256** (`281bd0fd`,
`71f0572d`, `beb0a65d` — во всех отчётах, манифестах и проде); blake2b-256
остаётся хеш-семейством только корпусных/дата-фингерпринтов (data-contract
§5) и на веса не переносится.

### R4. Контракт манифеста: schema 2 (исправления до первого тега)

| Правка | Содержание |
|---|---|
| `manifest_schema` | новое поле, значение `2` |
| `sha256` | **остаётся единственным дайджестом весов** (поле честно: содержит sha256 байтов `model.onnx`, сверено 2026-10-03) |
| `weights_path` | выпилить: поле мертво при переезде в реестр (локальные пути вида `data/stage2/artifact-b2/model.onnx` вне раскладки; движок грузит из своей) |

Поправка факта: предпосылка комитета «поле `sha256` уже содержит
blake2b-256» байтами не подтвердилась — там честный sha256 (`71f0572d…`).
Предлагавшееся переименование в `blake2b_256` **отклонено вердиктом TL**:
дайджесты весов всегда были sha256 (все манифесты, отчёты, прод и память
оперируют префиксами sha256), blake2b-256 — семейство только корпусных
фингерпринтов (data-contract §5); переименование дало бы дуализм полей,
миграцию движка (5.3.0/5.4.0 читают старое поле) и правки `cortex.artifacts`,
sanity-сьюта и тестов ради нулевой функциональной выгоды.

### R5. Релизный поезд: два поезда

| | Поезд пакета | Поезд модели |
|---|---|---|
| Триггер | тег `py-vX.Y.Z` | merge PR с весами → тег `model-v1-<fp8>` |
| Гейт | полный сюит CI + коридоры | sanity-сьют на PR (блокирует merge) + verify-джоба на теге |
| Артефакт | wheel **с весами** (реестр внутри пакета) | GitHub Release: `model.onnx`, `model.manifest.json`, `SHA256SUMS.txt` |
| Публикация | PyPI через trusted publishing (OIDC), environment `pypi`, required reviewer = владелец | вендоринг в движок следующим вагоном |
| Локальный fallback | владелец публикует с хоста токеном из `~/.secrets`; токен в GitHub НЕ заливается | — |
| Роллбэк | yank на PyPI | реверндоринг предыдущего фингерпринта |

**ПИН последних 2 хороших бандлов обязателен** — урок отзыва B2→B1 за один
день (2026-10-03): предыдущий ADOPT-артефакт всегда должен быть под рукой
как цель отката, с проверенным sanity-PASS.

### R6. CI-архитектура (по SRE-позиции)

| Workflow | Триггер | Содержание |
|---|---|---|
| `ci.yml` | PR + push main | ruff + format; pytest-матрица 3.12/3.13 (default-env); `make smoke`; job eval-sanity при изменениях `src/**`, `models/**` |
| `nightly.yml` | расписание | test-train + smoke-n, одна ось 3.12 |
| `release-py.yml` | тег `py-v*` | полный сюит → build wheel → publish (environment `pypi`) |
| `release-model.yml` | тег `model-v1-*` | полный сюит + коридоры → пересчёт дайджестов → GitHub Release |

Гейты: **merge = lint + test + smoke + детерминированные инварианты**;
**release = полный сюит + коридоры + environment**. Распределение проб по
слоям — [eval-methodology](../specs/eval-methodology.md) §4.

## Позиции и споры комитета

| Вопрос | Позиции | Решение |
|---|---|---|
| Placement гейтов | **SRE:** семантические пробы (near_boundary/unrelated) блокируют merge — ловить дефект до попадания в main. **Аналитик:** пороговые пробы флейтят на переобученных ревизиях — merge-гейт из них делает ложные блокировки | Merge-блокируют только детерминированные инварианты (bundle_integrity, feature_contract, типизированный выход, self_pair ≥ 0.9, монотонность tol 1e-6). near_boundary/unrelated — release-коридор |
| Заморозка порогов | **Аналитик:** привязать пороги к `feature_set_sha256`, чтобы смена фич меняла и пороги. **SRE:** сцепка неверно цели — пороги грейдят модель, не фичи | `gate_contract.json` со **своим** sha256, НЕ привязан к feature_set; правило «PR с порогами не содержит артефактов и наоборот»; пороги меняются только аддендумом-пререгистрацией; повышение порога в merge-гейт — только директива владельца (прецедент таксономии инвариант/коридор/вердикт — ADR-0026 движка) |
| Локбокс оценки | нужен ли holdout-набор вне всех коммитимых поверхностей | Принят: ~50 пар, другие сиды/темы, в репе только хеш (eval-methodology §5) |
| Реэкспорт без перекалибровки | сжигать ли holdout при реэкспорте неизменных весов | Исключение Layer B: если `weights_sha256` не изменился — эквивалентность 1e-6 на замороженном наборе вместо сжигания holdout |

## Последствия

- `models/vesma-cortex-v1/` появляется в git с ревизией B1 `beb0a65d…`
  (текущий прод) — волна MR-1; B2 в реестр не возвращается, живёт в истории
  отчётов и в [протоколе отзыва](../experiments/b0-escalation.md).
- Хвосты до первого тега `model-v*`: schema-2 в коде (sanity-сьют + тесты),
  `gate_contract.json` в репе, CI-workflows, issue в движок (байт-верификация
  вендоренного onnx), синхронизация текста charter §6 с R2.
- Чеклист волны-шаблона (roadmap §5) дополняется таблицей покрытия
  поверхности; sanity-сьют — уже обязательный шаг ADOPT (с 2026-10-03).
- Freeze тегов модели до 2026-10-16; пакетный поезд (`py-v*`) заморозкой
  не связан, но публикуется только с зелёным CI.
- Каждый ADOPT/отзыв сопровождается записью в `eval-results.json` — история
  модели машиночитаема без археологии по чатам.
