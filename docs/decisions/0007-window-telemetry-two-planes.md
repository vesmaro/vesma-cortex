# ADR 0007 — Телеметрия состава окна: две плоскости сбора, экспортёр вместо нового коллектора

- **Дата:** 2026-10-31 · **Статус:** proposed → MLC раунд 8 (авторский) →
  ратификация v1 · **Надзирающий:** MLC · **Замещает скелет** `59d419c`
  (draft/window-telemetry-spec) в части архитектуры.
- **Контекст:** Layer 0 плана «динамический контекст» (санкционирован
  владельцем 31.10): измерить состав окна модели до обучения какого-либо
  куратора (урок fusion REJECT). Примитивы движка vesma 6.6.0:
  assemble/CCR/context_rewrite/cache_aligner. Слои: L0 → L1 арбитр
  W1–W3 (ADOPT 30.10) → L2 rules-curator → L3 trained curator.

## 1. Решение: две плоскости сбора

**Plane A (память-recall, класс C2) — УЖЕ собирается движком.** Vitals-сайдкар
vesma 6.6.0 (ADR-0026, `src/vesma/metrics/schema.py`: `assemble_metrics`,
`injection_blocks`, `usage_reports`, default-on, TTL 90 дней, firewall
ратифицирован; верифицировано председателем по schema.py). Новый поток
`CORTEX-WINDOW` для C2 — **дубликат, отменяется**. Прототип Plane A =
два артефакта в vesma-cortex, ноль движковых правок:
1. аудит полноты usage-петли (доля assemble-циклов с ненулевым
   `usage_reports` — гейт G0b харнес-пака уже течёт);
2. **экспортёр датасета** `scripts/export_window_dataset.py`:
   read-only `file:…?mode=ro` над сайдкаром, join `assemble_metrics →
   injection_blocks → usage_reports → memories`, фриз в
   `data/stage3/window/` с манифестом+фингерпринтами, secret-scan ДО
   экспорта, каденс еженедельный (TTL сайдкара 90 дней — нефризенное
   теряется).

**Plane B (харнес-окно: C1 системный префикс, C3 tool-outputs, C4 диалог,
C5 запрос) — пост-хок снапшот-экспортёр, не live-обёртка.** Движок эти
классы видеть не может принципиально. Open dependency: формат
zcode-транскриптов (проверка за TL); до верификации C4/C5-census может
отложиться — Plane A самодостаточна для базлайнов L2 по памяти.

## 2. Таксономия (из существующих полей, без классификации контента)

W0 harness_system (только байты/токены, `owned: false`) · W1 pinned_rules
(lane=rules) · W2 memory_recall (+флаги: ccr_expanded, redactions>0,
dup_group по sha256(norm(content)), age_days, in_cache_prefix, content_type (класс W0–W4 события) — derived
поля экспортёра) · W2c хвостовые композиции (awareness-хвост ADR-0035 +
codegraph-beacon, вне budget-блоков) · W3 tool_dialog (source: harness) ·
W4 beacon (бюджетные beacon-блоки; W2c — только внебюджетные хвосты; артефакт классифицируется ровно один раз по месту в окне — без двойного счёта). Единицы: один счётчик токенов на событие
(`estimate_tokens` движка для W1–W4; W0 — оценка харнеса с флагом
`estimator: external`; смешивание в одной сумме запрещено). Дрейф
`tokens(Б) − tokens(А)` между точками съёма — метрика редактуры харнеса.

## 3. Плоскость B: снапшот на границе model-call

Пост-хок экспортёр транскриптов сессий (open dependency §см. выше);
raw-тексты Plane B не пишутся никогда (класс + токены + sha256 + длина);
join с Plane A по `assembly_id`.

## 4. Firewall (проверяемые пункты)

1. Observation-only с зубами: единственный легальный доступ Plane A —
   read-only URI; записывающий хендл = нарушение.
2. Скоуп: только наши сессии; чужие — reject на границе.
3. Тексты: Plane A уже HMAC-анонимизирована; Plane B — без текстов;
   secret-scan на границе фриза, hit → блок строки + no-federate-тег.
4. Ничего наружу (safety-контракт, без исключений).
5. Sampling фиксирован prereg'ом («все вызовы наших сессий»), изменение —
   аддендум до смены.
6. Firewall-якоря: B0-коллектор (counters-not-raw) + vitals-границы;
   append-only; в репу — счётчики/фингерпринты, никаких сырых строк.

## 5. Кэш-инварианты будущего L2 (rules-curator v0 — harness-side policy)

Актюаторы уже существуют (`on_context_rewrite` ADR-0018, `post_tool_call`
CCR). Инварианты: curator трогает только хвост после последнего
cache-breakpoint; тексты injected C2-блоков не переписывает никогда
(provider-owned); CCR-маркеры — защищённые регионы, эвикция переписыванием
маркера запрещена; динамические спаны в префикс не порождаются.
Advisor-not-executor: curator предлагает, harness решает, эвикция только
через lossless-канал.

## 6. Формат: ADR + prereg (не третий жанр спеки)

Спека-телеметрия = этот ADR (архитектура) + `window-dataset-prereg.md`
(датасет L3: схема экспорта, метки-иерархия, полы, гейты, retention).
MLC ратифицирует оба одним голосованием.

## 7. Поезд

Движковая часть L0 не нужна (vitals уже собирает); в минорный поезд vesma
едут только экспортёр + policy-v0 харнес-стороны (обычный harness-пак);
унификация collection-границ с W1–W3 — вопрос будущего пакета. Финально
решает GWS.

## 8. Альтернативы отвергнуты

- Новый поток CORTEX-WINDOW для C2 — дубликат vitals (NA, код-верифицировано).
- Live-обёртка model-call для Plane B — нет проверенной hook-поверхности;
  пост-хок экспортёр честнее и дешевле.
- Отдельная telemetry-spec v1 — третий жанр, дублирующий ADR-жанр и prereg.
