# ADR 0001: ArchCom A1 — архитектура mnema-модели решений и нейминг-онтология экосистемы

- **Status:** Accepted (АрхКом A1, 2026-09-29; оба вопроса приняты с условиями —
  условия и точка владельца по суффиксу артефакта зафиксированы в тексте)
- **Date:** 2026-09-29
- **Протокол:** Архитектурный комитет A1, 2026-09-29 (team-local)

## Контекст

Чартер [A0](../charter.md) закрепил за vesmaro-cortex одну задачу —
`is-duplicate(a, b)` для пар записей памяти — с локальным инференсом и нулём
сети. Оценка заморожена препрегом v2: 200 пар, 7 стратов, holdout 30 %
single-shot как единственное decision-число, 6 метрик, baseline = косинус
0.92; в supervised-распоряжении — около 140 размеченных пар. Обучение живёт в
бюджете Intel Arc 140T, запуск — ранбук → руки владельца. АрхКом A1 разбирал
два вопроса: архитектуру модели и нейминг-онтологию экосистемы.

Read-only инспекция движка и стора (делегат систем) дала факты, определившие
решение:

- onnxruntime >= 1.20 уже входит в core-зависимости движка; torch — только
  training extra, sklearn в движке отсутствует;
- стор хранит эмбеддинги 384-dim float32 unit-normalized за одним
  fingerprint эмбеддера (легаси-записи без fingerprint — исключать);
- `CanonRecordView` не несёт эмбеддинги, а `CanonState.similarity` живёт по
  принципу «providers consume it, never re-measure» — векторы голове модели
  нужно передавать отдельно.

## Решение

### V1. Двухкандидатная лестница D/N

Принята лестница из двух кандидатов; отбор внутренний, на оценку A5 едет
лучший, при сомнении — D.

| Кандидат | Что это | Роль |
|---|---|---|
| **D** | градиентный бустинг над фичами пары (целевые косинусы, char 3–5-граммы RU+EN, jaccard тегов, дельты метаданных) | равноправный ADOPT-кандидат и внутренний бар |
| **N** | голова ≤ ~0.5M параметров над замороженными векторами mnema-embed-v1; corruption-претрейн | нейро-кандидат |

Условия лестницы:

- **Входной контракт:** замороженный mnema-embed-v1 @ fingerprint; внешние
  претрейн-веса запрещены; собственного энкодера у N нет. Входной контракт и
  протокол отбора фиксируются этим ADR до старта A2/A3.
- **Претрейн N — corruption-based:** слабые позитивы = смыслосохраняющие
  трансформации, жёсткие негативы = тот-же-текст-сломанное-поле. Дистилляция
  косинуса запрещена.
- **Протокол отбора:** stratified 5-fold × 20 фиксированных сидов; метрики
  balanced accuracy + Brier (mean±std); превосходство кандидата N — больше
  1 std repeat-spread; гриды ≤ 8 конфигураций, замораживаются в коде A3.
- **Абляции до внутренней сдачи:** с/без претрейна, с/без полевых косинусов
  (заголовок/тело/теги). Докомпьют полевых косинусов bundle-эмбеддером на CPU
  допустим, но короткие поля — слабый сигнал; D-без-полевых — самый дешёвый
  рантайм.
- **Изоляция holdout:** физическая (метки вне train-дерева), ассерты
  пересечения pair_id, append-only run-лог с отказом на повтор, CI-тест.

Рационал. 140 пар — статистический факт: главный критерий — низкая
дисперсия, а не выразительность. Деревья — родная среда для такого объёма, а
фича-семейство «локальная расходимость при глобальной близости» бьёт точно в
урок W4c (близнецы со сломанным полем). Воля владельца — «специализированная
узкая архитектура как Jev, но своя», а не «обязательно нейросеть»: брифинг
сам называет не-нейросетевой контроль обязательным кандидатом, комитет
поднял его до равноправного.

Зависимость. Кандидату N нужна передача векторов в CanonState — аддендум
[ADR 0004](https://github.com/vesmaro/vesmaro-canon) канона. Прод-wiring N —
только после аддендума; оценка A5 не блокирована (раннер cortex читает
векторы сам, без аддендума); кандидат D от аддендума не зависит.

### V2. Дата-стратегия

- Размеченные ~140 пар — только supervised-фит.
- Неразмеченные пары стора — только corruption-претрейн кандидата N;
  pretrain-инициализация обязана перебиваться владельческими метками.
- Гигиена препрега при любом экспорте: секрет-скан + `no-federate` до
  экспорта, read-only URI, ни одной сырой строки стора в репе.
- Расширение train-определения сверх «≈140 пар» = аддендум препрега до
  любого прогона.

Рационал. Holdout single-shot — единственное decision-число, его чистота
требует жёсткой границы «размеченное — только supervised». Претрейн не меняет
train-определение (претрейн — не оценка), поэтому A2 аддендума не требует.

### V3. Артефактный контракт

- Одиночный ONNX ≤ 5 МБ, self-contained: feature-код в графе или пин в
  metadata_props. Δdeps движка = 0 — onnxruntime уже в core.
- `metadata_props` {name, version, embedder_pin, corpus_fingerprint,
  trained_at}; sha256 файла = fingerprint весов.
- Загрузка — паттерн NanoProvider: eager load + smoke-inference; провайдер
  падает громко при смене эмбеддера (ассерт пина).
- sklearn-pickle запрещён категорически (см. Alternatives considered).
- fail-open (сбой провайдера деградирует на DeterministicProvider, ingest не
  блокируется) и import-изоляция (ноль сети) — требования к W5d.

Рационал. Артефакт заходит в движок без новых зависимостей,
самодокументируется метаданными и живёт в дисциплине фингерпринтов эмбеддера
(ADR-0021 движка): смена весов = событие перекалибровки.

### V4. Нейминг-онтология экосистемы

Принята онтология из пяти уровней:

1. **org** — `vesmaro`.
2. **Продукт** — параллельный трек владельца, в онтологию не смешивается.
   Выбранное имя продукта не становится префиксом; после выбора — одна
   проверка коллизий.
3. **Репы-компоненты** — нейро-парадигма (`cortex`, движок `vesmaro`);
   `canon` — историческое исключение.
4. **Модели-артефакты** — `mnema-*`.
5. **Утилиты** — функциональные имена.

Правила:

- **Один концепт = одно имя на уровень**; плодить синонимы нельзя.
- **Реестр имён живёт в ADR.** Новое имя вносится в реестр до первого
  коммита, который его использует.
- **Серые зоны — по циклу выпуска:** у артефакта своя жизнь, внешние
  контракты или волны → репа-компонент; живёт внутри репы без внешних
  контрактов → утилита.
- **Разрушительные утилиты** (gc / purge / trim): имя звучит как то, что
  утилита делает, — без уютных эвфемизмов; плюс разрушительный гейт.
- **Нейро-имена кроме `cortex`** — резерв без права занятия: новое нейро-имя
  требует доказательства неперекрытия смыслов с существующими.
- **Машинные строки** (телеметрия, провенанс, имена артефактов) — только
  латиница.
- **Шум `cortex` в open source** (Grafana Cortex → Mimir, cortex.dev, PyPI
  cortex) приемлем для приватной репы; публичная публикация — под префиксами
  `vesmaro-` / `mnema-`.
- **Массовое переименование существующего не проводится**; соседние репы
  уведомляются о реестре.

Стартовый реестр имён:

| Концепт | Имя | Уровень | Репа-владелец |
|---|---|---|---|
| Организация | `vesmaro` | org | — |
| Канон контента | `canon` | репа-компонент | vesmaro-canon (историческое исключение) |
| Платформа локальных когнитивных сервисов | `cortex` | репа-компонент | vesmaro-cortex |
| Движок, хост MnemaProvider | `vesmaro` (repo engine) | репа-компонент | движок vesmaro |
| Эмбеддер | `mnema-embed` | модель-артефакт | движок vesmaro |
| Refine-модель | `mnema-refine` | модель-артефакт | planned |
| Модель решений (is-duplicate) | `vesma-cortex` (переименовано владельцем 2026-10-01 из `mnema-cortex`, рефактор `45b4297`) | модель-артефакт | vesmaro-cortex (дом семейства) |
| Глаза (мониторинг) | `mnemos-eyes` | историческое | вне онтологии новых имён |

Рационал. Единственное имя, которое видит пользователь, — имя артефакта;
вся строгость онтологии работает на уровне `mnema-*`. Функциональное имя
артефакта — защёлка scope-крипа: переименование бесплатно до калибровки,
после — audit-цена.

### V5. Имя артефакта: mnema-dedup

Рекомендовано `mnema-dedup`; финальная точка — владелец (строка в «ждут
владельца», решение до A3).

> **Снято решением владельца 2026-09-29** (см. «Аддендум владельца» в конце):
> артефакт называется `mnema-cortex`. Рекомендация комитета засчитана как
> рассмотренная и отклонённая; остальное V5 (терминологическая строка,
> «смена имени ≠ перекалибровка») действует с заменой константы.

Терминологическая строка: проза canon «mnema-роутер» — историческое имя
трека; артефакт модели — константа `mnema-dedup-v1`. Смена имени метки — не
событие перекалибровки: fingerprint = sha256 весов.

Рационал. Функция заморожена чартером §2 (одна задача is-duplicate);
`router` оставляет в телеметрии ложный след model-routing; сейчас
переименование бесплатно, после калибровки — audit-цена.

### V6. XPU-бюджет

A4 сохраняет форму «ранбук → руки владельца», содержание меняется:
walkthrough-прогон для провенанса + CPU/XPU детерминизм-гейт (совпадение в
допуске на одинаковых сидах). Технической потребности в XPU-обучении
лестница не создаёт: вход — предвычисленные векторы стора, обучение —
CPU-минуты.

Рационал. XPU-провенанс артефакта остаётся требованием чартера (бюджет
Arc 140T), но архитектура не делает XPU необходимостью — ранбук остаётся
управляемой поверхностью владельца, а не обязательным шагом обучения.

## Alternatives considered

| Альтернатива | Почему отвергнута |
|---|---|
| Cross-encoder над парой | без собственного энкодера вырождается в лёгкую голову над замороженным эмбеддером (это уже кандидат N); с внешним энкодером противоречит «архитектуре с нуля» |
| Transformer с нуля | 2.9к записей стора не тянут LM-претрейн; токенизация RU+EN — отдельная программа; бюджет сгорает |
| Собственный энкодер вместо замороженного эмбеддера | на 2.9к записей не переучит дистиллят; ре-эмбедд стора = событие перекалибровки (ADR-0021 движка) |
| Дистилляция косинуса как претрейн N | циклична — голова переоткрывает baseline |
| Self-embed провайдером в рантайме | drift: стор-вектор мог быть посчитан до правки записи; нарушает принцип CanonState «never re-measure» |
| sklearn-pickle как артефакт | execution-поверхность + жёсткий пин версии; категорически запрещён |
| XPU-обучение как необходимость | векторы предвычислены, обучение — CPU-минуты; XPU остаётся walkthrough + детерминизм-гейтом |
| «Только нейросеть, бустинг — не солидно» | статистика 140 пар требует низкой дисперсии, а не выразительности; брифинг владельца сам называет не-нейросетевой контроль обязательным кандидатом |

## Последствия

- Лестница D/N закреплена для волн A2–A6; входной контракт и протокол отбора
  зафиксированы этим ADR до старта A2/A3.
- Кандидат N попадает в прод только после аддендума ADR 0004 канона (передача
  векторов в CanonState) — это требование идёт первым пунктом хендофф-ноты
  W5d; оценка A5 не блокирована, D от аддендума не зависит.
- Имя артефакта — одна константа в трёх местах (директория, name провайдера,
  ключ конфига); до A3 его смена — правка одной константы.
- Реестр имён живёт в этом ADR; новое имя вносится до первого коммита,
  который его использует.
- A4 меняет содержание (walkthrough + детерминизм-гейт) без смены формы
  (ранбук → руки владельца).

## Аддендум владельца (2026-09-29, после заседания A1)

Владелец рассмотрел вердикты и принял два решения, уточняющих ADR. Остальные
вердикты (V1–V4, V6) подтверждаются без изменений.

### П1. Имя артефакта — `mnema-cortex`

Рекомендация V5 (`mnema-dedup`) отклонена владельцем: раз репа называется
`vesmaro-cortex`, модель носит тот же корень — `mnema-cortex` (артефакт
`mnema-cortex-v1`).

- Марка моделей `mnema-*` сохранена (фиксация владельца из брифинга
  2026-09-29 действует); `cortex` — корень артефакта, не отдельное голое имя.
- Корень `cortex` осознанно делится между уровнями как связка «дом
  семейства ↔ модель семейства»: репа `vesmaro-cortex` — дом моделей решений,
  артефакт `mnema-cortex-v1` — первая модель. Уровни не склеиваются: репа и
  артефакт различимы префиксами (`vesmaro-` / `mnema-`) и типом сущности.
- Рационал комитета о scope-защёлке снимается волей владельца: эволюционное
  имя — осознанный выбор (чартер §3). Расширение задач модели всё равно идёт
  через отдельные решения (чартер §2) — защёлка остаётся процессной, не
  лексической.
- Терминологическая строка V5 действует с заменой константы: проза canon
  «mnema-роутер» — историческое имя трека; артефакт — `mnema-cortex-v1`.
  Смена имени метки — не событие перекалибровки: fingerprint = sha256 весов.
- Реестр имён обновлён (строка «Модель решений (is-duplicate)»).

### П2. Двухэпостасная поставка — библиотека + пакет в сервере

Модель становится частью сервера vesmaro равноправно с эмбеддинг-моделью:
поставка в двух эпостасях.

- **Библиотека разработки** — эта репа: генерация корпусов, фичи, обучение,
  внутренняя CV, экспорт, оценка (раннер single-shot). Тяжёлые зависимости
  (torch, lightgbm/sklearn, skl2onnx) живут ТОЛЬКО здесь, в train-окружении
  (`~/.venvs/nm-train` / nano-llm контейнер).
- **Runtime-пакет** — одиночный self-contained ONNX-артефакт (вердикт V3
  без изменений: ≤5 МБ, Δdeps движка = 0, metadata_props, sha256 =
  fingerprint), бандлится в дистрибутив движка по образцу `mnema-embed-v1`
  (`src/vesmaro/models/<name>/`, загрузка паттерном NanoProvider — eager
  init, smoke-inference, ассерт пина эмбеддера). Обёртка-провайдер — на
  стороне движка (W5d канона, `MnemaProvider`).
- Публикация библиотеки cortex как отдельного PyPI-пакета — НЕ входит в
  этот ADR: решение владельца после вердикта A5 (ADOPT/DECLINE); до того
  репа остаётся приватной/локальной.
- Ограничение двух эпостасей: код обучения никогда не попадает в
  runtime-зависимости движка (torch — training extra по ADR-0021), артефакт
  никогда не требует кода библиотеки для инференса (self-contained ONNX).

### П3. Синтетический корпус для начального обучения (решение владельца, 2026-09-29)

Владелец предложил усилить обучение LLM-генерацией большого датасета пар:
синтетика — начальная стадия обучения, реальные владельческие пары —
финальная. Ядро принимается (это углубляет двухстадийную схему V2);
рамка ниже фиксирует границы ДО любой генерации.

- **Принятая схема стадий:** (1) синтетический корпус — претрейн/начальное
  обучение; (2) владельческие ~140 пар — финальный supervised-этап;
  оценка — только по препрегу v2 на владельческом holdout. Иерархия
  «реальное важнее синтетического» — воля владельца, она совпадает с
  методологией.
- **Корректировка «модель работает с текстом»:** вход модели — НЕ сырой
  текст, а числовые признаки пары (V1) и/или векторы mnema-embed-v1. Поэтому
  LLM-генерация — генератор ТЕКСТОВЫХ ПАР, которые проходят через тот же
  фиче-экстрактор; LLM не учит модель языку (языковое сходство уже несут
  фичи/векторы), а расширяет покрытие пространства признаков — прежде всего
  зону «высокий косинус, но семантически разные» (урок W4c) и
  около-пороговую область.
- **Метки по построению, не LLM-судейство:** пара генерируется С ЗАДАННОЙ
  семантикой (перефразировка одной памяти → позитив; топикно-близкая другая
  память → негатив; «близнец со сломанным полем» → негатив). LLM-судейство —
  только валидация выборки; финальная валидация — кодбук, сэмпл 20–30 пар
  глазами владельца до использования корпуса.
- **Аддендум препрега — до прогона:** если синтетика участвует в supervised
  или претрейне ФИНАЛЬНОЙ оцениваемой модели, train-определение расширяется
  сверх «≈140 пар» → аддендум препрега v2 пушится в canon main ДО любого
  прогона оценки (чартер §4; прецедент — аддендум 1). Формат аддендума
  фиксируется после A3b-экспериментов, когда измерен вклад синтетики.
- **Одна задача — один корпус:** «несколько датасетов под каждый тип задач»
  откладывается (чартер §2: расширение примитивов — отдельные решения);
  текущий синтетический корпус — только is-duplicate.
- **Гигиена и провенанс:** генерация детерминирована (seed, версия
  генератора и LLM в провенансе); корпус фингерпринтится по схеме
  data-contract; контент в репу не коммитится (манифесты и счётчики — да).
  Локальность: предпочтительна локальная LLM (ollama — ноль сети и
  стоимости); внешняя API-генерация допустима (синтетика — не записи стора,
  приватного контента не несёт), выбор фиксируется в провенансе корпуса.
- **Носители:** физически параллельные агенты запрещены (OOM-дисциплина) —
  карточка A2s в сторе задач, диспатч последовательный.
