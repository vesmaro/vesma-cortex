# ADR 0002: Реестр обязанностей vesma-cortex v2 и архитектура семейства артефактов

- **Status:** Accepted (АрхКом R-фазы, 2026-10-02; нейминг duty-суффиксов —
  финальная точка владельца)
- **Date:** 2026-10-02
- **Протокол:** Архитектурный комитет — фаза R, 2026-10-02 (team-local)

## Контекст

v1 закрыта ADOPT-вердиктом калибровки
[calibration-ds1000-a5](../experiments/calibration-ds1000-a5.md): артефакт
`vesma-cortex` (is-duplicate) принят по препрегу v2 + аддендуму 2; W5d
исполнен соседней сессией (merge `4a343e9`, бандл = ADOPT-веса `281bd0fd`,
`VesmaProvider` за флагом, выключен). Чартер при этом закреплял за моделью
одну задачу; директива владельца на расширение обязанностей (программа v2,
[roadmap](../roadmap-v2.md)) открыла два вопроса: какие обязанности вводить
и в какой архитектуре они живут.

Вход АрхКома — инвентарь TL из 9 кандидатов (roadmap §1, R1): от усиления
is-duplicate граф-признаками до генерации текста. На заседании приняты два
дополнения: **A best-match** и **B answerability** (предложил product
architect, senior system engineer подтвердил источники меток). Итого реестр —
11 позиций.

Эмпирический фундамент — волна **B0**: флаг W5d включается, 2–4 недели
прод-телеметрии собирают реальные промахи до любого решения об отложенных
обязанностях (принцип 0.1 roadmap: телеметрия раньше телепатии).

Архитектурный вопрос R2: один мульти-duty артефакт или семья узких
артефактов — принцип [ADR 0001](0001-archcom-a1-verdicts.md) «одна задача =
один артефакт» против соблазна эксплуатировать общее фиче-ядро весами.

## Решение

### R1. Реестр обязанностей

| # | Обязанность | Вердикт | Примитив | Приор. | Условия / триггер |
|---|---|---|---|---|---|
| 1 | is-duplicate v2 (граф-фичи) | ВКЛЮЧИТЬ | Noul | P1 | датасет v2 + прereg v3; граф-блок аддитивен (ревизия 1.n) |
| 2 | record-quality | ВКЛЮЧИТЬ (коррекция) | Score | P2 | фаза 1 — детерминированный Score поверх `canon_validate`, без артефакта и без чартер-гейта; фаза 2 условная — слияние с №8 в предиктор полезности |
| 3 | merge-arbiter | ВКЛЮЧИТЬ | Choice | P1* | чартер-гейт владельца на Choice; старт после B2; корпус — синтетика + владельческий спот-чек (объём исходов — десятки) |
| 6 | conflict-detector | ВКЛЮЧИТЬ | Noul | P2 | корпус = гейт: SQL-миграция kind `contradicts` — одной волной с корпусом |
| 4 | relevance-judge | ОТЛОЖИТЬ | Score | P3 | триггер: строго лучше awareness-эвристики на B0-телеметрии |
| 5 | staleness | ОТЛОЖИТЬ | Noul | P3 | триггер: ≥100 supersede/correction-событий; шлюз — OQ-2 (наличие `created_at`) |
| 8 | value/importance | ОТЛОЖИТЬ | Score | P3 | триггер: ≥1000 used-событий + дебайсинг по рангу |
| A | best-match | ОТЛОЖИТЬ | Choice | P3 | триггер: строго лучше эвристики на телеметрии проваленных выборок |
| B | answerability | ОТЛОЖИТЬ | Noul | P2–P3 | `fallback_used` уже в схеме B0; решение после окна телеметрии |
| 7 | canon-score | ОТКЛОНЁН | — | — | формализуемое правило = код, не модель; возврат при субъективных критериях |
| 9 | генерация текста | ОТКЛОНЁН (граница) | — | — | вне рамки «Jev без генерации»; формальная граница — 4 основания (ниже) |

Фиксируемые позиции кресла:

- **Коррекция №2** принята поверх исходной позиции: фаза 1 — код
  (`canon_validate` уже формализует нарушения дисциплины канона), ML-фаза —
  только если B0 покажет остаточные промахи; чартер-гейт на фазу 1 не
  тратится.
- **Четыре основания отклонения №9** (product architect): калибровка,
  провенанс стиля, артефактный контракт, роль советника — Jev остаётся
  классом без генерации.
- **Триггеры №4/A зависят от будущего шва:** `awareness.rank_provider` в
  main отсутствует (сознательно вне волн 0–2) — порог «строго лучше
  эвристики» считается по телеметрии, когда шов появится.
- **Конструктивные корпуса — норма фазы D:** повтор структурного NO-DATA
  принят к бюджетированию; «диких» пар в чистом сторе нет по построению.

### R2. Архитектура: семья узких артефактов

Принята **семья узких артефактов** при общей репе-доме. Горизонт v2 —
**2–4 артефакта**: is-duplicate (ревизия 1.n), merge-arbiter,
conflict-detector; record-quality стартует вовсе без артефакта.

**Фиче-ядро шарится кодом, никогда весами.** Общая библиотека cortex
(экстракция фич, пины, фингерпринты) одна; веса у каждого duty свои. Три
системные механики, которые это сохраняет:

1. **Pin-сцепка = радиус отказа.** Пин эмбеддера живёт в каждом артефакте
   отдельно (ассерт пина, ADR 0001 V3): смена эмбеддера инвалидирует ровно
   те duty, чей пин устарел, и каждый переезжает своим циклом
   перекалибровки — отказ не запирает всю семью в одну дату пересборки.
2. **Часы версий per-duty.** Смена весов одного артефакта — событие
   перекалибровки только этого duty (fingerprint = sha256 весов, дисциплина
   ADR-0021 движка); соседние duty не затронуты.
3. **Атрибуция телеметрии.** Каждая строка B0-лога относится к ровно одному
   артефакту: промахи считаются по duty, а не по «модели вообще».

Контраргумент weight-sharing разобран: то, что в мульти-duty артефакте
выглядит как «общие веса», в семье и так общее — фиче-ядро. Шаринг живёт на
уровне фич (код), не весов; защёлка scope-крипа («одна задача = один
артефакт») сохраняется процессно — через реестр и независимые фазы D/T.

### R3. Нейминг: duty-суффиксы

Новые артефакты семьи носят duty-суффикс: `vesma-cortex-<duty>-v<N>`
(образец из протокола — `vesma-cortex-quality-v1`). Действующий
is-duplicate-артефакт сохраняет имя `vesma-cortex`: массовое переименование
существующего не проводится (правило ADR 0001). Каждое новое имя вносится в
реестр имён ADR 0001 до первого коммита, который его использует. Схема
суффиксов — финальная точка владельца.

### R4. B0-телеметрия: две строки лога

Схема принята как дополнение к спеке W5d: две инфо-строки без миграций,
реализация — мелкий PR движка.

- **`CORTEX-DECISION`** — `{pair_sha256, probability, threshold, verdict,
  delta, latency}`. Join-ключ для корпуса реальных промахов: поздние
  human-supersedes рёбра сшиваются с решениями по `pair_sha256`.
- **`CORTEX-RECALL`** — `{candidates, best_similarity, fallback_used,
  abstained}`. Метки для answerability (B) и best-match (A) копятся с
  первого дня телеметрии.

`edge_stats` уже каптурит used/rejected с actor — метки для №8
(value/importance) накапливаются с сегодняшнего дня, без нового кода.

## Alternatives considered

| Альтернатива | Почему отвергнута |
|---|---|
| Один мульти-duty артефакт | сшитые фингерпринты: перекалибровка одного duty маскируется пересборкой целого — «перекалибровка-театр»; коррелированные отказы через общий pin; per-duty атрибуция телеметрии невозможна внутри одного sha256 |
| canon-score как ML-модель (№7) | цикличность: метки = вывод `canon_validate`-чеклера — модель лишь переоткрывает чеклист; тема возвращается при субъективных критериях каноничности |
| Немедленная реализация Choice без чартер-гейта | нарушение принципа 0.5 roadmap: новые примитивы — только отдельным решением владельца; старт №3 до санкции = скрытое расширение чартера |
| Вес-sharing при тощих корпусах (общая база весов + duty-головы) | отклонён как спекулятивный: выгоды не измерены, перенос калибровочных сдвигов между duty реален; шаринг уже достигнут там, где он бесплатен — на уровне фич |

## Последствия

- Горизонт v2 — 2–4 артефакта; состав определяет реестр, а не календарь.
- Каждая обязанность проходит фазы D/T независимо: свой датасет, свой
  пререг, свой holdout, свой вердикт; чеклист волны (roadmap §5) применяется
  per-duty.
- Choice (№3) стартует только после отдельной санкции владельца
  (чартер-гейт); готовность корпуса санкцию не заменяет.
- Миграция kind `contradicts` идёт одной волной с корпусом №6 — корпус
  является гейтом волны; до миграции conflict-detector не обучается.
- B0-лог-схема (`CORTEX-DECISION` / `CORTEX-RECALL`) — дополнение к W5d;
  реализация — мелкий PR движка без миграций.
- При переименовании import-пакета движка (волна W6) — синхронизировать
  3 скрипта cortex, завязанные на имя пакета.
- Отложенные обязанности (4/5/8/A/B) пересматриваются по количественным
  триггерам после окна B0; досрочный возврат — только через АрхКом.
- Новые имена артефактов вносятся в реестр имён ADR 0001 до первого
  коммита, который их использует.
