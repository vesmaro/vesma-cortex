# Методология оценки vesma-cortex v1.0

- **Статус:** Accepted (v1.0, полузаморожена: пороги меняются только
  аддендумом-пререгистрацией через `gate_contract.json` — §6; решение
  АрхКома MR0, [ADR 0003](../decisions/0003-model-artifacts-release-and-eval.md))
- **Дата:** 2026-10-03
- **Область:** чем и как оценивается модель — реестр метрик, бейслайны,
  три слоя оценки, таблица гейтов, локбокс, классы проб, правила
  пререгистрации. Основа — препрег v2 (canon) и урок #480: holdout-метрики
  слепы к дефектам, которых нет на поверхности оценки.

## 1. Реестр метрик

| Метрика | Формула / правило | Инструмент | Слой | Владелец |
|---|---|---|---|---|
| balanced accuracy (BA) | (sens + spec) / 2 | `sklearn.metrics.balanced_accuracy_score` | A, B, локбокс | TL |
| sensitivity / specificity | TPR / TNR на holdout | sklearn | A, B | TL |
| Brier | `brier_score_loss` | sklearn | A, B | TL |
| типизированность | доля ответов с валидным `Noul`+`Score` | runner | A, B | TL |
| self_pair | P(dup \| проба против себя, cos=1.0), порог ≥ 0.9 | sanity-сьют (`cortex.eval.sanity`) | A | TL |
| near_boundary | P(dup \| лёгкая пертурбация, cos≈0.99), cut ≥ 0.5 | sanity-сьют | A | TL |
| unrelated | P(dup \| разные темы, cos=0.578), потолок < 0.5 | sanity-сьют | A | TL |
| monotonicity | нестрогое невозрастание P по cos-лестнице {1.0, 0.99, 0.95, 0.8, 0.5}, tol 1e-6 | sanity-сьют | A | TL |
| bundle_integrity / feature_contract | sha256 байтов и порядок фич == манифесту == замороженному контракту | sanity-сьют | A | TL |
| prev_adopt-коридор | BA(release) ≥ BA(prev ADOPT) − max(0.02; CI95) | runner | A (release), B | TL |
| delta-rate | доля решений, где вердикт модели ≠ вердикту базлайна | B0-коллектор (`telemetry/metrics-2h.jsonl`) | B0 | SRE |
| no-harm в cos-полосе | доля расхождений модели с базлайном при cos ≥ 0.95 | B0-коллектор | B0 | SRE |

Пороги всех коридорных/инвариантных метрик фиксируются не в этом тексте,
а в `gate_contract.json` (§6) — источник значения для CI.

## 2. Бейслайны

- **Косинус 0.92 — первичный** (`DeterministicProvider` движка): порог
  препрега v2; всякая калибровка обязана показать BA строго выше него
  (ADOPT-условие 5).
- **prev_adopt — коридорный**: BA предыдущей ADOPT-ревизии — пол для
  release-гейта (§4). Ловит деградацию при перекалибровке; ранжированием
  близких ревизий не занимается (см. оговорку §4).

## 3. Три слоя оценки

### Layer A — CI-синтетика

- Два замороженных набора: **merge-набор ~60 пар** (быстрый, каждый PR) и
  **release-набор ≥ 200 пар** (стратифицированный, на release-гейте).
- Тексты проб коммитятся в репу (`tests/evalsets/<set-id>/`: `probes.jsonl`
  + `manifest.txt`) — синтетика, публичность разрешена
  [ADR 0003](../decisions/0003-model-artifacts-release-and-eval.md) R2;
  набор фингерпринтится — `eval_set_sha256` в отчёте прогона.
- **Пары ВСЕГДА считаются через `cortex.features.pair.features`** — урок
  #480: локальные копии фичевой математики расходятся с прод-обёрткой в
  порядке колонок, и сюит начинает мерить не тот артефакт.
- Сюит (`scripts/eval_sanity_suite.py`) — инструмент инвариантов и
  коридоров Layer A; прогон против бандла (dir или .onnx), exit ≠ 0 = провал.

### Layer B — калибровка по препрегу v2

Single-shot holdout по замороженному препрегу (canon): 7 стратов,
holdout 30 %, шесть условий ADOPT. Holdout сжигается одним прогоном;
исключение для реэкспорта неизменных весов — §6. Итог Layer B — вердикт
ADOPT/DECLINE/NO-DATA в `eval-results.json`.

### Layer B0 — поле

Прод-телеметрия по [плану B0](../experiments/b0-telemetry-plan.md):
delta-rate, no-harm-коридор cos-полосы, счётчики `CORTEX-E-*`. Поле —
источник правды о ценности, не гейт качества артефакта.

## 4. Таблица гейтов

| Слой гейта | Проверки | Блокирует | Оговорка |
|---|---|---|---|
| **ИНВАРИАНТЫ** | bundle_integrity; feature_contract (порядок фич == манифест == `FEATURE_NAMES`); типизированный выход; self_pair ≥ 0.9; монотонность (tol 1e-6) | **merge** | детерминированные: воспроизводимы бит-в-бит, флейта нет |
| **КОРИДОРЫ** | cosmetic_twin ≥ 0.5 (v2, экс-near_boundary); fact_edit_twin < 0.5 (v2); envelope_variant ≥ 0.5 (v2); unrelated < 0.5; синтетическая BA ≥ prev_adopt − max(0.02; CI95) | **release** | коридор ловит **обрывы**, не ранжирует близкие ревизии: падение в коридор — повод для разбора, а не автоматический вердикт «хуже» |
| **ВЕРДИКТЫ** | метрики препрега-v2 (Layer B); delta-rate (B0) | **никогда** (информационные) | ADOPT/DECLINE — решение владельца по замороженному decision rule; delta-rate — критерий ценности B0, не качества |

([ADR 0003](../decisions/0003-model-artifacts-release-and-eval.md),

## 5. Локбокс (holdout вне всех коммитимых поверхностей)

- ~50 пар, **другие** сиды и темы — не пересекаются с merge/release-наборами.
- В репе — только хеш набора (`lockbox_sha256`); сами пробы не коммитятся.
- Одноразовый прогон на release-гейте; повтор по тому же набору запрещён
  механикой run-log (refusal при повторном фингерпринте —
  [data-contract](data-contract.md) §8).
- Назначение: последняя независимая поверхность перед публикацией;
  не заменяет Layer B.

## 6. Анти-HARKing: `gate_contract.json`

Гипотезы после того, как данные видны (HARKing), запрещены механикой:

- Пороги всех гейтов живут в `gate_contract.json`, файл версионирован и
  несёт **свой sha256**; значения пиннутся в этом документе и в CI.
  Актуальная ревизия — **v3** (волна D4-3, 2026-10-05): `gate_contract.json`
  в корне репы (вне бандла — правило разделения выше), sha256
  `048fc5d951b1696ff127e4d0a617d6e9a84072a8bc28860bb5807a42c3025c88`.
  Пин обновлён волной реестра B2-v42 (2026-10-05): байты контракта пополнились
  presence-счётчиками `corner_qa` аддендума 5c (`t3_same_length_share`,
  `low_cos_high_overlap_notdup` — порогов не меняло, ревизия v3 сохранена),
  пин §6 остался на добарметровых байтах `abca91ea…` — CI eval-sanity
  с 00cd96e красный именно на этом; синхронизировано задним числом с
  раскрытием события здесь.
  Провенанс: ревизия v3, ратифицировано владельцем 2026-10-05 (PR #10
  аддендумы — policy v1.1 §8 и sanity v2 §10 этого документа), пороги —
  отдельным вагоном от артефактов. Дельта v3: новая секция `sanity_v2` —
  policy-aware экзамен (cosmetic_twin ≥ 0.5, fact_edit_twin < 0.5,
  envelope_variant ≥ 0.5; зонная монотонность v2: razor-зона (0.95; 1.0)
  двузначна — монотонность внутри не требуется, вне зоны операционально
  P(0.95) ≥ P(0.8) ≥ P(0.5), tol 1e-6); инвариант монотонности переписан
  под зоны, коридор near_boundary переименован в cosmetic_twin (числа те
  же, класс — по политике v1.1), таксономия §7 пополнена. Потребитель —
  `cortex.eval.sanity` (когерентность замороженных констант и секции
  пиннута тестом). Предыдущая ревизия — v2:
  `f94f0c907e0ae6e450cb20bebf016b5b1ae3582e4c7c6e21896cab26d65f350f`
  (волна D4-1/3, 2026-10-05; дельта — секция `corner_qa`: pre-train
  пороги приёмки корпуса dataset-v4 — клоны-негативы = 0, corner-DUP ≥ 10,
  identity ≥ 60, metadata ≥ 40, fact-edit ≥ 75, razor-зона = 0,
  G1-потолок по 7 фичам, G4 масса ≥ 8, presence/mismatch/cos-полы — по
  P0 §8.1 и labeling-policy-b2 §5; арбитраж TL 2026-10-05; потребитель —
  `cortex.data.corner_qa`, лоадер с fallback на замороженные константы).
  Ревизия v1: `6dd67367601bd6a4fa0d9a067591742a1ac05f58c6c36825596d748d781fef32`
  (MR-1, 2026-10-03).
- Контракт **не привязан** к `feature_set_sha256` (вердикт комитета:
  пороги грейдят модель, не фичи).
- Правило разделения: **PR с порогами не содержит артефактов, и наоборот** —
  смена правил и смена модели не едут одним вагоном.
- Порог меняется только аддендумом-пререгистрацией (до прогона оценки);
  повышение порога в merge-гейт — только директива владельца (прецедент
  таксономии инвариант/коридор/вердикт — ADR-0026 движка).
- Исключение Layer B для реэкспорта: если `weights_sha256` не изменился,
  holdout не сжигается — вместо него эквивалентность 1e-6 выходов на
  замороженном наборе.

| Класс | Что ловит | Статус покрытия |

| cosmetic-близнец (T1: пунктуация/регистр/пробелы, policy v1.1 §8.2) | обрыв на границе порога со стороны дубликата | сюит v2, проба (i) — коридор |
| fact-edit близнец (T3 razor: ключевой факт в теле) | доминанта зоны «всё близкое = не дубликат» | сюит v2, проба (ii) — коридор |

| type/lang рассогласования | неверный вес `type_match`/`lang_match` | фичи есть, **проб нет** — хвост |
| дегенераты | пустые/вырожденные записи | **не покрыто** — хвост |

Правила пополнения:

- **«Одна фича вошла — один класс проб вошёл»**, в том же PR: новая фича
  в `FEATURE_NAMES` обязана прийти с пробами своего класса (иначе сюит
  структурно слеп именно там, где модель изменилась).
- **Негативный фикстчер обязателен:** сломанный бандл (переставленный
  порядок фич-колонок) ОБЯЗАН фейлить сюйт — регрессионный тест
  `tests/test_eval_sanity.py` держит инверсию #480 воспроизводимой до знака.

## 8. ADOPT-отчёт: форма

Каждый ADOPT-отчёт **открывается таблицей покрытия поверхности**
(класс проб → пробы → источник; §7) — читатель сначала видит, что именно
умеет видеть методология, и только потом цифры. Числа без таблицы покрытия
не цитируются (правило с 2026-10-03, урок #480).

## 10. Аддендум: sanity v2 — policy-aware экзамен (2026-10-05)

- **Статус:** формализация ратифицированного владельцем направления
  (вердикт 2026-10-05, нога «б»); текст аддендума — proposal на
  ратификацию владельцем. Замороженные пороги D1-протокола (§1, §4) не
  переписываются — исторический факт; этот аддендум определяет экзамен
  v2 для следующих волн.
- **Триггер:** FAIL сьюта по обучению B2-prime (артефакт `89d6f329`):
  near_boundary 0.0261 при cut ≥ 0.5 и monotonicity FAIL — при
  вылеченном self-pair (0.0108 → 0.9934). Зонд near_boundary v1
  («title + "!"», cos ≈ 0.99) кодирует требование «любой близнец на
  0.99 = дубликат ≥ 0.5», а корпус по policy v1.0 заселил razor-зону
  192 факт-негативами против 72 позитивов — модель честно выучила
  доминанту зоны. Конфликтуют правила (политика против экзамена), не
  модель. Лечение — двусторонние пробы razor-зоны по
  [policy v1.1](labeling-policy-b2.md) (аддендум 1, §8.1–8.2).

### 10.1 near_boundary v1 → v2: три пробы вместо одной

| # | Проба v2 | Пертурбация | Класс по policy v1.1 | Требование |
|---|---|---|---|---|
| i | **cosmetic-twin** | только косметическое: «!» в заголовке, регистр, пробелы — по нормализации | cosmetic (T1) | **dup: P(dup) ≥ 0.5** |
| ii | **fact-edit twin** | та же запись с изменённым ключевым фактом в теле — число/имя | razor (T3) | **NOT dup: P(dup) < 0.5** |
| iii | **envelope-variant** (новая) | та же запись с другой датой в конверте (whitelist §8.1 политики) | whitelist-dup (новый dup-класс) | **dup: P(dup) ≥ 0.5** |

Двусторонность — суть v2: в razor-зоне экзамен требует от модели ОБА
верных ответа — позитив на косметику/конверт и негатив на факт-правку, —
а не одну сторону зоны, как v1. Пробы i–ii наследуют зонды S2/S3 препрега
([calibration-b2p-prereg](../experiments/calibration-b2p-prereg.md) §3) с
уточнением: cosmetic-класс отныне включает пунктуацию заголовка (policy
v1.1 §8.2). Проба iii — новая: проверяет, что конвертная дельта не читается
моделью как факт-правка. Новый класс проб встаёт строкой в таксономию §7
при ревизии контракта.

### 10.2 monotonicity v2: зонная лестница

v1 требовала нестрогое невозрастание по всей лестнице {1.0, 0.99, 0.95,
0.8, 0.5} — в razor-зоне это противоречит её двузначности по политике:
там живут оба класса. v2 — **зонная**:

| Зона cos | Правило |
|---|---|
| `[1.0]` identity | самопара пиннится инвариантом self_pair ≥ 0.9 (§1) |
| `(0.95; 1.0)` razor | двузначна по политике — **монотонность не требуется**, скачки внутри зоны допустимы |
| `[0.5; 0.95)` | нестрогое невозрастание, tol 1e-6 |
| `[0; 0.5)` | нестрогое невозрастание, tol 1e-6 |

Формулировка: **вне razor-зоны нестрогое невозрастание сохраняется; скачки
внутри razor-зоны допустимы.** Операционально на лестнице: P(0.95) ≥
P(0.8) ≥ P(0.5); ступени 1.0 → 0.99 → 0.95 на невозрастание не
проверяются (0.99 — внутри razor-зоны).

### 10.3 Change-control: gate_contract ревизия v3 — следующий вагон

Три пробы v2 и зонная монотонность — изменения замороженного
`gate_contract.json` (D1-протокол): коридор near_boundary (§4), инвариант
монотонности (§4), пополнение таксономии §7. По change-control §6:

- оформляется **ревизией v3 контракта** + аддендумом-пререгистрацией
  ДО прогона оценки;
- **пороги — отдельным вагоном от артефактов**: PR контракта не содержит
  корпусных или весовых изменений, и наоборот;
- пин sha256 в §6 обновится волной корпуса dataset-v4.1;
- **в этой волне (D4-2) `gate_contract.json` не трогается** — ревизия v3
  едет следующим вагоном корпуса.

**Исполнение (волна D4-3, 2026-10-05):** ревизия v3 контракта — sha256
`abca91ea3d08a968842645550eb7a6c0592088da8b362401222925e4c948288e`
(пин §6 обновлён), зонды v2 — `cortex.eval.sanity` (константы когерентны
секции `sanity_v2`, пиннуто тестом), корпус v4.1 и финал аддендума 5b —
отдельными коммитами того же вагона; пороговых артефактов (весов) вагон
не содержит.
