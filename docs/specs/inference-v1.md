# Инференс-спека mnema-cortex-v1

- **Статус:** Accepted (срез A3a; фиксирует контракт артефакта до реализации
  обучения — ADR 0001 [V3](../decisions/0001-archcom-a1-verdicts.md), аддендум
  владельца П2)
- **Дата:** 2026-09-29
- **Область:** контракт инференса runtime-артефакта `mnema-cortex-v1` — вход,
  выход, формат файла, загрузка, ошибки, версионирование. Потребитель спеки —
  волна W5d движка vesmaro (обёртка `MnemaProvider`) и экспорт этой репы (A6).
  Обучение и фичи-алгоритмы — срезы A3b+, эта спека их НЕ определяет.

Имена файлов/классов движка приведены по состоянию main на 2026-09-29
(read-only инспекция); движок цитируется как прецедент, не меняется.

## 1. Вход: канонический JSON пары (вариант D — базовый)

Вход артефакта — подготовленное canon-состояние по правилу 2
[ADR 0004](https://github.com/vesmaro/vesmaro-canon) канона: два
`CanonRecordView` (движок, `src/vesmaro/decision_provider.py`) + измеренное
сходство. Провайдер никогда не ре-измеряет косинус — принцип CanonState
«providers consume it, never re-measure».

```json
{
  "candidate": {
    "body": "<тело записи>",
    "language": "ru | en | null",
    "record_type": "note | snippet | fact | null",
    "tags": ["тег1", "тег2"],
    "title": "<заголовок>"
  },
  "record": {
    "body": "…",
    "language": "…",
    "record_type": "…",
    "tags": ["…"],
    "title": "…"
  },
  "similarity": 0.9312
}
```

Правила:

- Поля каждой стороны — в точности поля `CanonRecordView`: `title`, `body`,
  `tags` (массив строк; в движке — tuple), `language`, `record_type`.
  `language`/`record_type` — `null` для до-канонных записей (движок
  `CanonRecordView.from_memory` читает их из `metadata.canon`).
- `record` = запись a (более ранняя), `candidate` = запись b — порядок
  зафиксирован препрегом v2 (протокол W5c: «a — более ранняя запись»).
- `similarity` — измеренный косинус vector-leg движка над эмбеддингами
  mnema-embed-v1 (384-dim, unit-normalized); передаётся вызываемым кодом,
  артефакт его не вычисляет.
- **Канонизация для фингерпринтов** (дисциплина препрега): JSON с
  сортировкой ключей (`sort_keys=True`), UTF-8 (`ensure_ascii=False`),
  без лишних пробелов (`separators=(",", ":")`) → sha256. Канонический JSON
  пары — единственная основа `pair_sha256` (контракт данных,
  [data-contract.md](data-contract.md)).

## 2. Вход: вариант N (gated)

После аддендума ADR 0004 канона (передача векторов в CanonState) вариант N
добавляет к схеме:

```json
{
  "vectors": {
    "a": [384 × float32],
    "b": [384 × float32]
  }
}
```

- Векторы — стор-эмбеддинги mnema-embed-v1 (без ре-эмбеда: drift-запрет,
  ADR 0001, отвергнутая альтернатива «Self-embed провайдером в рантайме»).
- **Гейт:** вариант N не подключается к прод до аддендума канона. До того
  раннер оценки (A5) читает векторы сам, напрямую из стора — оценка
  аддендумом не блокирована (ADR 0001, «Зависимость» в V1).
- Артефакт варианта N обязателен к ассерту `embedder_pin` (раздел 6) даже
  строже, чем D: векторы — его прямый вход.

## 3. Выход: Noul + Score (оба обязательны)

Выход соответствует примитивам движка (`src/vesmaro/decision_provider.py`):
`Noul` и `Score`. Метрики 1 и 6 препрега требуют 100 % типизированной
полноты — свободный текст запрещён.

```json
{
  "noul": {
    "question": "is-duplicate",
    "probability": 0.87
  },
  "score": {
    "spectrum": "record-quality",
    "value": 0.5,
    "confidence": 0.5
  }
}
```

- **Noul** — вопрос `"is-duplicate"` (константа движка
  `QUESTION_IS_DUPLICATE`), `probability` ∈ [0, 1] — P(duplicate). Это
  калиброванная вероятность, не ступень: отличие от baseline, у которого
  `DeterministicProvider._is_duplicate_probability` возвращает жёсткие
  {0.0, 1.0} по порогу 0.92.
- **Score** — `"record-quality"` (константа `SPECTRUM_RECORD_QUALITY`),
  value/confidence = 0.5/0.5: плейсхолдер `RECORD_QUALITY_PLACEHOLDER` /
  `RECORD_QUALITY_CONFIDENCE` движка, NO-DATA дисциплина препрега (истинных
  меток качества в корпусе нет; фиксируется только типизированная полнота).
  Значение константно, пока калибровка record-quality не станет отдельной
  задачей (чартер §2 — вне скоупа).
- Про уверенность Noul — см. «Открытые вопросы», OQ-1.

## 4. Артефакт: одиночный ONNX, self-contained

Формат — по вердикту V3 ADR 0001 и аддендуму П2:

- **Один файл `model.onnx` ≤ 5 МБ** (`MAX_ARTIFACT_BYTES = 5 × 1024 × 1024`),
  self-contained: артефакт не требует кода библиотеки cortex для инференса
  (П2). Sklearn-pickle запрещён категорически (ADR 0001).
- **opset 15** — как у mnema-embed-v1 (`manifest.json` бандла движка,
  `src/vesmaro/models/mnema-embed-v1/`).
- **Feature-вход графа.** Фичи пары считаются ДО графа — в обёртке W5d на
  стороне движка (детерминированный Python, без сети); граф принимает
  готовый вектор:
  - вариант D: один вход `features: float32[K]` → выход `probability:
    float32[1]` ∈ [0,1] (sigmoid внутри графа);
  - вариант N: входы `scalars: float32[K]` и `vectors: float32[4, 384]`
    (блок `[a, b, |a−b|, a⊙b]`) → `probability: float32[1]`.
- **K и состав фич заморожены** в этой репе: упорядоченный список
  `FEATURE_NAMES` в `src/cortex/features/pair.py` (срез A3a). Список
  пиннуется в метаданных (ниже) — рассинхрон обёртки и артефакта
  обнаруживается ассертом длины/хэша, а не молчаливым сдвигом.
- **metadata_props** (ONNX model metadata, строки):

| Ключ | Значение | Назначение |
|---|---|---|
| `name` | `mnema-cortex` | идентичность модели (без суффикса версии) |
| `version` | `1` | мажор схемы; освежение весов внутри v1 → `1.<n>` (прецедент: mnema-embed-v1 → `1.1.0`) |
| `embedder_pin` | `nano:sha256:<hex>` | пин эмбеддера — точный формат живого fingerprint движка |
| `corpus_fingerprint` | `<blake2b-256 hex>` | фингерпринт train-корпуса (манифест пар, схема препрега) |
| `trained_at` | ISO-8601 UTC | провенанс |
| `candidate` | `d-boost` \| `n-head` | какой кандидат лестницы выиграл отбор |
| `features` | имена фич, `\n`-joined, в порядке входа | feature-контракт графа |
| `feature_set_sha256` | sha256 строки `features` | компактный ассерт состава |

- **sha256 файла `model.onnx` = fingerprint весов** — тот же дисциплинарный
  паттерн, что `mnema_weights_sha256` движка (`src/vesmaro/embeddings/__init__.py`).
  Смена весов = новый sha256 = событие перекалибровки (ADR-0021 движка,
  препрег «События перекалибровки»).

### Бандл в движке (образец mnema-embed-v1)

Поставка в дистрибутив движка — каталог
`src/vesmaro/models/mnema-cortex-v1/` c `model.onnx` + `manifest.json`
(машинные строки — латиница, ADR 0001 V4). Загрузка через
`importlib.resources` — паттерн `_mnema_artifact_dir`. Токенайзер не нужен:
артефакт не потребляет сырой текст, только фичи/векторы.

## 5. Выходные значения и их границы

- `probability` обязан попадать в [0, 1]; выход за границы = ошибка декода
  (`CORTEX-E-INFER`, раздел 7), не клип.
- `Score` всегда константа 0.5/0.5 (раздел 3) — артефакт обязан выдать оба
  примитива на каждый запрос; отсутствие Score = провал метрики 6.

## 6. Загрузка: паттерн NanoProvider (требование к W5d)

Обёртка `MnemaProvider` в движке повторяет паттерн `NanoProvider`
(`src/vesmaro/embeddings/__init__.py`), шаги и отказы:

1. **Eager init** — загрузка в конструкторе провайдера, без ленивости;
   старт движка либо поднимает модель, либо громко падает в warn-режиме
   (раздел 7).
2. **Валидация metadata_props** — `name == "mnema-cortex"`, `version`
   совместим (мажор `1`) → иначе `CORTEX-E-META`.
3. **Гейт размера** — файл ≤ 5 МБ → иначе `CORTEX-E-SIZE`.
4. **sha256 файла** — считается при загрузке, пишется в телеметрию
   (fingerprint весов).
5. **Ассерт `embedder_pin`** — значение из metadata_props сравнивается с
   живым fingerprint эмбеддера движка (`EmbeddingProvider.fingerprint`,
   для nano — `nano:sha256:<hex>`). Несовпадение = `CORTEX-E-PIN`,
   громкий отказ: это событие перекалибровки (смена vintage, ADR-0021),
   артефакт не может молча работать на другой геометрии.
6. **Сессия ORT** — `CPUExecutionProvider`, потоки по паттерну движка:
   `VESMARO_ORT_THREADS` (fallback `OMP_NUM_THREADS`, дефолт 4),
   `inter_op_num_threads = 1`.
7. **Smoke-inference на старте** — один синтетический валидный вход
   (нули размерности K / K+4×384) прогоняется через граф; проверяются
   форма и тип выхода → `CORTEX-E-INFER` при провале. Прецедент:
   `test = self._infer(["test"])` в конструкторе NanoProvider.
8. **Ассерт фич-контракта** — обёртка знает свой ordered-список фич;
   `feature_set_sha256` из метаданных обязан совпасть → иначе
   `CORTEX-E-META` (рассинхрон обёртки и графа).

Δdeps движка = 0: onnxruntime ≥ 1.20 уже в core-зависимостях движка
(`pyproject.toml`, NM-1c ADR-0021); токенайзер артефакту не нужен.

## 7. Ошибки и fail-open (требование к W5d)

Коды — машинные строки, латиница (ADR 0001 V4), логируются
машино-парсируемо (дисциплина телеметрии канон §9):

| Код | Условие | Момент |
|---|---|---|
| `CORTEX-E-SIZE` | файл артефакта > 5 МБ | загрузка |
| `CORTEX-E-LOAD` | файл отсутствует/повреждён; init сессии ORT упал | загрузка |
| `CORTEX-E-META` | metadata_props отсутствуют/невалидны: name≠`mnema-cortex`, несовместимый мажор, провал `feature_set_sha256` | загрузка |
| `CORTEX-E-PIN` | `embedder_pin` ≠ живому fingerprint эмбеддера | загрузка |
| `CORTEX-E-SCHEMA` | входной JSON нарушает каноническую схему (нет сторон/similarity, неверные типы, размерность векторов ≠ 384) | запрос |
| `CORTEX-E-INFER` | прогон ORT упал; выход не decodится; probability ∉ [0,1] | запрос |

**Семантика fail-open** (V3): любой `CORTEX-E-*` → деградация на
`DeterministicProvider` движка (порог 0.92) + warn с кодом; ingest и
остальной путь движка не блокируются. Громкость обязательна: молчаливое
продолжение работы mnema после отказа запрещено — warn-код в логе есть
всегда. `CORTEX-E-PIN` дополнительно телеграфируется как событие
перекалибровки (не штатная деградация).

## 8. Версионирование

- **`version` в metadata_props:** `1` при выпуске v1. Освежение весов внутри
  v1 (перекалибровка по той же препрегистрации) → `1.<n>` при новом sha256;
  имя каталога `mnema-cortex-v1` не меняется. Прецедент: mnema-embed-v1
  (`version: 1.1.0` в бандле движка при неизменном имени каталога).
- **v2 = ломающее изменение** входной схемы (состав CanonRecordView-полей,
  семантика similarity, вход-контракт графа) или выходной семантики. v2 —
  новый каталог `mnema-cortex-v2` в движке; сосуществование с v1 — решение
  волны удаления, не этой спеки.
- **Смена весов внутри v1** = новый sha256 = событие перекалибровки
  (препрег v2, «События перекалибровки»): повторная оценка по замороженной
  процедуре до допуска к продуктовым решениям. Смена метки имени — НЕ
  событие перекалибровки (ADR 0001, П1).
- Порог применения вердикта выбирает W5d, не артефакт: probability —
  калиброванное число, политика порога живёт в продукте (правило 1
  ADR 0004; принятый риск ArchCom A1: «порог применения выбирает W5d,
  не наследуется»).

## 9. Import-изоляция: ноль сети

- Артефакт и обёртка W5d не содержат сетевых импортов: `socket`,
  `urllib`, `http`, `requests`, `httpx`, `aiohttp`, `ftp` — запрещены в
  модуле провайдера. Паттерн гарантии — AST-трипвайр движка
  `tests/test_mcp_core_isolation.py` (запрет импорта mcp вне
  `mcp_server.py`): W5d добавляет аналогичный тест-хранитель для
  `MnemaProvider`.
- Эта репа несёт тот же запрет уже в A3a: `tests/test_skeleton.py`
  сканирует `src/cortex` на сетевые импорты (ноль допусков, без
  allow-list). Обучение и оценка локальны; стор читается через read-only
  URI `file:...?mode=ro` (контракт данных).
- Ограничение двух эпостасей (П2): код обучения (torch/lightgbm/sklearn)
  никогда не попадает в runtime-зависимости движка; артефакт никогда не
  требует кода этой библиотеки.

## 10. Открытые вопросы

Факты движка, не согласованные с контрактными документами на момент A3a.
Обходов нет — фиксируются здесь и выносятся в отчёт среза.

- **OQ-1. `Noul` без поля `confidence`.** Архитектурный контракт A1
  (таблица компонентов, строка `artifact`) и брифинг среза описывают выход
  как `Noul(is-duplicate, probability, confidence)`, но действующий
  `Noul` движка (`src/vesmaro/decision_provider.py`) —
  `{question, probability}` без confidence. Варианты: (a) не расширять —
  калиброванная probability сама несёт уверенность бинарного вопроса
  (рекомендация: дешёвое, семантически честное); (b) расширить `Noul`
  полем `confidence` в аддендуме ADR 0004 (W5d) — тогда отображение
  `confidence = max(p, 1−p)`. Спека фиксирует выход как `{question,
  probability}` по текущему интерфейсу; артефакт отдаёт probability,
  confidence-маппинг — решением OQ-1. Нужна точка канона (W5d).
- **OQ-2. Дельта времени в фичах.** Архитектурный контракт A1 называет в
  `pair_features` «дельты метаданных (длины, время, тип, язык)», но
  `CanonRecordView` не несёт `created_at` — на инференсе дельта времени
  невычислима из правила-2 состояния. Решение A3a: замороженный
  `FEATURE_NAMES` НЕ содержит time-фичи (артефакт не может зависеть от
  поля, которого нет во входном контракте); `created_at` остаётся в
  оценочном pair-манифесте (пререг: экспорт включает `created_at`) как
  train-сторона диагностика. Если time-фича понадобится — сначала аддендум
  канона о расширении CanonRecordView, потом фича. Нужна точка ArchCom.
- **OQ-3. Векторы в CanonState** (известный, gated): вариант N ждёт
  аддендума ADR 0004 канона; до того N живёт только в раннере оценки,
  который читает векторы сам. Не блокирует A5 и вариант D.
