## 1. Правило подтверждающего гейта (владелец, 22.10)

Кандидат r7 — экспорт `wt/embed-r7-train/training/runs/embed-r7/export/int8-dynamic/`,
weights sha256 `a186abaa500e9776cd80af23829d479e253e3c38ec7e20ee0071b8ac1e3b9422`
(верифицирован TL 22.10; совпадает с `gate_r7_report.json` 18.10).

- **Исход:** r7 проходит PA-Q1 на ОБОИХ гейт-наборах (запечатанный `cb367577…`
  и свежий `r5_gate_v2`) ⇒ **ADOPT** (релизный поезд: тег, GitHub Release,
  бандл в vesma, pin VesmaProvider, cortex-recalib, версионная
  ре-векторизация). Не проходит хотя бы на одном ⇒ **REJECT финален**,
  embed-линия закрывается, следующая — cortex B2-граф.
- **PA-Q1 формула** (АрхКом 20.10, позиция прод-архитектора Q1; пороги из
  брифа владельца 22.10):
  - G1: llm-страта cross R@5 ≥ **0.90** КАЖДОЕ направление отдельно;
  - G2: полы страт (overall): real ≥ **0.90**, twin ≥ **0.95**, seed-dup ≥ **0.90**;
  - G3: mono best-distractor медиана по направлениям: |Δ кандидат − прод| ≤ **0.005**
    отдельно en-сторона, отдельно ru-сторона;
  - G4: max_rank ≤ **80** (overall; per-direction публикуется);
  - G5: no-regression: total cross R@5 ≥ prod_total + **0.02**.
- **Дисциплина:** single-shot на финальной форме артефакта (int8-dynamic),
  один прогон на набор, re-roll'ы запрещены; прод-якорь измеряется тем же
  раннером (plumbing, `3b752e06…`); измерительная механика — verbatim r5
  (`training.embed_r5.gate_r5`); reporting extension (class×direction,
  per-side mono, per-pair ранги) — измерительно-аддитивная, коммитится ДО
  прогона (совершено: `4875e9b`, feat/embed-r7-train).
- **Часть A — исполнена и верифицирована 22.10:** PASS по G1..G5 на
  `cb367577`; TL-пересчёт из per-pair дампа совпал бит-в-бит; ретро-числа
  АрхКома воспроизведены (llm 0.9265/0.9706, total 0.9556, max_rank 64,
  mono +0.0027/+0.0013).

## 2. АДДЕНДУМ 1 (TL, 22.10): материал v2 — свежая генерация, не семейный пул

### 2.1 Доказанная неисполнимость исходного рецепта

Рецепт владельца для v2: «рецепт cb367577 + новый seed + страты крупнее
(~220-260) + замена label-noise 106/141/163 + zero-overlap proofs vs
cb367577 / все training corpora / burned V43-TDUP». Survey 22.10
(DE; воспроизведён TL байт-точно, импорт хелперов `build_gate_set.py`,
corpus fp `7a3bf00b…` asserted, eligible pool 3478 = llm 1617 / real 1451 /
twin 330 / seed-dup 80 — совпадает с манифестом-оригиналом):

| Стадия каскада исключений | Осталось пар |
|---|---|
| eligible-пул | 3478 |
| − стороны cb367577 (5a) | 3291 |
| − burned V43-TDUP (5c) | 3291 (0 пересечений) |
| − ЛЮБАЯ из training-поверхностей (5b: r4 corpus / r4 gen / r5 corpus / r7 corpus) | **0** |

Причина структурная: cb367577 вырезан ДО сборки корпусов r5/r7, и те
исключили его 315 строк; всё остальное семейство осталось в
training-поверхности round-5/6/7. Диагностика по сторонам: llm/seed-dup/twin
— 100% обеих сторон в r5|r7; real — 1388/1388 dst-сторон. Семейный v2 был бы
измерен на текстах, которые кандидат учил контрастивом → фальсификатор
фиктивен (смещение вверх).

### 2.2 Отклонённые альтернативы

- **B (tatoeba-only набор)** — чист, но одностратен: ратифицированная
  страт-формула Q1 (G1/G2 по llm/real/seed-dup/twin) на нём невычислима.
  Пере-скуоп гейт-формы после увиденных результатов части A = HARKing,
  требует решения владельца — не TL.
- **D (семейный пул с раскрытой контаминацией)** — смещение только вверх;
  информативен лишь в сторону FAIL, подтверждающим гейтом быть не может.
- **E (пересборка корпуса + ретрейн)** — это round-9, не подтвердающий
  прогон; вне санкционированного скоупа волны.

### 2.3 Решение: материал — свежая генерация (форма гейта неизменна)

- **Источник текстов** — заметко-подобный материал, отсутствующий во ВСЕХ
  training-поверхностях: Tatoeba-пул quality-pass минус 750 обученных
  псевдо-заметок и минус расширенный де-контам (пул 122 747 чистых заметок,
  survey 22.10), реальные записи стора с created_at позже потолка
  real-part (2026-10-07T16:30:05Z — граница training-поверхности real-класса).
  Availability-манифест по стратам — ДО генерации, честные девиации вместо
  добивки грязным материалом.
- **Цель 224 пары** (TL-решение 22.10 по availability-манифесту):
  llm 125 / seed-dup 40 / twin 52 / real 7 — исходные пропорции оригинала
  (91/82/29/38) урезаны реальностью real-источника: в сторе после потолка
  real-part доменных записей 7 (сервисные записи агентов не считаются —
  не тот класс материала), дефицит перераспределён на llm/seed-dup/twin
  (дополнительная мощность — в llm-страту, где у кандидата наименьший
  запас к порогу). Итог в коридоре «~220-260» брифа владельца.
  G2-real на n=7 вырожденно-строг (все 7 в top-5) — принимается как
  свойство консервативного фальсификатора; en→ru клетка real = 0
  (мониторинг). Постстратный баланс направлений ±1.
- **Конструкторы страт** сохраняют семантику оригинала (llm = перевод
  заметки учителем; seed-dup = record/translation конструкция; twin =
  synth-twin пара; real = реальная запись + перевод).
- **Учитель** — тот же, что round-7: Qwen3-1.7B-Instruct Q8_0 локально.
  Качество пар — гейты round-4/5/7: digit-preservation на каждой паре,
  teacher-cos ≥0.55, анти-копия, A-серия ассертов, n-граммы 8-13
  zero-tolerance нового материала против всех training-поверхностей.
- **Детерминизм:** генерация однократна → пул замораживается (fp пула в
  манифесте) → селекция из замороженного пула детерминирована → double-run
  = два прогона селекции byte-identical (прецедент: corpus fp + double-run
  build). Seeds: старый 42, новый 385918605 — оба в манифесте.
- **Zero-overlap proofs (все = 0, hash-уровень):** vs cb367577 (360),
  vs все training-поверхности (r4 corpus+gen, r5 corpus вкл. tatoeba-750,
  r7 corpus+gen, v43 datasets/real-part/seed, burned V43-TDUP 288),
  + стороны label-noise пар 106/141/163.
- **Дистрактор-механика раннера не меняется** (240 same-language из пула
  r4-корпуса, одинаково для обоих наборов и обеих моделей). Известное
  свойство: дистракторы частично видны кандидату в обучении → консервативное
  смещение ПРОТИВ кандидата, одинаковое с прод-якорем; для фальсификатора
  приемлемо и фиксируется.
- **Выход:** `data/embed-r4/r5_gate_v2/` (gate_set.jsonl — схема байт-в-байт
  cb367577, манифест numbers-only, fp); коммит numbers-only отдельно от
  этого документа (правило разделения документов и артефактов).
- **Seal:** fp докладывается TL; набор читает только раннер.

### 2.4 Что НЕ меняется

PA-Q1 формула (§1), пороги, population-классы, single-shot дисциплина,
правило «обоих наборов», прод-якорь, ранняя косинусная рамка остаётся
без веса вердикта (АрхКом 20.10).

## 3. АДДЕНДУМ 2 (TL, 22.10, ДО прогона части B): замороженный пул дистракторов для набора B

- **Факт** (установлен ML 22.10 исполнением на read-only входах, без
  измерений артефакта): пул дистракторов раннера — детерминированная
  функция полей `corpus_row_src/dst` строк гейт-набора (family-стратификация
  рецепта phase-0, seed 42, 240/язык). В наборе B эти поля `null` по
  построению (свежий материал вне r4-корпуса) — построение пула по рецепту
  невозможно («pool too small: 0»). Дополнительно раннер пришит к набору A:
  путь, sha-ассерт `cb367577…`, счётный ассерт `len == 180`.
- **Решение — замороженный пул:** для части B пул дистракторов = **точный
  пул части A** (детерминированная функция `cb367577 × seed 42 × 240/язык`),
  выгруженный в файл с sha256 и подаваемый раннеру аддитивным аргументом
  `--distractor-pool`. Самопроверка заморозки: две сборки byte-identical;
  ассерт раннера при загрузке: пересечение пула со сторонами набора B = 0
  (следует из zero-overlap proofs, проверяется кодом).
- **Раннер — аддитивные аргументы** (дефолты = поведение части A бит-в-бит):
  `--gate-set PATH`, `--expected-gate-sha HEX`, `--distractor-pool PATH`;
  счётный ассерт 180 снимается в пользу sha-пиннинга файла набора (sha
  фиксирует файл точно); метка набора проходит в отчёт (провенанс).
  Измерительная математика (эмбеддинг, ранжирование, метрики G1..G5) не
  трогается; правки коммитятся ДО прогона.
- **Обоснование сравнимости:** идентичный competitor-набор для обоих
  подтверждающих прогонов изолирует переменную текстов гейта — A и B
  различаются только самими парами. Консервативное свойство дистракторов
  из r4-корпуса (training-видимые кандидату) одинаково для кандидата и
  прод-якоря (§2.3). Альтернатива «пересборка по распределению семейств
  набора A» отклонена: добавила бы шум регенерации пула в сравнение A vs B.
- **Формула PA-Q1, пороги, single-shot дисциплина — без изменений.**
  Run-лог части B фиксирует и остановку до прогона (STOP before run),
  и сам прогон — append-only.

## 4. АДДЕНДУМ 3 (TL, 22.10, ДО прогона части B): plumbing-ассерт при не-дефолтном наборе

- **Факт** (установлен ML 22.10 до прогона, single-shot не расходован):
  STORED-флоры plumbing-ассерта (`mono_overall 0.8982`, `cross_r5 0.8722`,
  `proxy_median 0.9014`, `proxy_scal 0.6889`) — characterization прода
  `3b752e06…` на населении набора A + пул A, допуски ±0.0005/±0.002.
  На наборе B прод измеряется на другом населении (223 свежие пары) —
  жёсткое сравнение детерминированно валит прогон ДО измерения кандидата.
- **Решение (вариант A):** при не-дефолтном `--gate-set` жёсткое сравнение
  с STORED понижается до калибровочной пометки в отчёте (измеренные флоры
  прода на текущем населении записываются всегда); **sha-проверка
  идентичности прод-артефакта (`3b752e06…`) остаётся жёсткой** — она от
  населения не зависит. На дефолтном пути (набор A) поведение бит-в-бит.
- **Обоснование:** plumbing-ассерт — стража рантайма/окружения, не часть
  гейт-формулы; G3/G5 опираются на ин-процесс измерение прода на тех же
  surfaces (дифференциальная сравнимость кандидат↔прод в одном процессе),
  а не на STORED-числа. Вариант B (регистрация set-B прод-якоря
  пред-измерением) отклонён: лишнее измерение на запечатанном наборе
  до гейта без добавленной стражи.
- **Формула PA-Q1, пороги, single-shot дисциплина — без изменений.**
