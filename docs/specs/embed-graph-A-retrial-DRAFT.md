## 2. Объектив: варианты инъекции граф-контекста

Обозначения: u, v — записи; e(u,v)=1 — формальное ребро; cos — косинус
энкодера; τ_dup = 0.97 (верхняя граница dup-зоны, константа is-duplicate);
FR-* — таксономия framing §7.1.

### (A1) Мультитаск-контрастив на рёбрах с зона-сохраняющими маржинами

**Механика.** Три члена лосса на одной геометрии:

1. `L_rel` — рёберный контрастив с **односторонним насыщающим хинджем**:
   `L_rel = max(0, τ_rel − cos(u,v))²` на парах-позитивах из рёбер.
   Механика против стягивания dup-зоны (прямой ответ на вопрос реестра R1):
   градиент **равен нулю** при cos ≥ τ_rel — позитив тянет пару только до
   цели «достаточно близко», никогда «до единицы». τ_rel = 0.92 (PROPOSED —
   нижняя граница зоны похожести): пары-рёбра, уже сидящие ≥0.92 (~84 %
   позитивов; 16 % ниже 0.92 — факт манифеста MLC), получают нулевую тягу.
   Обучение давит ТОЛЬКО туда, где косинус недобирает относительно
   формального родства — геометрия dup-зоны не получает рёберной тяги
   по построению, а не по надежде на регуляризацию.
2. `L_dup` — **dup-якорь**: `max(0, cos(u,v) − τ_dup)²` на выборке пар
   FR-N-hard (0.92–0.97 без эвиденса) — «не поднимать выше 0.97 то, что
   движок различил»; плюс **preservation-член** на реальных seed-dup парах
   (68 пере-сохранений, нулевой граф-вектор, все NOT-эвиденс): не опускать
   ниже их прод-значения минус маржа. Якоря — формальные предикаты, не слова.
3. `L_KD` — **KD-реплей-якорь** к прод-векторам (посрезовая MSE 64/128/256/384
   с L2-ренормализацией, рецепт r5) на широком реплей-миксе (§5). Это главный
   зона-сохраняющий механизм: вся геометрия, кроме явно адресованных рёберных
   пар, привязана к прод-геометрии; оверсэмплинг пар зоны [0.92, 1.0] в миксе
   (вес, ратифицируемый в составе) защищает территорию is-duplicate
   дополнительно. Негативы — in-batch + hard-negative mining из FR-N-hard.

Итого: `L = L_KD + λ_rel·L_rel + λ_dup·L_dup`; сетка λ/τ — пилотом на val до
полного прогона (прецедент r5-пилот), фиксация в run-log до полного прогона.

**Данные.** Позитивы: рёбра снапшота после гигиены минус маска (§5).
Негативы: FR-N-hard/FR-N-far квоты. Якоря: seed-dup + FR-X-сэмпл + реплей-микс.
Честный объём: рёбер 1 844 — на порядок ниже контрастив-корпусов r5–r7
(25k+ пар); компенсация — in-batch-негативы (каждое ребро создаёт O(batch)
пар), KD-якорь не требует пар-меток. Оценка сигнала — characterization (§6).

**Сдвиг геометрии:** умеренный (полный тренинг энкодера; KD-якорь ограничивает
радиус дрейфа, но не обнуляет его).

**Риск для v42:** прямой — новые векторы = новый пин = полный CORTEX-E-PIN (§7);
raw-v42 на новой геометрии ожидаемо просядет (это измеряет leg-raw §4).

**Стоимость:** лайны 21h-класса (прецедент r8: 21h20m, zero kills); 2–4
CPU-дня лайнов; календарно см. §8.

### (A2) Adapter/LoRA-дообучение замороженной базы

**Механика.** База — веса прод-семейства (30M-класс, fp-преемник round-3 из
training-репо); тренируется низкоранговый адаптер (LoRA, ранг из пилот-сетки)
при замороженной базе; объектив — тот же (A1); экспорт = merge → dynamic int8
(рецепт r5/6/7, проверен cos 0.9994 к fp32; static int8/fp16 запрещены).
Против r8-ломкости: полный FT harrier дал кросс 1.0→0.9694 после 4 эпох и
кандидата 0.7417; LoRA ограничивает число степеней свободы сдвига геометрии
тем же механизмом, каким r8-урок диагностировал болезнь.

**Честная оценка «параллельного индекса без пере-эмбеддинга»** (поставлено
брифом): adapter меняет ФУНКЦИЮ энкодера — каждый вектор стора в новой
геометрии ≠ старому; старый индекс для новой геометрии нечётен. Вариант
«параллельный индекс» означает: старые векторы остаются каноническими
(is-duplicate не тронут — pin-налог на is-duplicate НЕ платится), новая
геометрия обслуживает второй индекс поиска. Цена: (а) двойное эмбеддинг-
умножение на записи (два инференса); (б) движковая волна второго индекса
(та же, что у опции D); (в) постоянный архитектурный форк «поиск живёт в
фьюжн-геометрии, дедуп — в базовой» с навсегда разделённой атрибуцией.
Вердикт честной оценки: **параллельный индекс = экономика D при худшем
рантайме и худшей атрибуции** — если платить двойную геометрию, D делает это
малой головой вместо второго полного энкодера. Поэтому параллельный индекс
**отвергается как дефолт** (возврат — только явным решением владельца, §10);
pin-налог при ADOPT платится полным планом §7. LoRA при этом остаётся
ценным как РЕЖИМ ТРЕНИНГА (ограничитель ломкости), независимо от деплой-формы.

**Данные / сдвиг геометрии / риск v42:** данные те же (A1); сдвиг — малый–
умеренный (ранг-кап); риск v42 тот же по структуре (новый пин), меньше по
амплитуде. Вариант init: (i) прод-база round-3 — чистая атрибуция, чистый mono-
якорь (рекомендуется); (ii) init от r6/r7-класса чекпоинта (кросс R@5 0.9556,
REJECT которого — артефакт cosine-рамки, но mono-en −0.0191 на свежем материале
— реальная эрозия) — только по мягкому триггеру characterization (если
прод-init не двигает primary на val), pre-registered.

**Стоимость:** лайны легче полного FT — консервативно планируются в том же
потолке r8-класса (MemoryMax 14G), фактический порядок 5–15 ч/лайн.

### (A3) Структурный вспомогательный loss (общие соседи / степени)

**Механика.** Вспомогательный член, предсказывающий структурные величины пары:
наличие/число общих рёберных соседей (cn — формальный предикат снапшота) как
бинарная/регрессионная голова, опционально triplet по 2-hop структуре.
Сигнал чисто структурный: «граф-прайор» в геометрии без контентного
контрастива.

**Честная роль:** самостоятельным объективом слаб — 1 844 рёбер дают тонкую
cn-структуру (средняя степень ~4.1); как **aux к A1/A2 с малым λ_struct
(pre-registered)** — регуляризатор, чей вклад измеряется ablation-ногой
(с-aux vs без-aux), а не верой. Не вносит собственный конфликт с dup-зоной
(не тянет контентные пары вместе), риск v42 минимальный.

**Стоимость:** маргинальная над A1/A2 (одна голова + член лосса).

### Рекомендация

**Рекомендую составной объектив: A2-режим (LoRA на замороженной прод-базе,
init-прод) × A1-лосс (насыщающий хиндж τ_rel=0.92 + dup-якорь + KD-реплей с
оверсэмплингом зоны) + A3-структурная aux как низковесная pre-registered нога
(вклад меряет ablation).** Обоснование: что учить — определяет A1 (единственный
из трёх, прямо адресующий родство через формальные метки с механикой защиты
dup-зоны по построению); как не повторить r8-ломкость — определяет A2 (ранг-кап
вместо полного FT — прямой ответ на измеренный отказ); чем регулялизовать —
A3. Полный FT как arm не пред-регистрируется (r8-урок); init от r6/r7 — только
по мягкому триггеру characterization. Аттрибуция членов лосса — обязательная
ablation-матрица в characterization (полный / без-aux / без-L_dup / только-KD).

ДО тяжёлых лайнов (K1/K2 §6) и forecasting-полосами П6 (§6) — владелец
получает фальсифицируемый прогноз, а не надежду.

## 4. Исправленная рамка оценки

**Первичная: PA-Q1 retrieval-form** (вердикт АрхКома 20.10; прецедент
r7-confirm, где retrieval-превосходство генерализовалось, а косинусные
охранные — нет). Две запечатанных поверхности, правило «обоих наборов»
наследуется binding'ом: PASS на обоих = ADOPT; иначе REJECT финален.

### 4.1 Что уходит и почему

| Старый гейт | Судьба | Почему |
|---|---|---|
| llm-класс косинус: мед ≥0.93 (затем 0.90), доля ≥0.85 (0.90/0.75) | **УХОДИТ** (binding) | Калибровочно неверная рамка (АрхКом 20.10): порог выше собственного прода; поверхность — переводные пары. **Остаётся monitored** как диагностика сохранения translation-геометрии — честно фиксируем: граф-объектив может её не держать, и это не красит попытку само по себе |
| seed-dup косинус: мед ≥0.85, доля ≥0.50 | **УХОДИТ** (binding, косинус-форма) | Та же рамка. Защитную роль «не обрушить dup-геометрию» наследует G2-класс retrieval-флор + dup-якорь лосса + g_nharm |
| g1 0.9252 S1m no-harm; gX0 | **УХОДИТ** | Наследие косинус-рамки; no-harm роль переезжает в g_total/g_mono/g_nharm retrieval-формы |
| Абсолютный guard max_rank ≤80 | **УХОДИТ в абсолютной форме** | Анти-урок r7-confirm B (прод сам 220 на свежем населении) — заменяется дифференциальным g_rank |
| mono-guard тренинга 0.8932 (r6-механика) | **Наследуется как training-монитор**, не гейт | Расписание-механика (KD-replay ≥1:3 при просадке прокси) — проверенный анти-эрозионный механизм; binding меряется один раз на печатях |

### 4.2 Гейты попытки (формулы; binding состав)

Прод-якорь (`3b752e06…`, sha-ассерт жёсткий) измеряется тем же раннером на
каждом наборе в том же процессе (дифференциальная сравнимость, прецедент
аддендума-3). tol_* — из полов characterization (ML-STD-0001: tol ≥ 2× max
пола; полоса [1×,2×) — явная ратификация). δ-константы — PROPOSED до
ратификации.

| Гейт | Формула | Статус / примечание |
|---|---|---|
| **g_rel** (PRIMARY) | Δrecall@5 (кандидат − прод) на masked-edge позитивах; воронка = cosine top-K + инъекция masked-позитивов запроса; multi-positive: \|позитивы в top-5\|/\|позитивы в пуле\| по запросу (MLC 28.10-форма). ≥ max(2×CI95halfwidth, δ_rel), δ_rel PROPOSED 0.02, CI = paired bootstrap по запросам (seed/ресэмплы в преге) | «Связка работает в геометрии»: родство достижимо косинусом НОВОГО энкодера лучше, чем прод |
| **g_mrr** | ΔMRR@10 ≥ max(2×пол(ΔMRR), δ_mrr PROPOSED 0.01) | Устойчивость lift по рангу |
| **g_mono** | \|Δ\| mono best-distractor медианы (кандидат − прод_на_наборе) ≤ tol_mono отдельно per direction (en-сторона, ru-сторона); tol_mono PROPOSED класс 0.005 (наследие r7-формулы владельца), пол пересчитает | Анти-эрозия одноязычного качества; та же форма, что убила r5 и часть B r7-confirm |
| **g_rank** | max_rank(кандидат) ≤ max_rank(прод_на_наборе) + tol_rank (per-direction публикуется) | Дифференциальная форма вместо мёртвого абсолюта ≤80 (анти-урок §3) |
| **g_total** | total cross R@5 ≥ прод_на_наборе + 0.02 | No-regression (формула владельца 22.10 — ратифицированный класс) |
| **G2-флоры** | real ≥ 0.90, twin ≥ 0.95, seed-dup ≥ 0.90 (PA-Q1-класс PROPOSED); pre-registered правило ре-якоря: если прод сам ниже флоры на новом населении — флора якорится к прод_на_наборе ДО прогона (никогда пост-фактум) | Защита от обрушения retrieval-геометрии классов |
| **g_nharm (binding leg-C)** | BA на v42-276 **перекалиброванного** v42 (refit бустинга на фиче-поверхности новой геометрии, калибровочный корпус v4.x-рецепта, ре-эмбед текстов корпуса) ≥ 0.9449 − max(tol; CI95) | «is-duplicate восстановим на новой геометрии» — honest-измерение pin-налога ДО ADOPT. Перекалибровка — часть попытки (дёшево: тексты существуют, ре-эмбед минутный, refit ~50 с) |
| g_nharm-raw (leg-R, **monitored**) | BA сырого v42 на новой геометрии — публикуется, не гейтует | Диагностика амплитуды сдвига; ожидаемо красный при любом реальном сдвиге (pre-declared) — binding в raw-форме был бы REJECT-машиной для любого нового энкодера, что dishonest к чартеру владельца |
| **g_lat / g_size** | mean latency ≤ 45 ms PROPOSED (g6a-класс), ≤ 60 MB (g7); измерение на финальной форме (dynamic int8) | Продуктовые константы |
| Вердикт | конъюнкция binding-ног на ОБОИХ наборах ∧ детерминизм ∧ гигиена ∧ ассерты сборки | ADOPT → §7 (pin-план) → движковая волна → релизный поезд (GWS); REJECT финален и идёт владельцу как валидный исход линии |

**П6-прогнозные полосы (плейсхолдеры до ратификации, ML-STD-0003 П6):**
ожидаемая полоса Δrecall@5 = **[X, Y]**; ожидаемая полоса BA leg-C = **[Z, W]**;
числа вносит автор линии при ратификации с power-арифметикой (~370 позитивов
@ ρ=20 % от 1 844 рёбер; после гигиены пересчитывается — 1 391/4 797 записей
не проходят гигиену, доля рёберных концов среди них замеряется в Фазе 1).
Прогноз НЕ CONFIRMED публикуется как есть, без перезаписи.

### 4.3 Kill-criteria (пре-декларированные, до прогона)

- **K1 (STOP, класс «данные»):** извлекаемых masked-позитивов в воронке <
  STOP-минимум ратификации → вердикт «датасет не поддерживает гейт при этой
  ρ» ДО тренинга; тихой смены ρ нет (наследие MLC 28.10).
- **K2 (STOP, класс «сигнал»):** пол пермутации рёбер (retrain-включающий
  розыгрыш) ≥ δ_rel в characterization → «рёберный сигнал ниже шума состава
  на этом сторе» — попытка закрывается честно до тяжёлых лайнов. Это легальный
  владелеческий исход: реестр рисков конвертирован в измерение.
- **K3 (ABORT, класс «инструмент»):** NaN/дивергенция лосса, красный fidelity-
  preflight, расхождение byte-tripwire — печати не читаются, эскалация TL.
- **K4 (early kill, легальный):** leg-R raw-BA < PROPOSED-катастрофический
  пол 0.90 → остановка до чтения печатей (v42-276 — стоячая экзаменационная
  поверхность с историей чтений, не запечатанный набор; экономит ресурс).
- **K5:** mono-прокси тренинга < порога → переключение расписания (KD-replay
  proportion ↑, r6-механика); binding меряется один раз на печатях (§4.1).

**Single-shot:** один прогон раннера на набор; re-roll после израсходованного
single-shot = отказ раннера (ML-STD-0003 П8); resume — только маркером с полным
повторным прологом. Пролог П1–П9 дословно (swap_check → env → host →
byte_tripwire → activation → frozen_inputs → gate_start; декларация стоимости
П9). **Честный REJECT — полноденный исход линии** (прецедент B2-канона); вердикт
идёт владельцу, который и принимает финальное решение отклонить/ухватить.

## 5. Данные: таксономия, гигиена, гейт-наборы

### 5.1 Формальная таксономия (директива 22.10: предикаты, не слова)

Классы FR-P / FR-N-hard / FR-N-far / FR-Q / FR-X наследуются из framing §7.1
предикатами дословно (тот же снапшот-механизм, порядок «гигиена → классы →
маска», MLC 28.10). Для тренинга эмбеддера добавляются роли:

| Роль | Предикат | В train | В гейтах |
|---|---|---|---|
| TR-POS-edge | FR-P после гигиены, minted ≤ D0, вне маски | позитивы L_rel | — |
| TR-POS-masked | FR-P, попавшие в seed-маску ρ=20 % (seed в преге) | **ЗАПРЕЩЕНО** во всех тренировочных ногах | g_rel/g_mrr (PRIMARY) |
| TR-NEG | FR-N-hard/FR-N-far квоты | in-batch/hard-негативы | g_spec-класс страта |
| TR-ANCHOR | seed-dup пары (68, все NOT-эвиденс) + FR-X сэмпл | preservation/KD-цели (геометрия, НЕ семантика) | leg-R/leg-C v42-276 отдельно |
| TR-REPLAY | реплей-микс: heritage-корпуса embed-дуги (sealed TRAINING-поверхности r5 `e64fdbea…` / r7 `ad3d438f…` — легальное переиспользование: это тренировочные поверхности, не гейт-наборы) + сэмпл текстов стора с оверсэмплингом зоны [0.92,1.0] | L_KD | — |
| FR-Q (карантин) | cn ≥ 1 без ребра | **НЕ тренируется в v1** (см. §10, вопрос 2) | вне гейтов |

**Специфика маски для эмбеддера (честно, отличие от B).** У ранжера B маска
cut-closure защищает граф-ФИЧИ (они вычисляются из рёберного графа). У
эмбеддера вход — тексты; утечка возможна только через ПАРУ: точная пара
masked-ребра не должна встречаться ни в одной тренировочной ноге (рёбра,
якоря, реплей-пары, heritage-корпуса — pair-level дизъюнктность ассертами
hash-уровня). Косвенный структурный вывод «концы masked-ребра сближаются,
потому что у каждого есть train-рёбра к общим соседям» — это НЕ утечка, это
ровно тот механизм link-prediction, который попытка и проверяет (transductive
структурный вывод — легитимная цель, не контаминация); это фиксируется в
преге словами, чтобы characterize-отчёт не пересчитывался задним числом.

### 5.2 Гигиена и дизъюнктность

Порядок data-contract §6 дословно: mode=ro → снапшот в /tmp → скан секретов
ДО экспорта → no-federate/quarantine → в репу только счётчики/фингерпринты;
`data/` gitignored. Дизъюнктность поимённо (hash-уровень): masked-пары vs все
тренировочные ноги; train-пары vs v42-276; vs калибровочные поверхности v43/
v4.4; vs сожжённые наборы `cb367577…`/`r5_gate_v2` (их материал не попадает
ни в train, ни в новые наборы); vs манифесты heritage-корпусов r5/r7.
**v4.5 и g4-spec-v1: не читаются, hash-пруфы против них НЕ строятся** (чтение
ради пруфа = сожжение) — защита по построению label-поверхности: рёберные
пары все NOT-dup (перепись: 1 296 рёберных пар все NOT-dup; 68 реальных
пере-сохранений — все с нулевым граф-вектором; дизъюнктность dup×эвиденс —
конструкция записи), а поверхности v4.5/g4-spec-v1 — dup-метки.

### 5.3 НОВЫЙ запечатанный гейт-набор (требования)

Сожжённые `cb367577…` и `r5_gate_v2` гейтами не служат. Строятся два набора,
формула и дисциплина — verbatim PA-Q1 + первичная нога:

- **Состав:** PA-Q1-страты (llm / real / twin / seed-dup; PROPOSED ~220 пар
  набором, пропорции availability-манифестом — прецедент честных девиаций
  r7-confirm §2.3) + masked-edge извлекаемые позитивы (~370 @ ρ=20 %, после
  гигиены пересчитывается) + замороженный пул дистракторов (прецедент
  аддендума-2). **Два независимых набора α и β** — свежая генерация, разные
  seed'ы (оба в манифестах), правило «обоих наборов» binding.
- **Требования (поимённо):** свежий материал вне ВСЕХ тренировочных поверхностей
  (heritage-корпуса, edge-train, якоря, калибровочные корпуса — zero-overlap
  proofs hash-уровня, все = 0); конструкторы страт сохраняют семантику PA-Q1;
  gейты качества пар (digit-preservation, teacher-cos ≥0.55, анти-копия);
  n-граммы 8–13 zero-tolerance нового материала против всех известных
  training-поверхностей; детерминизм: генерация однократна → пул замораживается
  (fp в манифесте) → double-run byte-identical; ассерты pair-ключа, заморозки
  квот/edge_kind, snapshot-относительности (MLC-набор framing §7.3
  переиспользуется поимённо).
- **Кто строит:** dataset-engineer по ратифицированному рецепту; карта
  fidelity-ассертов 1:1 + preflight на фикстурной ячейке (ML-STD-0002) до
  emission; **seal у TL**; набор читает только раннер, один раз.

## 7. Pin-налог при ADOPT (полный план CORTEX-E-PIN)

При ADOPT новый пин = радиус отказа по ADR-0002 R2. План по шагам:

| Шаг | Содержание | Оценка |
|---|---|---|
| 1. Re-embed стора | 4 797 векторов, батч-скрипт, double-run ассерты, леджер нового пина, snapshot-верификация 100 % смены пина | 0.5 дня (минуты вычислений + ассерты) |

## 9. Взаимосвязь с B/D

- **B не зависит от эмбеддера** (прод заморожен ассертом): его цикл лёгкий
  (лайны минут-часов, LightGBM ~50 с/модель) и может идти параллельно
  A-дизайну/characterization календарно. **Тяжёлая ресурсная очередь — одна**:
  21h-лайны A занимают окно; B-обучение в том же окне не ставится (дисциплина
  «одна тяжёлая линия»), лёгкие B-лайны вне окон A допустимы.
- **При ADOPT A:** B/D переучиваются на новой геометрии дёшево — B: ре-экстракция
  фич (минуты) + refit бустинга (~50 с) + перепрогон своих гейтов на новой
  геометрии (печати своих циклов — свои/новые, не эти); D: перетрейн головы
  384→384 (минуты–часы). Движковое потребление обоих — их dependency-лист.
- **При REJECT A:** B/D не затронуты — асимметрия в пользу секвенции
  «A сейчас, B следом за вердиктом».
- Guard-крас кандидата A на свежем наборе при зелёном первом = REJECT по
  правилу обоих наборов (§4); «ADOPT с флагом» для A не вводится — энкодер
  либо готов к pin-поезду, либо нет.

## 10. Вопросы владельцу

Формат ответа: «**принимаю позиции 1..N**» или правки по номерам.

1. **Объектив:** составной — LoRA-режим (A2) на замороженной прод-базе
   (init-прод; init-r7 — только по мягкому триггеру characterization) ×
   мультитаск-контрастив (A1: насыщающий хиндж τ_rel=0.92 PROPOSED, dup-якорь,
   KD-реплей с оверсэмплингом зоны) + структурная aux (A3) низковесной
   pre-registered ногой. Полный FT не пред-регистрируется.
2. **FR-Q как тренировочные позитивы** (cn ≥ 1 без ребра — косвенное родство):
   v1 = **НЕТ** (директива 22.10: спорное не размечается молча); опциональная
   нога v1.1 — только отдельной ратификацией. Рекомендую: нет в v1.
3. **δ-константы и допуски (до сборки корпуса):** δ_rel = 0.02 PROPOSED;
   δ_mrr = 0.01 PROPOSED; tol_mono класс 0.005 (наследие r7, финал — от полов
   Фазы 1); g_total ≥ прод + 0.02 (ратифицированный класс формулы владельца
   22.10); G2-флоры 0.90/0.95/0.90 PROPOSED с pre-registered правилом
   ре-якоря к прод_на_наборе.
4. **Бюджет:** ОДНА single-shot; два запечатанных набора (α+β), PASS на обоих
   = ADOPT, иначе REJECT финален (наследие правила владельца 22.10); K1/K2 —
   легальные досрочные закрытия до тяжёлых лайнов.
5. **Pin-план при ADOPT:** полный CORTEX-E-PIN по §7 (4–7 дней стены, 2–3 дня
   вне очереди линии); no-harm binding = перекалиброванный v42-корридор
   (BA ≥ 0.9449 − tol) с перекалибровкой ВНУТРИ попытки; raw-v42 = monitored;
   параллельный индекс отвергнут как дефолт.
6. **Рамка гейтов:** PA-Q1 retrieval-form первичная; косинус-гейты embed-эпохи
   уходят (llm-поверхность — только monitored); mono per-direction, дифференциальный
   max_rank, total ≥ прод+0.02 — binding; абсолюта выше значения прода на
   свежем населении не осталось нигде (анти-урок r7-confirm B).
7. **Ресурсное окно:** 21h-класс лайны с потолками MemoryMax 14G / SwapMax 16G /
   CPUQuota 800 %, детач от zcode, последовательность, swap_check первым
   событием — санкционировать в рамках iron rules.

## 11. Открытые вопросы и зависимости (не блокируют ратификацию рамки)

- fp-преемник весов прод-семейства для LoRA: наличие fp32/чека в training-репо
  верифицируется Фазой 0; если fp-весов нет — init от последнего студента
  embed-дуги становится единственным путём, и это меняет атрибуцию (отдельный
  аддендум ДО ратификации рецепта, не молча).
- Судьба ретро-таблицы retrieval-формы embed-дуги (обещана брифом 19.10) —
  не блокирует; её метрика может стать дополнительным monitored-сигналом.
- Числа стора — точка 28.10; при сборке корпуса — свежий снапшот с fp и
  пересчитанными каунтами (L6 framing).
- Движок занят волнами ADR-0049: потребление при ADOPT — волна parity в
  движковой очереди (§7), никаких движковых работ из линии.
