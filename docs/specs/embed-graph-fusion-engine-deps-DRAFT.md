## 0. Принципы (унаследованные, не новые)

- Семья узких артефактов (ADR-0002 R2/R3): фьюжн — отдельный duty
  `vesma-cortex-<fusion-duty>-v1`, свой пин-ассерт, свои часы версий, своя
  атрибуция телеметрии; фиче-ядро шарится кодом (`cortex.features.*`),
  никогда весами.
- Смена эмбеддера НЕ входит в этот лист: фьюжн v1 наследует прод-пин
  `nano:sha256:3b752e06…` ассертом; при будущей ротации эмбеддера фьюжн
  переезжает своим циклом перекалибровки (pin-куплинг = радиус отказа).
- За флагом до релизного поезда (паттерн VesmaProvider W5d); release parity —
  GWS.
- (MLC 28.10) Прогноз: production lift ≥ evaluated lift — masked-оценка видит
  меньше, чем прод; расхождение прод↔оценка при потреблении — анализ в волне,
  не сюрприз.

## 2. Пункты маршрутов C/D (НЕ активируются при маршруте B — помечены для памяти)

- **D (проекционная голова):** второй векторный индекс (f-пространство 384-dim)
  рядом с основным; двойная запись при вставке (base + fused); политика
  байт-ассерта базового индекса (нетронутость для CORTEX-фич); холодный
  бэкфилл f-векторов; pin-цепочка головы.
- **C (GNN):** второй индекс фьюжн-представлений + cold-start политика
  (индуктивный скор для записей без рёбер до их векторизации) +policy
  предсказанных рёбер (graph-completion): подача кандидатов-рёбер в консолидацию
  как ПРЕДСКАЗАНИЙ (никогда как фактов — урок L1 семантики рёбер).

## 3. Явно НЕ входит (границы)

- Любые изменения схемы векторной таблицы основного индекса (v1/B — не трогаем).
- Механика минта рёбер auto-dedupe (фьюжн читает рёбра, не пишет и не меняет
  правила).
- Консолидация (merge/supersede) — граница движка, зафиксирована
  design-package §1; фьюжн может поставлять кандидатов для будущих решений
  консолидации, но не принимает их.
- Ротация эмбеддера / re-embed — отдельные события CORTEX-E-PIN, вне этого
  листа.
- (MLC 28.10) Стадия 2 v1 НЕ расползается на auto-dedupe-селектор: фьюжн-ранкер
  потребляется только в поиске; селектор консолидации — отдельное решение вне v1.
