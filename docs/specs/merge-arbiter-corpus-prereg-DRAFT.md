**Главный вывод для корпуса — исход «какая запись живёт» (kept vs re-saved)
из имеющихся полей НЕ извлекаем, и это не дефект данных, а отсутствие
события:** обе записи каждой пары живут (обе published, обе с вектором, ни
одной могилы/ребра/пометки) — схлопывания не происходило, решать было
некому. Чего в популяции нет вообще: (а) resolved-исходов, (б) пометок
lineage_marks, (в) невырожденных различий (все 64 кластера — байт-твины).

Следствия (принимаются как дизайн-аксиомы этого прега):

1. **Реальные кластеры дают реальные ВХОДЫ, но не метки исхода.** Для
   байт-идентичных членов выбор «кого оставить» информационно вырожден:
   любой член сохраняет 100 % содержания (zero-loss, канон ADR-0019 §2b) —
   по собственной логике ADR 0002 (№7 «формализуемое правило = код, не
   модель») такой выбор — территория ратифицированного детерминированного
   правила, а не обучаемой модели.
2. **Невырожденный сигнал Choice — только синтетика с меткой по построению
   + владельческий спот-чек десятков исходов** (формула ADR 0002 №3
   выполняется не «по желанию», а по необходимости: в сторе исходов нет).
3. **`lineage_marks` как вход арбитража (policy v1.1 §8.3) в проде сейчас
   пуст** — корпус v1 опирается на синтетические пометки; реальные появятся
   только после движковой волны W1–W3 (вне этого прега — вопрос 7 владельцу).

## 1. Задача арбитра и вход-контракт

- **Вход:** кластер C = (r_1 … r_k), k ≥ 2, предъявленный ТОЛЬКО после
  серебряного воротила (§A policy: двусторонний энтейлмент + ключевые факты;
  для вырожденных классов — предикат CH-0/CH-5 ниже). Арбитр не отменяет
  вердикт is-duplicate v42 — он исполняет консолидацию там, где система уже
  считает пару дубликатом (policy §8.3: вердикт консервативен, действие —
  территория консолидации).
- **Выход (примитив Choice, 1-из-k с воздержанием):** `keep ∈ {1..k} ∪
  {ABSTAIN}`. ABSTAIN = fold не производится, записи остаются как есть
  (нулевая цена воздержания: лишние копии — шум ранжирования, дёшев и
  исправим; FP-схлопывание с потерей факта — тихо и необратимо, §2 policy —
  асимметрия унаследована и здесь).
- **Correct-set семантика:** для вырожденных классов acceptable-set = все
  члены (zero-loss при любом выборе); для CH-3 acceptable = члены-надмножества
  (в синтетике — ровно один). Попадание = `keep ∈ acceptable`; ABSTAIN
  считается отдельной величиной (g_abstain_sens), не «неверным выбором».
- **Фиче-поверхность Choice — OQ-3 (вопрос 5 владельцу):** замороженный
  pair-контракт is-dup (RecordLike: title, body, tags, language, record_type)
  не видит конверт (created_at вне контракта, OQ-2 policy). Для выбора «кто
  живёт» конверт — единственный дискриминатор реальных кластеров и
  whitelist-поле §8.1. Предложение: ОТДЕЛЬНЫЙ Choice-фиче-контракт
  (pair/cluster-фичи + конвертные поля), собственный пин по правилу
  pin-сцепки ADR 0002 (радиус отказа = только этот duty). Состав фич —
  фаза characterization, не этот документ.

## 2. Формальная таксономия классов Choice (предикаты, не слова)

Поверхность записи: `B(r) = norm1(body)` (lower + collapse whitespace — тот
же нормализатор серебра), `T(r) = norm1(title)`, `G(r) = set(tags)`,
`Y(r) = record_type`, `L(r) = language`, `sha(r) = sha256(body)`,
`E(r) = created_at`. `F(r)` — факт-множество: для синтетики — генераторская
декларация (множество вставленных/изменённых факт-токенов: числа, даты,
версии, имена, суммы по таблице маркеров §8.2); для реальных кластеров
факт-экстрактор не нужен — все они вырождены по CH-0 (текст байт-равен).
Кластер — C = (r_1…r_k), предикаты по парам (i ≠ j):

| Класс | Предикат | Fold? | Верный исход |
|---|---|---|---|
| **CH-0 identity** | ∀i≠j: sha(r_i)=sha(r_j) ∧ T_i=T_j ∧ G_i=G_j ∧ Y_i=Y_j ∧ L_i=L_j | да | keep — любой член (вырожден); модель: keep∈members или ABSTAIN, оба корректны |
| **CH-1 envelope-twin** | B, T, G, Y, L попарно тождествены ∧ ∃i≠j: \|E(r_i)−E(r_j)\| ≥ τ_E (τ_E ратифицируется; сегодня в проде 0 — все Δ ≤ 130 с сидят в CH-0) | да | keep по ратифицированному tie-break-правилу; вход — пометка same-message-other-envelope (§8.3) |
| **CH-2 metadata-mismatch** | ∀i≠j: B_i=B_j ∧ T_i=T_j ∧ (G_i≠G_j ∨ Y_i≠Y_j ∨ L_i≠L_j) | **запрещён** (T2, §1.3: метаданные управляют видимостью — подавление теряет дельту) | ABSTAIN |
| **CH-3 fact-superset** | ∃(i,j): B_i≠B_j ∧ F(r_j) ⊂ F(r_i) ∧ \|F(r_i)\F(r_j)\| ≥ 1 ∧ norm2-дельта тел исчерпывается декларированными факт-слотами (norm2 определён в §2.1 — MLC 28.10: правка N8) | да | keep = r_i (надмножество фактов — сохранение фактов) |
| **CH-4 fact-conflict** | ∃(i,j): F(r_i) ⊄ F(r_j) ∧ F(r_j) ⊄ F(r_i) при B_i ≈ B_j (razor-класс §1.2) | **запрещён** (потеря факта; урок #480 — угол «почти идентичны» уже инвертировала одну модель) | ABSTAIN |
| **CH-5 cosmetic-variant** | ¬CH-0 ∧ ∀i≠j: B_i=B_j ∧ sha(r_i)≠sha(r_j) (различие стирается нормализацией: регистр/пробелы) | да | как CH-0 — выбор вырожден |

Замыкающее правило (аналог §1.5 «спорное → NOT dup»): **класс не определён
или определён как запрещённый → ABSTAIN**. Предохранители двойные: CH-2/CH-4
не должны проходить серебряное воротило вовсе; корпус тем не менее содержит
их страты — проверка, что арбитр держит запрет независимо от воротила
(no-harm-страты, §5).

### 2.1 CH-3 под-страты, norm2 и механическое серебро (MLC 28.10: правки N1, N8)

**norm2-дельта (определение):** тела нормализуются замороженным
нормализатором `cortex.features.pair` (norm1: lower + collapse whitespace;
импорт, 0 реимплементаций); norm2-дельта пары (B_i, B_j) — кластеры
non-equal регионов `difflib.SequenceMatcher(None, B_i, B_j)`; механический
пин кластеризации: non-equal опкоды, разделённые пробегом равного текста
≤ 12 символов, смыкаются в один регион-халл (difflib дробит слитную
фразовую правку вокруг общих букв; слоты разнесены ≥ 100 символов, так что
GAP=12 не может слить два разных слота; ассерт «число кластеров = числу
слотов» остаётся fail-closed; границы кластера обязаны лежать в пределах
слота ± GAP и покрывать ≥ 0.8 длины слота — difflib может сматчить крайние
буквы слота с заменяемой фразой и сдвинуть халл на символ-два). CH-3
требует БИЕКЦИЮ кластеров ↔
декларированных факт-слотов: каждый кластер целиком накрывает ровно один
декларированный слот, каждый слот накрыт ровно одним кластером, прочих
изменений 0. Механическая форма A-silver (§6): сверка исполняется на
КАЖДОЙ CH-3-паре корпуса (не выборочно); нормализаторы — только из
замороженного модуля.

**Под-страты CH-3 — пин сборки (нарушен любой пункт — сборка не
запечатывается):**

| Под-страта | Доля CH-3 | Конструкция | Какой прокси убивает |
|---|---|---|---|
| вставка слота | 1/2 | факт-слот вставлен в член-надмножество; позиция вставки рандомизирована: начало / середина / конец; форматирование слота варьируется (скобки/тире/инлайн; форматы дат, версий, имён) | позиция-в-тексте, форматный ярлык |
| замена на короткую факт-фразу («короткое супермножество») | 1/2 | длинная общая фраза базы заменяется КОРОТКОЙ факт-фразой, добавляющей факт, — член-надмножество получается КОРОЧЕ члена-подмножества | length-прокси (базлайн longest-body) |

Каждая CH-3-сценария (k=2) выпускается в ОБЕИХ ориентациях сериализации —
P(x,y)=P(y,x) на уровне предъявления (урок B2, таксономия §7 методологии),
порядок кандидатов рандомизирован 50/50 независимо от метки (ассерты
A-symmetry, A-order-indep §6).

**Build-ассерт полов базлайнов (N1):** per-stratum acc всех базлайнов §5
(keep-oldest / longest-body / first) фиксируется в манифесте сборки;
`acc(longest-body)` на CH-3 ОБЯЗАН быть < 1.0 с запасом ≥ 0.1 —
обеспечивается под-стратой «короткое супермножество», на которой
longest-body выбирает подмножество и ошибается систематически. Красный
ассерт = emission корпуса запрещён.

### 2.2 Решающее правило Choice — пре-регистрация (MLC 28.10: правка N2)

Симметричная listwise/eligibility-параметризация, НЕ позиционный
мультикласс. Скоринг члена кластера инвариантен к перестановке
предъявления: признаки члена агрегируются симметрично по остальным членам
(mean-over-others), выход — eligibility-оценка e_i ∈ [0,1] на каждого
члена. Решение: keep = argmax_i e_i при одновременном e_(1) ≥ τ_hi и
e_(1) − e_(2) ≥ τ_m; иначе ABSTAIN. Вся свобода решения — два скаляра
(τ_hi, τ_m); параметры (τ_hi, τ_m) фиттятся ТОЛЬКО train-only CV
(K-fold по кластерам, фолды попарно-дизъюнктны) и замораживаются ДО seal.
Sealed-holdout (MA-holdout-choice) не используется ни для одного выбора
порога — ни прямого, ни косвенного (выбор гиперпараметров или фиче-состава
по holdout запрещён тем же правилом). Нарушение = порог-фиттинг, крас
гейта цикла; попарная симметрия обучения обеспечивается A-symmetry (обе
ориентации).

Незадействованные классы фиксируются как вне-объёма v1: k ≥ 4 (прод-максимум
3 — 2 кластера), CH-1 без пометки (требует движкового минта, волна W1–W3).

## 3. Состав корпуса (един decision-кластеров; формулы, не константы)

Три части по формуле ADR 0002 №3 — реальная + синтетическая + спот-чек.

### 3.1 Реальная страта R (из 64 кластеров стора)

- **Состав:** все 64 кластера / 130 записей снапшота зонда (62×2 + 2×3;
  id-список пинится манифестом сборки). **Предикат страты — silver-dup
  переписи (восстановлен и зафиксирован 29.10 при сборке; MLC 28.10: правка
  N9, механическое уточнение):** hygiene-цепочка без engine-сканера

  silver-dup: norm1-равенство тел и заголовков + равенство tags, type и
  language (metadata.canon.language) → кластеры = компоненты связности по
  парам. Scanner-нога hygiene верифицирована как no-op на этой популяции
  (те же 68/130/64 на пиннутом снапшоте; scanner исключил 25 записей вне
  dup-популяции). ВАЖНО (уточнение к §0): 64 кластера — это silver-dup
  silver-класс переписи, а не ВСЯ байт-дубль-популяция стора: полный
  байт-цензус того же снапшота даёт 78 кластеров / 628 записей (записи вне
  hygiene/серебра — с 29.10 зафиксированы как отдельная популяция для
  отдельного разбора, в страту R не входят).
- **Назначение — только гейтовая страта, НЕ train:** меток исхода нет (§0),
  вырожденность — by predicate; все 64 — CH-0 (доказано §0: byte-identity
  68/68 пар silver-dup). Страта обслуживает: correct-set-гейт на
  вырожденных (§5), sanity identity-corner, no-harm-eligible-проверки.
- **Гигиена:** сырые тексты реальных записей в репу не едут (data-contract
  §1/§6): в манифесте — id, скелеты ≤1 строки, счётчики; полные тексты
  обрабатываются только в build-пайплайне из пиннутого снапшота.
  **D0-fp = `f82da814844565a6…7372353f`** (vesma.db снапшота зонда §0;
  durable-копия снапшота с vectors.db — gitignored-путь в worktree,
  `data/merge-arbiter/snapshot/probe-20261028/`; /tmp волатилен).
  **ПРАВИЛО РЕМАТЕРИАЛИЗАЦИИ (MLC 28.10: правка N9, уточнено 29.10 по
  уроку сборки):** живой стор растёт и НЕ является источником
  рематериализации пиннутой страты; рематериализация = восстановление
  durable-копии снапшота (сверка sha256 обоих файлов с D0) + повторный
  прогон silver-dup цензуса §3.1 (машина воспроизводит 68/130/64 exact).
  Расхождение counts при равном fp = STOP. Перепиновка страты на свежую
  перепись живого стора — только отдельным зонтом (новый зонд + фиксация
  в манифесте), не молчаливой пересборкой.
- **Если бы исход был нужен** (фиксация для будущих волн): он появляется
  ТОЛЬКО после того, как движок начнёт исполнять схлопывание и минтить
  пометки (`merged-by-arbiter` с ref — тогда «kept» читается по выжившей
  записи). Ничего запрашивать у стора больше не нужно — вопрос закрыт
  доказательством §0; владельцу/движку от корпуса ничего не требуется.

### 3.2 Синтетическая страта S (генерация без LLM)

- **Принцип policy §4:** метка = функция построения. Детерминированные
  шаблоны/замены на базе шаблонного пула корпуса-наследия v3/v4.3

  LLM — только ассистент по санкции; для v1 не запрашивается — вопрос 6).
- **Квоты — формулой от общего объёма N_syn = 600 decision-кластеров**

  доли — как другая):

| Страта | Доля | Кластеров | Метка by construction |
|---|---|---|---|

### 3.3 Владельческий спот-чек (десятки исходов; протокол)

- **Объём:** 40 decision-кластеров, одна сессия владельца ≤ 60 минут,
  + вторая короткая прохода только по расхождениям (≤ 10 позиций).
- **Состав листа (стратифицированный, seed фиксирован):** 20 реальных CH-0
  (скелеты, реальные id) + 20 синтетических (8 CH-3 в обе ориентации,
  6 CH-2, 6 CH-4).
- **Формат:** таблица `cluster_id | skeleton-A | skeleton-B [ | skeleton-C]
  | ваш выбор: A / B / C / NO-SAFE (схлопывать нельзя)`. Порядок кандидатов
  в листе — перемешанный (не порядок, который увидит модель).
- **Что метка владельцаgold-ит:** (а) g_spot-гейт §5 — согласие модели с
  владельцем на CH-3-страте листа и совместный вердикт «запрет fold» на
  CH-2/CH-4; (б) QA генератора (метки синтетики by construction сверяются с
  интуицией владельца — прецедент двойной проверки 30/30 в B2); (в) на
  реальных CH-0 проверяется ИМЕННО вырожденность: валидны все ответы
  «A»/«B» (zero-loss), диагностический сигнал — только ответ «NO-SAFE»
  (значит правило fold-eligibility разошлось с интуицией владельца — стоп
  линии, разбор).
- **Дисциплина:** лист хэшируется и замораживается ДО обучения владельцем
  (sealed-поверхность); метки не меняются после первого прогона; модель
  метки листа в train не получает. Вторая прохода — ТОЛЬКО диагностика
  (метки листа иммунны к её исходу; MLC 28.10: правка N9).

## 4. Характеризация (полы допусков по ML-STD-0001; флоры не гейтуют)

До сборки seal-поверхностей — полы считаются СТРОГО на материале до seal
(MLC 28.10: правка N5; имя «holdout» зарезервировано печатью
MA-holdout-choice, поэтому розыгрыши состава, а не «holdout-состав/пары»);
≥ 3 розыгрыша на каждый пол, у floor_q — ≥ 10 (MLC 28.10: правка N4;
без retrain), розыгрыш = та же статистика тем же кодовым путём.
Per-stratum acc базлайнов (keep-oldest / longest-body / first) — таблица в
манифесте сборки с build-ассертом §2.1 (MLC 28.10: правка N1).

| Пол | Нулевое условие (эффект = 0 по policy) | Статистика |
|---|---|---|
| floor_perm | перестановка порядка кандидатов в кластере (модель обязана быть order-инвариантной) | Δchoice-rate по ≥3 перестановкам |
| floor_seed | пересборка синтетики другим seed (s ≠ 42) при замороженном рецепте | Δacc(модель−базлайн) между розыгрышами |
| floor_inv | cosmetic-вариация пар pre-seal материала (регистр/пробелы — policy-константный класс: выбор не должен меняться) | Δagreement-rate |
| floor_q | abstain-rate на CH-3 при замороженной модели, разные розыгрыши состава (pre-seal материал) | разброс rate по ≥10 розыгрышам |

Policy-константные проверки (пол не нужен — детерминированный запрет, аналог
плато-шага П3 ML-STD-0001, декларация здесь): g_fold_exact, g_noharm_v42,
g_corner (§5) — красный там есть красный при любом численном шуме.

## 5. Гейты ADOPT (формулы; все δ — PROPOSED, ратифицирует MLC — §7 поз. 3)

| Гейт | Формула | Порог (PROPOSED) |
|---|---|---|
| g_acc | acc_choice(sealed-holdout, CH-3) − max(acc_keep-oldest, acc_longest-body, acc_first) ≥ δ_acc; δ_acc := max(2·floor_seed; 0.10) | ≥ δ_acc (прецедент +10пп — АрхКом 06.10, routing-choice) |
| g_fold_exact | proposal_rate(CH-2 ∪ CH-4, holdout) = 0 | exact 0 |
| g_abstain_sens | abstain_rate(CH-3, holdout) ≤ q; q := max(0.20; p90_char + 2·floor_q), p90_char и floor_q — по ≥10 розыгрышам состава (MLC 28.10: правка N4) | ≤ q |
| g_noharm_v42 | на замороженной NOT-dup поверхности (train-страты v42/v4.3; holdout-ы и печати НЕ читаются): fold-proposal rate = 0 | exact 0 |
| g_inv | cosmetic-инвариантность: agreement(choice, choice∘cosmetic) ≥ 1 − δ_inv; δ_inv := 2·floor_inv | ≥ 1 − δ_inv |
| g_corner | identity-corner (урок #480), нога 1: self-кластер → fold-eligible ∧ keep ∈ members. Бывшая нога 2 (байт-твин real-страты) — тавтология на correct-set-семантике, из конъюнкции УБРАНА и переведена в sanity-сьют как диагностика (MLC 28.10: правка N6) | exact |
| g_spot | agreement(модель, комитет-серебро — ADDENDUM-1, MLC 29.10; субъект «владелец» заменён): CH-3-страта листа (8 ячеек) — правильно ≥ 7 из 8 (целочисленный порог; MLC 28.10: правка N4) — **consistency-on-train + QA генератора, НЕ генерализация** (генерализация — g_acc на sealed-holdout); CH-2/CH-4-страта: совместный «запрет fold» = 1.0; консенсус-NO-SAFE ≥ 2/3 на реальных CH-0 = стоп-линия (диссент-NO-SAFE 1/3 — именованный пункт MLC-валидации) | ≥ 7/8 / 1.0 |
| g_disj | pair- и record-level дизъюнктность от ВСЕХ eval-поверхностей (ассерты сборки), включая ЯВНУЮ ногу train↔MA-holdout (MLC 28.10: правка N8; уточнено 29.10): дискриминативные страты (CH-3/CH-4) — 0 общих сценариев; ВСЕ страты — 0 общих кластеров/текстов (holdout-семейство несёт инертные нейтральные концовки для байт-дизъюнктности вырожденных классов — пул из 12 скаффолдов не позволяет сценарную дизъюнктность по Дирихле) | exact 0 |

Каждый гейт фиксирует, ЧТО он меряет (MLC 28.10: правка N7): **модель** —
g_acc, g_abstain_sens, g_inv, g_spot (модельная нога контура §5.1);
**пайплайн** (сквозной контур §5.1: классификатор + код + модель) —
g_fold_exact, g_noharm_v42, g_corner, g_disj.

Вердикт = конъюнкция g1–g8 + ассерты сборки (§6); провал любого = DECLINE +
разбор, holdout читается один раз (single-shot, ML-STD-0003). Базлайны
формальны: keep-oldest = argmin E(r) (само tie-break-правило — модель обязана
строго превосходить его там, где у выбора есть содержание, т.е. CH-3);
longest-body = argmax \|body\|; first = первый член кластера (позиционный,
контроль против выучивания порядка).

### 5.1 Производственный контур v1 — порядок предикатов (MLC 28.10: правка N7)

Сквозной конвейер арбитража; порядок явный, пересечение CH-0∩CH-1 устранено
вычислением CH-0 первым:

1. **CH-0** (sha-тождество) → tie-break-код (keep-oldest), fold производится;
2. **CH-5** (при ¬CH-0) → tie-break-код, fold производится;
3. **CH-2** → отказ (ABSTAIN, fold не производится) — метаданные-предикаты
   вычислимы в проде без факт-экстракции;
4. **остаток** (CH-1 с пометкой, CH-3, CH-4, класс не определён) → модель
   {keep \| ABSTAIN} по правилу §2.2; ABSTAIN → fold не производится.

CH-4 не refusal-ится кодом сознательно: его предикат требует факт-множеств,
которые в проде не извлекаются, — запрет CH-4 держит МОДЕЛЬ (abstain-страта
обучения), и g_fold_exact меряет сквозной пайплайн. Гейты §5 декларируют
объект измерения («модель» / «пайплайн») — таблица выше.

   lineage_marks и схлопывания появятся только после движкового минта
   (сейчас 0 записей с пометками, §0); арбитр v1 исполняется как advisory-
   выбор + ручное/отложенное схлопывание. Фиксация границы: ADOPT корпуса
   не создаёт прод-схлопываний без отдельной движковой волны.

## 8. Seal-стратегия

- **MA-holdout-choice** — новый holdout из НОВОГО синтетического материала
  (свежий seed, независимая генерация), 10 % decision-кластеров, seal до
  любого обучения, дизъюнктность g_disj ассертами, включая явную ногу
  train↔holdout (правка N8; прецедент прега v3 §2 holdout-инъекции). Хеши
  печати публикуются в отчёте сборки; контент не читается ни одним кодовым
  путём до single-shot.
- **MA-spot-sheet** — лист владельца §3.3, хэш заморожен до обучения,
  читается один раз на g_spot; вторая прохода — только диагностика, метки
  листа иммунны (правка N9).
- **Чужие печати не трогаются:** holdout v4.5 и g4-spec-v1 остаются
  девственными для reopen B2 A2.9; ни одна поверхность этого корпуса их не
  переиспользует (другая label-поверхность — прецедент fusion-framing 28.10).
- **Дисциплина цикла** — ML-STD-0003 целиком: машинный пролог
  (swap_check → env → host → byte_tripwire → activation → frozen_inputs <
  gate_start), run-log append-only, single-shot на sealed-поверхностях,
  resume = полный повторный пролог, STOP при tripwire ≠ байт-равенство.
  Снапшот стора волатилен — манифест сборки пинит D0-fp и правило
  рематериализации (§3.1; правка N9).
  Прег активируется отдельным коммитом (DRAFT → ACTIVATED) после
  ратификации; сборка корпуса — после неё же.

## 9. Ресурс-план (директива владельца 28.10 «не свыбец мне снова»)

- **Лёгкие лайны** (сборка корпуса, характеризация, гейт-циклы класса
  LightGBM — прецедент B2: полный цикл 57–78 с, ~640 МБ): прямой
  последовательный запуск допустим; /usr/bin/python3; свой venv — только
  внутри worktree (чужие venv не трогать — правило env-изоляции после
  инцидента bathys↔vesma); full-store-подобные расчёты — шардирование
  блоками (паттерн B=512 зонда), никогда не «весь стор в память».
- **Тяжёлое (если появится)** — только detached-хост-контекст (systemd-run
  в дистробоксе недоступен): MemoryMax 14G, SwapMax 16G, CPUQuota 800 %,
  отрыв от zcode-сессии; своп-чек `swapon`/`free` — ПЕРВОЕ событие run-log
  каждого тяжёлого лайна (П9 ML-STD-0003); лайны строго последовательные;
  тренинг внутри zcode-сессии запрещён.
- **Прогноз цены цикла v1:** сборка корпуса — минуты CPU, < 2 ГБ RAM;
  characterization — ≤ 6 прогонов лёгкого класса; single-shot-цикл —
  прецедентные 57–78 с. Декларация уточняется при активации.
