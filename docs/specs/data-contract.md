# Контракт данных vesmaro-cortex

- **Статус:** Accepted (срез A3a; фиксирует данные-контракты до построения
  корпусов — A2/A5 работают по нему)
- **Дата:** 2026-09-29
- **Область:** форматы pair-манифестов (оценочный и pretrain-корпуса),
  манифест меток, схема фингерпринтов, гигиена экспорта из стора, каталоги
  репы. Источник заморозки — препрег v2 (canon, W5a) и ADR 0001 (V2
  дата-стратегия); потребитель — код `cortex/data/` (сигнатуры срез A3a,
  реализация A3b).

## 1. Каталоги

```
data/                      # gitignore ЦЕЛИКОМ: ни одного сырого фрагмента стора
  pairs/<corpus-id>/       # оценочный корпус (контент pairs.jsonl + manifest)
  labels/<corpus-id>/      # метки владельца + их манифест (holdout-метки — вне train-дерева, §7)
  pretrain/<corpus-id>/    # pretrain-корпус A2 (без меток)
  vectors/<corpus-id>/     # докомпьют полевых косинусов / векторные сайдкары (A2)
artifacts/
  weights/                 # gitignore (*.onnx, *.pt) — контент артефактов
  manifests/               # КОММИТИТСЯ: манифесты артефактов (метаданные, §9)
  runs/run_log.jsonl       # КОММИТИТСЯ: append-only run-лог оценки (§8)
```

Правило: `data/` — локальные данные владельца, репа хранит только счётчики,
распределения и фингерпринты (в отчётах/манифестах). `artifacts/` —
метаданные коммитятся, контент никогда (текущий `.gitignore` уже режет
`data/`, `artifacts/weights/`, `*.onnx`).

## 2. Идентификаторы

- **pair_id** = `<id_a>--<id_b>`, где `id_a`/`id_b` — стор-id записей,
  `a` — более ранняя по `created_at` (тай — лексикографически меньший id);
  сортируем лексикографически. Ограничение: стор-id не содержат `--`
  (валидация при экспорте, отказ при нарушении). Пререг W5c опирается на
  сортировку по `pair_id` (holdout: первые ⌈0.3·n⌉ в страте).
- **corpus-id** — строка-латиница вида `eval-v2-<date>` / `pretrain-<date>`:
  машинная строка (ADR 0001 V4), задаётся карточкой корпуса (W5b — для
  оценочного).

## 3. Оценочный pair-манифест (корпус препрега v2)

Файл `data/pairs/<corpus-id>/pairs.jsonl` — одна пара на строку:

```json
{
  "pair_id": "mem-0123--mem-0456",
  "id_a": "mem-0123",
  "id_b": "mem-0456",
  "stratum": "P2",
  "similarity": 0.9312,
  "sha_a": "<sha256 стороны a>",
  "sha_b": "<sha256 стороны b>",
  "pair_sha256": "<sha256 канонического JSON пары>",
  "record":     {"title": "…", "body": "…", "tags": ["…"], "language": "ru", "record_type": "note", "created_at": "2026-08-01T10:00:00Z"},
  "candidate":  {"…те же поля…"}
}
```

- `stratum` ∈ {P1, P2, P3, P4, N1, N2, N3} — страты препрега; `similarity`
  — измеренный косинус vesma-embed-v1 (по нему стратифицировали).
- **Фингерпринтуемый объект пары** (основа `pair_sha256`): канонический
  JSON `{"record": <сторона>, "candidate": <сторона>, "similarity": <float>}`
  со сторонами в составе экспорта препрега (title, body, tags, language,
  record_type, created_at). `pair_id`/`id_*`/`stratum`/`sha_*`/метка —
  НЕ входят: это назначение, не содержание. Правка `created_at` ловится
  фингерпринтом (состав экспорта препрега включает время).
- `sha_a`/`sha_b` — sha256 канонического JSON каждой стороны отдельно
  (провенанс-гранулярность: какая сторона менялась при перестройке).
- **Отличие от входа артефакта:** каноническая пара
  [inference-v1.md §1](inference-v1.md) — проекция этого объекта БЕЗ
  `created_at` (точный CanonRecordView-срез по правилу 2 ADR 0004). Это
  два разных канонических объекта; смешение запрещено.

## 4. Pretrain-манифест (A2, без меток)

Файл `data/pretrain/<corpus-id>/pairs.jsonl` — та же строка, кроме:

- поля `label` НЕТ вообще (ADR 0001 V2: неразмеченные пары — только
  претрейн N; в supervised-фит они не попадают никогда);
- вместо `stratum` — `source` ∈ {`weak-positive`, `hard-negative`} и
  `transform` (имя трансформации из `cortex/pretrain/corruption.py`);
- источники записей — те же фильтры включения/исключения, что у оценочного
  корпуса (§6), гигиена идентична.

Манифест и фингерпринт — та же схема (§5). Претрейн не меняет
train-определение препрега («претрейн — не оценка»), аддендум не нужен.

## 5. Фингерпринты (схема препрега, заморожена)

1. Канонический JSON: `sort_keys=True`, `ensure_ascii=False`,
   `separators=(",", ":")` → UTF-8 байты (код:
   `cortex/data/fingerprints.py::canonical_json`, константа
   `CANONICAL_JSON_KWARGS` — пиннута тестом).
2. `pair_sha256` — sha256 фингерпринтованного объекта пары (§3).
3. `manifest.txt` — строки `pair_id <pair_sha256>`, отсортированные по
   `pair_id`, `\n`-терминированные (код: `manifest_bytes`).
4. **Фингерпринт корпуса** = BLAKE2b-256 (hex) байт `manifest.txt`
   (код: `corpus_fingerprint`). Stdlib `hashlib` — внешних хеш-зависимостей
   нет.
5. **Манифест меток**: `data/labels/<corpus-id>/labels.jsonl` — строки
   `{"pair_id": "…", "label": "duplicate|not-duplicate|disputed", "reason":
   "<только для disputed, одна строка без содержания>"}`; фингерпринт
   меток — та же схема по своему каноническому объекту (словарь
   pair_id → label; `reason` в фингерпринт НЕ входит — оперативное поле,
   не разметка).
6. Оба фингерпринта фиксируются ДО прогона (карточка корпуса W5b) и
   пересчитываются на месте перед оценкой (A5): несовпадение = прогон
   невалиден. Любая правка после фингерпринта = перестройка корпуса по той
   же процедуре с раскрытием события (пререг, «запрет пост-фактум правок»).

## 6. Гигиена экспорта (порядок заморожен препрегом)

1. Отбор кандидатов SQL-процедурой из единого стора движка; доступ —
   ТОЛЬКО read-only URI `file:…?mode=ro` (код открытия передаётся флагом
   CLI `--store-uri`, запись через такой URI невозможна).
2. На каждую сторону: сканер секретов движка (`secrets_detector`) + тег
   `no-federate` + `quarantine_reason` — находка ⇒ пара исключается со
   счётчиком по причине, БЕЗ содержания в логах.
3. Только после п. 2 — экспорт пары (состав §3). Порядок 2→3 обязателен:
   секрет-скан ДО экспорта, не после.
4. Фингерпринты (§5) — по завершении экспорта.
5. В репу (коммит) попадают: счётчики, распределения классов/стратов,
   фингерпринты. Ни одной сырой строки стора — `data/` gitignored целиком.

## 7. Holdout-изоляция (физическая)

- Сплит по препрегу: в каждом страте пары сортированы по `pair_id`, первые
  `⌈0.3·n⌉` — holdout, остальные — train; спорные исключены ДО сплита
  (код: `cortex/data/holdout.py::split_holdout`).
- **Физическая изоляция:** метки holdout лежат вне train-дерева
  (`data/labels/<corpus-id>/holdout/` недостижим из train-корня); код
  ассертит нулевое пересечение `pair_id` (`assert_no_pair_overlap`) и
  внеположность путей с резолвом симлинков (`assert_labels_isolated`).
- Holdout читается один раз — раннером A5 (`cortex/eval/runner.py`);
  подбор гиперпараметров и ранний стоп по train только.

## 8. Run-лог оценки (append-only)

`artifacts/runs/run_log.jsonl` — строка на прогон: `run_at` (ISO-8601 UTC),
`weights_sha256`, `corpus_fingerprint`, `label_fingerprint`. Коммитится
(tamper-evidence). Повторная запись того же `corpus_fingerprint` = отказ
(`RunLogRefusalError`), не warn — механика single-shot препрега.

## 9. Манифесты артефактов

`artifacts/manifests/<artifact-name>.json` — метаданные экспортированного
артефакта, один файл на выпуск: `name`, `version`, `sha256` (весов),
`embedder_pin`, `corpus_fingerprint`, `trained_at`, `candidate`,
`features`, `feature_set_sha256`, `size_bytes`, относительный путь до
весов. Состав зеркалит `metadata_props` ONNX (inference-v1.md §4) плюс
провенанс путей; коммитится вместе с выпуском артефакта (контент весов —
нет).

## 10. Открытые вопросы

- **Формат `pair_id` (разделитель `--`)** — моя инстанциация: препрег
  замораживает сортировку по `pair_id`, но не формат; финальную точку
  держит карточка корпуса W5b (канон-сессия). Если W5b выберет другой
  формат — правится `data-contract.md` + валидатор ДО первого экспорта;
  фингерпринт-схема (§5) от формата не зависит.
