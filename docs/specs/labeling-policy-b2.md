# Политика разметки near-duplicate пар (тиры T0–T3) — proposal для волны B2'

- **Статус:** Proposal. Проработка карточки `vesma-b2-brokenfield-labeling-policy`;
  ждёт ратификации владельцем. После ратификации правки едут в волну B2'
  отдельными PR: генераторы корпуса + `work/validate.py` (corner-гейт, §5),
  аддендум `gate_contract.json` и зонды `cortex.eval.sanity` (§6) — по
  правилу разделения [eval-methodology](eval-methodology.md) §6 (правила —
  отдельно, артефакты — отдельно).
- **Дата:** 2026-10-04
- **Область:** превращение продуктового вопроса «одна подмена поля = дубликат
  или нет» в ратифицируемую политику: асимметрия цены ошибок по коду движка,
  тиры близости с метками и эмпирическими бэндами, rulebook синтеза датасета
  B2', corner-гейт для валидатора корпуса, пререгистрация eval B2' ADOPT.
  Потребитель решения — движок vesma (в этом слайсе read-only). Работа
  датасетом/обучением НЕ входит: retrain-волна заблокирована до ратификации.
- **Основание:** вердикт #480 (B2 `71f0572d` отозван из прода 2026-10-03,
  инверсия self-пары P(dup)=0.0108 — [постскриптум
  B2](../experiments/calibration-b2-edge-neighborhood.md),
  [b0-escalation](../experiments/b0-escalation.md)) и корень расследования:
  в dataset-v3 ноль identity-позитивов, а угол «тексты почти одинаковы»
  (cos med 0.999) занят 50 broken-field-негативами («почти-клоны с одной
  подменой поля») — модель выучила «почти идентичны = не дубликат» и
  перенесла на «идентичны». Контракты B1/B2 идентичны (H1 опровергнута);
  W5d/dataset-v2 здоров (негативы не доходили до угла, max cos 0.9920).

## 1. Продуктовый ответ (что ратифицируем)

1. **Дубликат — та же мысль и те же факты, другими словами.** Перефраз,
   реструктуризация, смена связок — дубликат (позитивная зона v3 сохраняется).
2. **Изменился хотя бы один факт (число, дата, версия, имя, сумма) — НЕ
   дубликат.** Одна содержательная подмена поля = отдельная запись; связь
   пары — существующее relates_to-ребро.
3. **Изменились только метаданные (теги, тип, язык) — НЕ дубликат:** метки
   и тип управляют фильтрами и видимостью стора, подавление записи теряло бы
   эту дельту.
4. **Контент-эквивалент — дубликат:** самопара, байт-копия, отличия в регистре
   и пробелах (то, что стирает нормализация текста фич). Пунктуационные правки,
   меняющие нормализованный текст, — уже T3-класс (см. §3: иначе грань
   невыучиваема).
5. **Все спорные случаи решаются в сторону «не дубликат»** — из асимметрии
   цены ошибок (§2): потерять факт нельзя, лишнюю копию уберёт консолидация.

## 2. Асимметрия цены ошибок — по коду движка

Кто потребитель вердикта is-dup сегодня (якоря: `vesmaro`, ветка прод-линии):

| Точка | Что делает при «дубликат» | Цена FP (изменённая запись названа дублем) | Цена FN (дубль назван изменённой) |
|---|---|---|---|
| `graph_minting.AUTO_DEDUPE_SIMILARITY_THRESHOLD` (0.92, vector-leg cosine) | минтит `relates_to`-ребро, weight 2.0 — **rank-only** по контракту (I3): запись никогда не подавляется | лишнее ребро: шум ранжирования | пропущенное ребро: близнецы не сгруппированы |
| `decision_provider.IsDuplicateRequest` → `Noul` (шаг 0/1 при cos ≥ 0.92); калиброванный cut модели `CORTEX_DUPLICATE_PROBABILITY_THRESHOLD = 0.5` | вердикт для «будущего minting call site» (комментарий контракта W5d); в проде — **advisory** (план B0: «ложное срабатывание раздражает, но не разрушает»); fail-open: `CortexError` → деградация в deterministic | неверная подсказка; при будущем хардненинге — подавление записи | неподключённый дубль |
| `context_rewrite` (CCR idempotency, content-hash) | **единственное реальное подавление записи**: байт-идентичная повторная доставка → `status: "deduplicated"`, второй записи нет | — (хэш не может ложно сработать на изменённой записи) | — (класс покрыт полностью) |

Канон движка уже кодирует асимметрию: ADR-0019 §2b — отклонённый контент
хранится RAW, невидимым, **zero-loss**; гейты никогда не уничтожают данные
пользователя. Авто-дедуп — намеренно rank-only. Итого:

> **FP (настоящая изменённая запись отброшена как дубль) — тихая потеря
> факта, необратимая для пользователя и противоречащая zero-loss канону.
> FN (дубликат сохранён) — шум в выдаче, дешёвый и исправимый. Поэтому
> асимметрия смещает МЕТКИ, а не только порог: лейбл «дубликат» даётся
> только парам, слияние которых ничего не теряет.**

Отдельный якорь: `RecordLike`/`CanonRecordView` не содержит `created_at`
(OQ-2) — время невидимо фичевому контракту, метки от него не зависят
(см. §4, правило выучиваемости).

## 3. Тиры близости и метки

Бэнды — по факту dataset-v3 (600 пар: train 420 + holdout 180, фичи считены
замороженным `cortex.features.pair.features`); это агрегаты, сырые фрагменты
стора в репу не едут (data-contract §1).

| Тир | Определение | Метка | Обоснование (из §2) | Бэнд по данным v3 |
|---|---|---|---|---|
| **T0 identity** | самопара; байт-копия | **duplicate** | слияние не теряет ничего; CCR-хэш уже подавляет этот класс | cos = 1.0; char5_jaccard = 1.0; все len-delta = 0. **В v3: 0 пар** — корневой дефект |
| **T1 cosmetic** | отличаются только тем, что стирает нормализация (регистр, пробелы) | **duplicate** | информационная дельта нулевая | char5_jaccard = 1.0 по построению; cos ≈ 1.0 |
| **T2 metadata-only** | тело и заголовок тождественны; меняются теги / record_type / language | **not-duplicate** | теги и тип управляют видимостью и фильтрами (`mnemos:no-federate` и др.) — подавление теряет дельту | cos ≈ 0.95–1.0; char5_jaccard = 1.0; tag_jaccard < 1. **В v3: 0 пар** — на позитивах и broken-field tag_jaccard вырожден в 1.0 |
| **T3 fact-edit («razor»)** | заменён один факт-токен: цифра, дата, версия, имя, сумма; сюда же пунктуационные правки, меняющие нормализованный текст | **not-duplicate** | FP здесь = тихая потеря факта (запрещено §2); FN = одна лишняя копия (дёшево) | broken-field v3: cos 0.9975–1.0000 (med 0.9990), char5_jaccard 0.9774–0.9979, все len-delta = 0, заголовок/теги/тип тождественны |
| **T4 paraphrase+** (сущ. позитивная зона) | перефраз/реструктуризация при тождестве фактов: страты light / substantial / structural | **duplicate** | FN дёшев; слияние ничего не теряет | light cos 0.994–1.0; substantial 0.996–1.0; structural 0.959–0.999; char5_jaccard ≤ 0.9931 / 0.9838 / 0.9967 |
| сущ. негативные страты | template-twin (0.954–0.972: общий скелет, другой контент), near-topic (0.80–0.969), cross-topic (0.83–0.966) | **not-duplicate** | здоровая «рёберная окрестность» — не трогаем | без изменений |

Две находки по данным, которые политика обязана чинить:

1. **Угол инвертирован:** в полосе cos ≥ 0.998 — 156 позитивов и 48
   негативов, причём Т3-негативы занимают самую верхушку (med 0.9990) и
   **превышают потолок позитивов** по char4_jaccard (0.9985 > 0.9976) и
   char5_jaccard (0.9979 > 0.9967). Самопара — вырожденная точка того же
   облака (все jaccard/containment = 1.0, дельты 0): градиент «чем ближе,
   тем не-дубликат» экстраполировался в 0.0108 на self-паре. Это и есть
   механика #480.
2. **Шум меток в razor-зоне:** 4 light-позитива (DV3-P-075/099/108/111) —
   служебные правки в 3–4 символа («=»→«как», «,»→« и») при тождественных
   заголовке и тегах — тот же фиче-сигнатурный класс, что T3-негативы
   (48 из 50 broken-field сидят в cos ≥ 0.998). Различить «служебную связку»
   и «факт-токен» по замороженным фичам нельзя; 4 пары — шум поколения
   light-страты. В B2' они перегенерируются (пол массы правки, §4/§5-G4).

Почему T1 без пунктуации: грань «дубликат/не дубликат» обязана быть
**выучиваемой** из замороженной поверхности фич. Односимвольная «!» и
односимвольная цифра дают неотличимые jaccard-сигнатуры — любой carve-out
для пунктуации делает грань невыучиваемой. Косметика = ровно то, что
стирает нормализация текста фич (lower + collapse whitespace).

## 4. Rulebook синтеза датасета B2'

Принцип: **лейбл = функция построения**. Синтетический генератор знает, что
именно он поменял, и ставит метку по тиру (§3); метка обязана быть вычислимой
из замороженной фичевой поверхности (RecordLike: title, body, tags, language,
record_type + измеренный cos). `created_at` не участвует (невидим модели).

Источники и генераторы:

- База — тот же гигиеничный таргетированный экспорт рёберной окрестности
  (373 записи; живой стор read-only; правила data-contract §7). Здоровые
  страты v3 (template-twin, near-topic, cross-topic, light, substantial,
  structural) сохраняются с их квотами.
- **G-identity:** самопары экспортированных записей + байт-копии (T0) —
  дёшевы, метка by construction. Цель: ≥ 60 пар (≥ 10 % позитивов);
  полоса cos ≥ 0.998 становится ≥ 216 pos : 48 neg (сейчас 156:48).
- **G-cosmetic:** регистр/пробельные варианты (T1) — в ту же квоту.
- **G-metadata:** дельта тегов / record_type / language при тождественном
  теле (T2) — ≥ 40 пар. Побочный эффект: снимает вырожденность
  tag_jaccard / tag_count_delta / type_match / lang_match (сейчас на
  позитивах и broken-field это константы — фичи без сигнала).
- **G-fact-edit:** T3 — существующие 50 broken-field + ≥ 25 новых: замены
  факт-токенов (цифры, даты, версии, имена, суммы) с вариацией cos по полосе
  0.99–1.0 и обеими ориентациями пары (хвост симметрии P(x,y)=P(y,x),
  таксономия §7 методологии).
- **Пол массы для light:** перефраз-генератор обязан переносить ≥ 8 символов
  ИЛИ ≥ 2 контент-токена — запрет на связочные микро-правки (лечение находки
  2, §3).
- Перегенерация 4 шумовых light-пар (DV3-P-075/099/108/111 — идентификаторы
  корпуса, не стора).
- Сиды фиксированы, фингерпринт корпуса по data-contract; счётчики и
  распределения — в репу, сырой контент — нет.

## 5. Corner-гейт для work/validate.py (спека; код НЕ меняется в этом слайсе)

Формулируемые правила — валидатор отказывает в приёмке корпуса (корпус не
считается собранным, holdout не запечатывается) при нарушении любого:

- **G1 — фиче-потолок:** для каждой монотонно-дупликативной фичи
  f ∈ {cos_target, char3/4/5_jaccard, char3/4/5_containment}:
  `max f(негативы) ≤ max f(позитивы)`. «Негатив не может сидеть выше
  позитивов» — фиксирует инверсию градиента до обучения.
  *dataset-v3 сегодня: FAIL — char4_jaccard 0.9985 > 0.9976, char5_jaccard
  0.9979 > 0.9967* (лечится заселением угла T0/T1: identity пиннит потолок 1.0).
- **G2 — identity-угол заселён:** ≥ max(30; 5 % позитивов) пар с
  `char5_jaccard == 1.0` и нулевыми len-delta, и ВСЕ они — duplicate.
  «Угол около 1.0 обязан содержать позитивы». *dataset-v3 сегодня: FAIL (0 пар).*
- **G3 — чистота razor-зоны:** открытая зона (char5_jaccard ≥ 0.977 ∧
  char5_containment ≥ 0.995 ∧ все len-delta = 0 ∧ cos ≥ 0.995 ∧
  jaccard < 1.0) не содержит позитивов. *dataset-v3 сегодня: PASS (4
  broken-field, 0 позитивов)*. Константы зоны фиксируются в препрег-аддендуме
  корпуса B2', не в коде движка.
- **G4 — пол массы позитивов:** у каждой позитивной пары difflib-масса правки
  тела ≥ 8 символов либо правится title/tags. Запрещает связочные
  микро-правки в позитиве. *dataset-v3 сегодня: FAIL (те же 4 light-пары).*
- **G5 — механическая сверка тиров:** метки T0/T1-пар = duplicate и
  T2/T3-пар = not-duplicate выводимы из корпуса правилом §3 — линтер
  сверяет и падает при расхождении.

Санкция гейта: невалидный корпус не экспортируется; фингерпринт не
выдаётся. Гейт — свойство корпуса, не модели: он ловит дефект ДО обучения
(holdout-метрики слепы к нему — урок #480).

## 6. Пререгистрация eval B2' ADOPT (до прогона)

Форма — по [eval-methodology](eval-methodology.md) §8: отчёт открывается
таблицей покрытия поверхности, числа без неё не цитируются. Пороги после
ратификации едут в `gate_contract.json` ОТДЕЛЬНЫМ PR (правило разделения §6).

Поправки зондов сюита (пререгистрируются аддендумом, код — в волне B2'):

- near_boundary-твин меняется с `title + "!"` (односимвольная правка — это
  T3-класс по §3; текущий зонд кодирует опровергнутую #480 аксиому
  «почти одинаково = дубликат») на **косметический твин** (регистр/пробелы,
  `char5_jaccard == 1.0`), требование ≥ 0.5 сохраняется;
- **новый razor-зонд:** замена одной цифры при cos ≈ 0.999 → P(dup) < 0.5;
- **новый metadata-зонд:** delta тегов при тождественном теле → P(dup) < 0.5;
- лестница монотонности {1.0, 0.99, 0.95, 0.8, 0.5} без изменений
  (нестрогое невозрастание; razor-ступень может падать круто, но не расти).

Критерии ADOPT (все одновременно):

| # | Критерий | Порог |
|---|---|---|
| 1 | Adversarial sanity suite (расширенный) — ДО цитирования holdout-метрик | PASS, exit = 0 |
| 2 | self-pair (запись против себя, cos = 1.0) | P(dup) ≥ 0.9 |
| 3 | Layer B holdout B2': typedness / sens / spec / Brier | 100 % / ≥ 0.90 / ≥ 0.90 / ≤ 0.25 |
| 4 | BA строго выше косинус-базлайна 0.92 (тот же раннер) | > |
| 5 | Коридор prev_adopt: BA ≥ BA(B1 `beb0a65d` = 0.987) − max(0.02; CI95) | ≥ |
| 6 | tier-sens: T0/T1; light/substantial/structural | ≥ 0.95; ≥ 0.90 |
| 7 | tier-spec: broken-field (T3); T2 metadata; template-twin | ≥ 0.90; ≥ 0.90; ≥ 0.90 |
| 8 | **cos-blind razor** (ключевая способность): P(dup \| cosmetic-твин, cos ≈ 0.99) ≥ 0.5 **и** P(dup \| замена цифры, cos ≈ 0.999) < 0.5 | оба |
| 9 | family-бэнд B1: P(dup) в полосе cos ≈ 0.98 на B1-семейных пробах | < cut (прецедент B1: 0.016) |
| 10 | Монотонность по лестнице (tol 1e-6) | нестрогое невозрастание |

Правило решения: ADOPT = все 10; любой провал = DECLINE + разбор. Негативная
дельта против B1 — расследование, никогда не merge. Holdout запечатывается до
обучения; run-log append-only; смена весов = перекалибровка. Сравнение с B1
(#9) — преемственность с прод-артефактом: B2' не имеет права ухудшить
здоровую полосу, которую B1 держит монотонно.

## 8. Аддендум 1 (2026-10-05): whitelist изменяемых полей — policy v1.1

- **Статус:** формализация ратифицированного владельцем направления
  (вердикт 2026-10-05, три ноги); текст аддендума — proposal на
  ратификацию владельцем. Оригинал §1–7 не переписывается — исторический
  факт policy v1.0; при расхождении приоритет у этого аддендума.
- **Триггер:** вердикт сьюта по обучению B2-prime (артефакт `89d6f329`):
  self-pair вылечен (0.0108 → 0.9934), но FAIL по near_boundary (твин
  cos 0.99 → P(dup) 0.0261) и monotonicity.
- **Корень:** политика §1.2 в паре с замороженным экзаменом (near_boundary
  v1, cut ≥ 0.5) несогласованы в razor-зоне. Корпус dataset-v4 заселил
  полосу cos 0.95–1.0 по §1.2 честно: 192 факт-негатива (T3) против
  72 косметических позитивов (T1). Модель выучила доминанту зоны («почти
  идентичны → не дубликат») — и на твин «title + "!"» отвечает политически
  корректно по §3 (односимвольная пунктуационная правка, меняющая
  нормализованный текст, — T3-класс), а замороженный экзамен требует
  «любой близнец на 0.99 = дубликат ≥ 0.5». Это конфликт правил, а не
  дефект обучения.
- **Ратифицированное направление:** (а) whitelist изменяемых полей — этот
  аддендум; (б) экзамен v2 policy-aware с двусторонними пробами
  razor-зоны — [аддендум
  eval-methodology](eval-methodology.md); (в) имя поля наследственных
  пометок — `lineage_marks` (принято; схема поля едет в vesma-canon —
  вне скоупа этой волны).

### 8.1 Три класса полей записи

| Класс | Поля | Различие в паре | Вердикт |
|---|---|---|---|
| **Ключевое содержание** | итоговые цифры расчётов, суммы, выводы, имена, версии, условия (обещания, ограничения) | задет хотя бы один | **NOT dup — всегда** (уточнение §1.2: не «любой факт», а поля этого класса) |
| **Разрешённо-изменяемые (whitelist)** | конверт записи: дата фиксации/события в конверте, счётчики редакций, источник повторной встречи | различие только в whitelist-полях | **dup при совокупности факторов**: смысл и ключевые факты совпали |
| **Метаданные** | теги, record_type, язык | — | **NOT dup** по §1.3 (T2) — без изменений |

Конверт — не содержание: «то же сообщение, зафиксированное позже /
повстречанное в другом источнике» — та же мысль и те же факты (§1.1), и
слияние по §2 ничего не теряет. Whitelist не пересекается с метаданными:
теги/тип/язык управляют видимостью и фильтрами стора (§3, T2), конверт —
история записи в сторе, на фильтры не влияет.

### 8.2 Маркеры ключевых фактов в тексте (правило суждения для разметки)

Генератор корпуса знает класс поля by construction; для суждения по
произвольному тексту (разметчик, спот-чек владельца):

| Маркер в тексте | Класс |
|---|---|
| числа расчётов, суммы, дедлайны в теле, имена, версии, условия | **ключевой факт** — различие = NOT dup |
| упоминания времени фиксации, приветствия, форматирование, обёрточные даты | **incidental** — cosmetic/конверт, dup-сторона |

Явная пара-пример: «дедлайн: 5 октября» в теле — ключевой факт (изменение
этой даты = NOT dup); «записано 3 октября» в шапке — конверт (изменение
этой даты = whitelist-дельта, dup при совокупности факторов).

Следствие для §3: T3 («razor») сужается до замены ключевого факт-токена по
этой таблице; пунктуация заголовка («!»), регистр, пробелы, приветствия и
форматирование уходят в cosmetic-класс (dup). Твин «title + "!"» из
замороженного зонда near_boundary v1 отныне cosmetic-класс — что и
фиксирует экзамен v2 (аддендум методологии).

### 8.3 Спорный случай: вердикт и системное действие разделены

- Правило §1.5 «спорное → NOT dup» **остаётся на уровне вердикта** модели
  (is-dup): асимметрия цены ошибок §2 не меняется.
- **Новое правило системного действия:** в пограничной зоне движок может
  **схлопывать** записи, несущие пометку `lineage_marks` («то же сообщение
  существовало с другой датой»). Вердикт консервативен («не дубликат»),
  действие — территория консолидации: merge-arbiter (реестр обязанностей
  [ADR 0002](../decisions/0002-duty-registry-v2.md) №3) принимает пометку
  как вход арбитража, а не как вердикт классификатора.
- Zero-loss канон не нарушается (§2, ADR-0019 §2b): схлопывание по пометке
  переносит `lineage_marks` на принимающую запись — наследственность
  сохраняется, ничего не удаляется.
- Имя поля `lineage_marks` ратифицировано владельцем 2026-10-05; схема
  поля — в vesma-canon, не в этой волне.
