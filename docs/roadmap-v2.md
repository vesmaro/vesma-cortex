# Дорожная карта vesma-cortex v2: расширение обязанностей модели

- **Статус:** Proposed (план v1; фаза R ждёт green-light владельца)
- **Дата:** 2026-10-02
- **Основа:** vesma-cortex-v1 — ADOPT по препрегу v2 + аддендум 2
  ([calibration-ds1000-a5.md](experiments/calibration-ds1000-a5.md));
  W5d исполнен соседней сессией (merge `4a343e9`, бандл = наш ADOPT-веса
  `281bd0fd`, VesmaProvider за флагом, выключен).

## 0. Принципы (неизменны для всех фаз)

1. **Телеметрия раньше телепатии:** перечень обязанностей калибруется
   против реальных промахов из прод-обкатки (фаза B0), не только догадок.
2. **Пререг ДО прогона:** каждая новая обязанность — своя замороженная
   препегистрация (или аддендум) в vesma-canon до любого прогона оценки.
3. **Датасеты в три волны:** создатель (субагент) → независимые Jev-верификаторы
   (роутер + чистый Jev) → арбитраж TL; метки-по-построению приоритетнее
   LLM-судейства; владельческий спот-чек ближней зоны.
4. **Субагенты = рабочая сила** (постоянное правило); гигиена — кодовым
   пайплайном вокруг.
5. **Чартер-гейт:** новые примитивы (Choice, новые Score-спектры) — только
   отдельным решением владельца.
6. Каждый принятый пункт дорожной карты даёт пруф-документ в копилку
   продукта (отчёт с числами и фингерпринтами).

### R2. Заседание АрхКома (одна сессия, два блока)

Состав: TL (chair), product architect, system engineer, делегат движка;
вход — R1 + телеметрия B0 + W2a/W3 артефакты соседней сессии (ростер-координация).
Блок 1: **реестр обязанностей** — по каждому кандидату вердикт
(включить / отложить с триггером / отклонить), примитив, приоритет.
Блок 2: **архитектура много-обязанностей** — ключевой вопрос: один
мульти-duty артефакт (vesma-cortex-v2) или семья узких артефактов
(принцип ADR 0001 «одна задача = один артефакт» vs эксплyatация общего
фиче-ядра). Выход: ADR (в этой репе) + реестр.

### R3. Ратификация владельцем перечня и архитектуры.

## 2. Фаза D — датасеты по обязанностям (на каждую принятую)

1. **Проектирование** (TL): страты сложности, объёмы, баланс, источник
   записей (реальный пул + синтетика), формат манифеста.
2. **Генерация** (субагенты-создатели, батчи) + **три волны валидации**:
   создатель → jev-router → чистый Jev (decisions API) → арбитраж TL;
   ближняя зона — владельческий спот-чек.
3. **Фингерпринты + печать holdout** (30 %) до любого обучения; препрег
   по обязанности — в vesma-canon до прогона.

## 3. Фаза T — обучение и оценка (на каждую принятую)

1. Обучение (лестница/специфичная архитектура по ADR фазы R), CV-отбор
   по замороженному протоколу, holdout не трогается.
2. Single-shot оценка по пререгу → вердикт → артефакт-ревизия
   (fingerprint-дисциплина; мульти-duty — по архитектурному решению R2).
3. Пруф-отчёт в docs/reports/ (в копилку продукта).

### 5.1 Adversarial sanity suite (обязателен с 2026-10-03, vesmaro/vesma#480)

> **Почему:** «B2 scored sens 0.989 while inverting the self-pair — the
> eval surface had no exact self-pairs» (vesmaro/vesma#480).

Каждый ADOPT начинается с adversarial sanity suite против артефакта-бандла
(ONNX + манифест): четыре проверки на синтетических пробах — self-pair /
near-boundary / unrelated / монотонность — плюс контрактные предпроверки
(sha256, порядок фич манифеста и метаданных против замороженного
13-фиче-контракта). Все зелёные ДО любых других метрик; красный suite
блокирует ADOPT. Исполнитель:

    uv run python scripts/eval_sanity_suite.py --bundle <dir-или-model.onnx>

(exit ≠ 0 = провал; `--json` — машинный отчёт; регрессионные тесты —
`tests/test_eval_sanity.py`). Полное описание проверок — раздел
«Обязательный adversarial sanity suite» в
[calibration-b2-edge-neighborhood.md](experiments/calibration-b2-edge-neighborhood.md).
