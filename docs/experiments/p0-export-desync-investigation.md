# P0: «export-desync» артефакта B2 — расследование (2026-10-04)

Исполнитель: gcw-ml-engineer. Ветка `investigate/p0-export-desync` от main
(298ce1b). Это расследование: код не менялся (микро-фиксы не понадобились —
все проверки выполняются над существующими артефактами и датасетами),
прод/holdout/публикации не тронуты, перекалибровка НЕ запускалась.

---

## 1. Симптомы (воспроизведены до знака)

`cortex.eval.sanity.run_sanity_suite` на четырёх бандлах
(ветка «adversarial sanity suite», гейт ADOPT):

| Бандл | weights sha256 | self_pair (≥0.9) | near_boundary | unrelated | monotonicity | вердикт |
|---|---|---|---|---|---|---|
| stage2-base (prereg) | 0ba71960 | **0.9904** | 0.9904 | 0.0037 | ok | PASS |
| ds1000 | 281bd0fd | **0.8019** | 0.9833 | 0.0126 | НАРУШЕНА | FAIL |
| B1 | beb0a65d | **1.0000** | 1.0000 | 0.0000 | ok | PASS |
| B2 | 71f0572d | **0.0108** | 0.9898 | 0.0052 | НАРУШЕНА | FAIL |

Лестница монотонности B2: cos 1.00→0.9805, 0.99→0.9898 — P **растёт** при
падении косинуса. При этом holdout-180 у B2: sens 0.9889 / spec 0.9778
(brier 0.0113) — модель сильна на своей поверхности оценки. Точная
инверсия self-пары — только в вырожденной точке «запись против самой себя».

## 2. Гипотезы

- **H1 (основная, из #480):** desync порядка фиче-колонок — обучающая
  матрица собрана в ином порядке, чем замороженный
  `cortex.features.pair.FEATURE_NAMES`, а ONNX-вход подаёт фичи по
  контракту; манифест и ONNX-метаданные при этом консистентны.
- **H2:** отравление обучающего датасета в вырожденной области
  exact-match (self-pair-угол фиче-пространства).
- **H3:** дрейф кода обучения/экспорта между экспортами.

## 3. Доказательства

### E1 — транспозиция исключена на уровне данных (решающий тест)

LightGBM-бустер хранит `feature_infos` — фактические min/max каждой
колонки обучающей матрицы. Пересчитали 13 фич по каждому train-манифесту
**текущим замороженным кодом** (`cortex.features.pair.features`) и
сравнили с бустером (допуск 1e-9, все 13 колонок):

| Прогон | Датасет | n | Сходство колонок |
|---|---|---|---|
| ds1000 | data/stage2/ds1000-train-700.jsonl | 700 | **13/13 точное** |
| B1 | data/stage2/b1/train.jsonl | 350 | **13/13 точное** |
| B2 | data/stage2/b2/train.jsonl | 420 | **13/13 точное** |

Колонки 8/9/10 (title/body/tag_count len-delta — единственные семейства с
неограниченным масштабом: диапазоны [0:119], [0:4322], [0:9] у B2) стоят
ровно на контрактных позициях во всех бустерах. Перестановка сместила бы
диапазоны по колонкам — не совпало ни одно значение. **H1 снята: все
обучающие матрицы были в замороженном порядке.**

### E2 — экспортная цепочка верна

Штатный ONNX B2 против библиотечного бустера + Platt на self-pair-векторе:
0.01080653 (ONNX, float32) vs 0.01080654 (library, float64) — экспорт не
искажает граф. (`_smoke_onnx` в d_boost.py дополнительно сверяет граф с
библиотекой на экспорте.)

### E3 — артефакт есть детерминированная функция своего датасета

Переобучение конфигом d-l7-lr005/seed=1 тем же кодом на тех же данных
(скрипты в §8):

| Прогон | self_pair переобученный | self_pair шипованный |
|---|---|---|
| base | 0.9904 | 0.9904 |
| ds1000 | 0.8019 | 0.8019 |
| B1 | 1.0000 | 1.0000 |
| B2 | **0.0108** | 0.0108 |

B2-повтор также воспроизводит holdout в точности: sens 0.9889 / spec
0.9778. Нынешний код == код, обучивший все четыре артефакта, — **H3 снята:
дрейфа кода нет.** Значит, дефект живёт в данных.

### E4 — корень: отравление exact-match угла датасета

«Угол» = строки с cos>0.98, всеми jaccard>0.95, всеми containment>0.98 и
нулевыми len-delta (вырожденная окрестность self-пары):

| Датасет | Строк в углу | dup | **not-dup** | Клоны-негативы (body-ratio ≥ 0.999) |
|---|---|---|---|---|
| base (prereg, владелец) | 0 | — | — | 0 (макс. ratio негатива **0.202**) |
| ds1000 («700 hard pairs») | 28 | 1 | **27** | 26 |
| B1 (dataset-v2) | 5 | 5 | **0** | 0 (макс. ratio негатива 0.578) |
| B2 (dataset-v3) | 50 | 15 | **35** | 29 |

Клоны dataset-v3 — это негативы `DV3-N-*`, отличающиеся от позитивной
стороны на **≤2 символа**: DV3-N-153 — тела по 4142 символа, разница в
одном символе ('0'→'1'); DV3-N-155 — «РЕЛИЗ 4.3.0» → «РЕЛИЗ 4.3.1» в
байт-идентичном теле, при этом title/tags/record_type совпадают, cos =
0.999–1.0, body_len_delta = 0. Модель честно выучила урок датасета:
«текстуально идентично + cos≈1 ⇒ скорее not-duplicate» (35 из 50 угловых
строк). Self-pair — самая крайняя точка этого угла → P(dup)=0.0108.
ds1000 отравлен тем же классом слабее (27:1) → 0.8019. У base и B1 угол
чист или позитивный → PASS.

Замечание по контракту фич: 13 фич не разделяют «клон с бампом версии» от
«испорченного дубликата» — для фич это одна и та же точка. Разметка таких
пар негативами делает угол необучаемым в принципе.

### E5 — контрфактические сигнатуры desync (для полноты)

- Перестановка, применённая **одинаково** на обучении и инференсе —
  математический no-op (переименование колонок): holdout и self_pair не
  меняются (проверено).
- Realistic desync (обучение в переставленном порядке, инференс по
  контракту), перестановка jaccard↔containment: self_pair 0.0110 +
  сломанная монотонность — sanity-сигнатура та же, что у B2 (сам по себе
  sanity не различает desync и отравление угла!), но holdout почти не
  двигается (sens 0.978). **Именно этот сценарий исключён E1.**
- «Убойная» перестановка cos↔body_len_delta: специфика holdout падает
  0.978→0.833 — у шипованного B2 такой дыры нет (0.978).

## 4. Вердикт по корню

**Корень — не desync порядка фич, а состав обучающих данных: в датасетах
ds1000 и B2 (dataset-v3) негативами размечены текстуальные клоны
(пра 1–2 символа), которые заполняют exact-match угол пространства фич;
модель экстраполировала этот урок на self-пару.** Артефакт верен контракту
экспорта (E1, E2), воспроизводим из данных до 4-го знака (E3) и остаётся
сильным на своей holdout-поверхности, потому что holdout из того же
распределения не содержит self-пар (поверхность слепа к углу).

## 5. Хронология: почему PASS/FAIL именно у этих четырёх

Код обучения/экспорта не менялся от скелета до сегодня
(`src/cortex/features/pair.py`, `d_boost.py`, `cli/main.py`,
`artifacts/`: только 19f3081→4b18767 (создание), 45b4297 (переименование
модели), 96ab6a4 (ruff, zero-semantics)). Менялся **датасет каждого
прогона**:

| Когда (UTC, trained_at) | Артефакт | Датасет-источник | Коммиты/доки |
|---|---|---|---|
| 09-30 23:58 | base PASS | prereg-корпус владельца (canon-data, 276 пар, клоны 0) | 5b22de7/8e12ac2 stage-2 |
| 10-01 03:20 | ds1000 FAIL | синтетика «700 hard pairs» (26 клонов-негативов) | 38f3ec9 handshake |

уже после экспорта B2, как реакция на симптом.

## 6. Чистота B1 (вопрос 3) — вердикт: sanity-PASS ≠ контрактная чистота

Разбор весов/важностей B1 против замороженного контракта (gain-важности,
% от суммы по всем деревьям):

| Фича | base | ds1000 | **B1** | B2 |
|---|---|---|---|---|
| cos_target | 0.4% | 0.5% | **0.1%** | 6.4% |
| char3/4/5_jaccard | 44/11/44% | 43/23/2% | 27/20/26% | 0.4/2/1% |
| char3/4/5_containment | 0/0/0% | 1/1/27% | 0/**27**/0% | 0.1/**73**/0.6% |
| tag_jaccard | **0%** | **0%** | **0%** | **0%** |
| title/body/tag_len_delta | 0.1/0.1/0% | 0.5/3/0% | 0/0.2/0% | 0/**17**/0% |
| type_match | const | const | **const** | [0:1] |
| lang_match | const | [0:1] | **const** | const |

- **tag_jaccard мёртв во всех четырёх бустерах (0% важности).**
- **type_match — константа в обучении base/B1/ds1000**: во всех строках
  этих датасетов `record_type=None`, а `_match(None, None)=0.0` по
  контракту — модель физически не могла научиться type-матчу. lang_match —
  константа в B1 (языки варьируются между парами, но всегда совпадают
  внутри пары).
- cos_target у B1 почти не используется (0.1%): ~99.9% важности —
  текстовые n-gram-перекрытия.

**Следствие для проду:** B1 валиден как текст-overlap-скорер (его
holdout-числа честные), но защитные фичи контракта type/lang/tag в нём
структурно инертны — они не «сломаны», они никогда не встречались в
обучении в вариативном виде. Доверие к проду — с этой оговоркой; чинится
только датасетом (квоты вариативности), не кодом.

## 7. Связь с находками Layer A (вопрос 5)

Layer A (release-v1: `type-lang-mismatch` 36/36; «на текст-идентичных
парах P не опускается ниже cut при cos 0.8/0.5») — **та же семья корня
(состав обучающих данных против контракта фич), но другой механизм, не
#480-desync:**

- 36/36 на «тот же текст + битое поле» — прямое следствие константных
  type_match/lang_match в обучении B1 (§6): модель не умеет весить то, чего
  не видела. Это дефект покрытия датасета, тот же класс, что и отравление
  угла; #480-транспозиция исключена для B1 тем же тестом E1 (13/13).
- Удержание P выше cut при cos 0.8/0.5 на текст-идентичных парах —
  следствие профиля важностей (текст ≈ 100%, cos 0.1%): B1 отвечает
  «дубликат» по текстовой идентичности, почти не глядя на принудительный
  косинус. Это согласуется с sens 1.0 на identity-self и не является
  инверсией; корректируется той же перекалибровкой с квотами.

## 8. План фикса (вопрос 4) — НЕ исполнялся

Корень — датасет → ремонт вlane gcw-dataset-engineer; гейты и
перекалибровка — здесь (gcw-ml-engineer).

1. **dataset-v4 (требования к составу, фиксируются prereg-аддендумом):**
   - запрет клонов-негативов: ни одного негатива с body-ratio ≥ 0.999
     (сейчас 29 в B2, 26 в ds1000);
   - квота угла: ≥ 10 дубликат-размеченных строк с char4_jaccard>0.99 и
     body_len_delta=0 (в B2 сейчас 15 положительных против 35 отрицательных);
   - квоты вариативности: type присутствует и варьируется ≥15% строк
     (сейчас в base/B1/ds1000 — 100% None), языковые и типовые mismatch-пары
     по кодбуку владельца;
   - стратификация cos вниз до 0.4–0.5, чтобы cos_target стал обучаемым
     (сейчас [0.836:1] у B2);
   - разметка клоно-подобных пар (версионные соседи) — только владельцем
     по кодбуку, не силвером.
2. **Код-гейты (маленькие, отдельным PR после расследования):**
   - экспортный смоук `_smoke_onnx` дополнить all-ones угловым вектором и
     unrelated-пробой (сейчас только нули — вырожденный вход);
   - датасет-QA гейт до обучения в `build_train_manifest.py` /
     `verify_dataset.py`: публикация угловых счётчиков (corner dup/not-dup,
     клоны-негативы, константность type/lang) в манифесте и отказ при
     нарушении квот (пороги — через prereg-аддендум);
   - хватит ли sanity-гейта? Как гейт ADOPT — да (поймал B2, в
     gate_contract.json). Но он стреляет ПОСЛЕ траты обучения; corner-QA
     стреляет ДО. Держать оба: sanity — обязательный ADOPT-гейт, corner-QA —
     pre-train гейт.
3. **План перекалибровки** (по docs/runbooks/operator-protocol.md; не
   запускается этим отчётом):
   prereg-аддендум (состав v4 + замороженные пороги corner-QA + seed) →
   сборка dataset-v4 + QA → обучение (5 конфигов D-грида; на 420–700 парах
   CPU: ~30–60 c на конфиг, весь select ≈ 10–20 мин, RAM < 2 ГБ, пиковая
   оценка по б2-прогону) → **sanity-сьют ОБЯЗАТЕЛЕН** (exit ≠ 0 = стоп) →
   single-shot holdout (запечатать до обучения). Объём: ~1 рабочий день,
   машинного времени < 1 ч. ADOPT-вердикт остаётся у Layer B/владельца.

## 9. Воспроизведение

Все числа воспроизводятся локально (данные b1/b2/ds1000 локальные, не в
git; артефакты на месте):

```bash
# симптомы
uv run python -c "from cortex.eval.sanity import run_sanity_suite; from pathlib import Path; \
  r=run_sanity_suite(Path('data/stage2/artifact-b2')); [print(c.name,c.passed,c.detail) for c in r.checks]"
# E1: feature_infos vs пересчитанным фичам, E3-E5: переобучения и контрфакты —
# скрипты из тела отчёта (§3-§5), каждая проверка < 1 мин CPU
```

Переобучения: `DBoostModel().train(features(...), labels, d-l7-lr005)` на
соответствующем train.jsonl, seed=1, `cortex train`-эквивалент — детерминизм
закреплён тестами.
