## 1. Популяция: reconcile «5095 vs 3654»

| Число | Что это | Где живёт |
|---|---|---|
| 5 095 | зонд слайс-0 (пре-гигиена, живой стор, устное чтение «пара с граф-эвиденсом») — триггер ADR-0002 | прег v3 §0; артефакта в репе НЕТ, воспроизведению не подлежит |
| 3 654 | sealed эвиденс-страты пула v4.4: edge-direct 1 139 + edge-common 801 + mint-top 1 714 | `datasets/b2-graph/pool_manifest.txt`, fp `87b3d4c2` (перепроверен BLAKE2b-256 из `pool_candidates.jsonl` — совпадает байт-в-байт) |
| 8 654 | весь пул (+ control 5 000) | там же |

Перепись считалась по ЗАПЕЧАТАННОЙ популяции 3 654 (+ control 5 000 как
контекст). 5 095 ≠ 3 654 потому, что зонд слайс-0 считал пре-гигиену и без
капов пула (полоса [0.85,0.97), top-K=3, дедуп 89 occupied-text-key) — это
третье независимое чтение того же неформального термина «эвиденс-пара»
(см. C4, §6). Тексты пар взяты из локального gitignored-снапшота
`data/b2-graph-corpus/pool_candidates.jsonl` (8 654 строки, fp сверен) —
живой стор для C1/C2 не нужен.

## 2. Методика серебра (детерминированные правила, LLM запрещён)

Источник полей: `pool_candidates.jsonl` — обе стороны (title, body, tags,
language, record_type, created_at), sifter-признаки, граф-колонки, флаги.

| Правило | Формула | Вердикт |
|---|---|---|
| Q карантин | `detect_lang(body_a) ≠ detect_lang(body_b)` при {ru,en} (реплика b2_graph_corpus_v44r2.detect_lang: кириллица/латиница-маджорити, порог 0.7) | вне скоупа (§A(i)), не размечается |
| S-dup | `norm1(body_a)=norm1(body_b)` ∧ `norm1(title_a)=norm1(title_b)` ∧ tagset-равенство ∧ record_type ∧ language; `created_at` свободно (whitelist §8.1) | **silver-dup** (классы 1–2 таксономии; покрывает T1-косметику по нормализации и конверт-дельты) |
| T2 | body+title норм-равны, но tags/type/language различаются | **not-dup** (policy v1.1 §8.1, метаданные) |
| T3-числовой | тела норм-неравны; токен-последовательности равны кроме позиций, где ОБЕ стороны несут цифровые токены | **not-dup** (детерминированное подмножество razor, класс 7) |
| остальное | — | **disputed → NOT dup** (§8.3) |
| `norm1(s)` | lower + collapse whitespace (пин задания) | — |

Честное ограничение: полный razor (факт-правка НЕцифрового ключевого токена —
имена, версии, условия) без понимания текста детерминированно не выделяется —
эти пары уходят в disputed (→ NOT dup по §8.3), т.е. оценка dup ЗАВЫШЕНА не
может быть по построению (консервативна в обе стороны: dup только при точном
норм-равенстве; всё спорное — негатив).

Чувствительности (считаны, в вердикт не входят): `norm2` (доп. схлопывание
пунктуации, §8.2-косметика) — 0 доп. dup; body-only равенство без титульных/
мета-условий — 0.

## 5. C3 — жизнеспособность floor ≥30 (K=30 + непрерывность ≤0.005)

Из sealed пула v4.4: **floor НЕ достижим — максимальный честный размер
dup-страт с эвиденсом = 0 строк.** Инъекционные T0/T1-позитивы (путь v4.4)
граф-эвиденса не несут по построению (ZERO-эвиденс) — g4 на них структурно
равен нулю (диагноз REJECT 22.10 подтверждён переписью).

Зонд живого стора (read-only, `mode=ro` + `PRAGMA query_only`, гигиена 1:1
с цепочкой пула — SQL-гейты → no-federate → quarantine → пин вектора →
ENGINE-сканер; контент только в памяти/`/tmp`) дополнил картину: real-real
дубликаты в сторе ЕСТЬ, но граф-эвиденса на них НЕТ.

### 5.1 Зонд стора (снапшот 22.10, live; два прогона в пределах сессии)

| Метрика | Значение |
|---|---:|
| Снапшот (прогон 1 / прогон 2, стор растёт на глазах) | 4 405→4 407 memories; 1 527 рёбер; 4 377→4 379 векторов |
| Гигиена: candidates / excluded / passed | 4 407 / 1 112 / **3 295** (memory_type 1 058, length<80 16, no-federate 7, status 28, scanner 3) |
| Эндпоинты пула (736), проходящие гигиену сейчас | **736/736** — стороны пула не дрейфнули |
| Пары cos ≥ 0.92 (зона минта, вся) | 936 314 |
| Пары cos ≥ 0.97 | 44 140 (из них с ребром 117) |
| **silver-dup (детерминированное серебро §2)** | **68 пар** (все: body+title norm-равны, теги/тип/язык равны, created_at различается ≤ минуты) |
| …из них с граф-эвиденсом (edge ∨ cn>0) | **0** |
| Спорные / карантин кросс-язык в зоне | 913 137 / 23 109 (транслированные близнецы) |

| Связь с пулом | **0 из 130** записей дуп-кластеров — эндпоинты пула (пул = записи с рёбрами; безрёберные записи в пул не попадали) |

Формулировка вердикта:

1. **Floor «≥30 dup-строк с эвиденсом» — НЕ достижим** ни из пула (0), ни из
   живого стора (68 реальных dup — все с нулевым граф-вектором; 1 296
   рёберных пар в зоне — все silver-NOT-dup: 0 из 68 dup имеют ребро).
   Аттрибуция ΔBA на этой популяции структурно равна нулю: аблированная
   модель видит тот же нулевой граф-блок → предсказания идентичны → ΔBA ≡ 0
   (тот же отказ, что в 1.n, теперь доказан на всей реальной популяции).
2. Реальная dup-масса стора — **артефакт пере-ингаляции**: 64 кластера
   покомпонентно идентичных записей, сохранённых в пределах минут
   (batch re-save), вне рёбер и вне пула. Формально coverage-ассерт §D на
   банде [0.985, 1.0] прошёл бы вырожденно (K=68, max-gap 0 в одной точке
   cos=1.0 — нет интерполяционного покрытия), и всё равно не дал бы g4
   ничего: эвиденс-нуль.
3. Дедуп-движок движка НЕ ставит рёбра на точные пере-сохранения (68/68 без
   рёбер) и НЕ сшивает дубликаты — «граф-эвиденс» и «дубликат» в текущем
   сторе — непересекающиеся множества. Это факт ПОПУЛЯЦИИ, не порогов.

### 5.2 Альтернативы (перечень, выбор — не в этом слайсе)

- **A. Store-native dup-страта без g4.** Взять 68 (растущих) real-real dup
  как позитивную эвиденс-струну для g2-типа проверок («модель ловит реальные
  дубликаты»), g4 на них не замерять. Меняет смысл g4 → решение TL/NA +
  владелец (прег = аннулирование, нужен новый прег).
- **B. Owner-gold на рёберных парах [0.97,1.0].** 117 пар с рёбрами при
  cos ≥ 0.97 (серебро: NOT-dup) — отдать владельцу на разметку; если среди
  них есть истинные дубликаты — появятся dup-строки С ребром. Ожидаемый
  выход низкий (вердикт B2: relates_to = связность; sifter: медиана 38
  razor-токенов), риск нуля реален.
- **C. Синтетика с store-идентичностью (v4.5-генерация).** Регистрировать
  T0/T1/T5/T6-позитивы в scratch-сторе и прогонять через реальный
  auto-dedupe — граф-фичи возникают из настоящей топологии. Риск
  тафтологии (модель выучит «ребро есть ⇒ dup»), но это и продовая семантика
  признака. Решение NA/TL; в этой волне НЕ запускается.
- **D. Движок: сшивание точных пере-сохранений.** Фича-запрос продукту vesma
  (дедуп движка не эджит 68 кластеров точных копий) — когда появится,
  real-real dup-масса начнёт нести рёбра естественно. Вне скоупа cortex.
- **E. Переформулировать аттрибуцию g4.** Вместо ΔBA на тонкой страте —
  уровневая аттрибуция (важности/сплит-статистика граф-блока на полной
  популяции). Методология оценки, пороги формально не трогает, но меняет
  прег → владелец/NA.
- **F. Отложить 1.n+1 (watchlist).** Триггер прега §5 «доля эвиденс-записей
  в проде» дополнить условием «существуют ≥K dup-пар с ненулевым
  граф-вектором» — пересчёт этим же зондом (скрипт в /tmp, воспроизводим).

## 6. C4 — формальное определение эвиденс-строки

Три чтения термина «эвиденс-строка» на одной и той же поверхности holdout
v4.4 (75 строк) дали три числа — источник расхождения «18 vs 24» в отчёте
retry:

| Чтение | Формула | Число |
|---|---|---:|
| provenance (страта происхождения) | stratum ∈ {edge-direct, edge-common, mint-top} | 24 |
| замороженный флаг (так мерил g4) | `has_graph_evidence = edge_ab ∨ common_neighbors>0` по замороженным колонкам пула (`src/cortex/features/graph.py`) | 18 (10+7+1: из 7 mint-top только 1 несла cn=2) |
| свежий sidecar-джойн | пересчёт по текущему стору на гейте | 10 (7+2+1; у 14 из 24 строк стороны в текущем сторе не разрешаются) |

**Предложение (одной фразой):** эвиденс-строка v4.5 := строка, чей вектор
граф-фичей ненулевой хотя бы в одной из пяти замороженных компонент
`GRAPH_FEATURES`, что эквивалентно `edge_ab=1 ∨ common_neighbors≥1`
(остальные три импликативно покрыты: nj>0 ⇒ cn>0; cos_to_common_max>0 ⇒ cn>0;
supersedes ⇒ edge_ab) — прицепленный граф-блок на такой строке реально
отличается от нуля, т.е. абляция g4 наблюдаема покомпонентно.

Implications для holdout v4.5 (10% нового материала):

1. Стратифицировать выборку holdout по (label × evidence-флаг × страта), не
   только по (label × страта): эвиденс-строка — свойство строки, а не страты.
2. mint-top распадается на два подмножества: mint-top-evidence (196 в пуле
   1.714) и mint-top-zero (1 518); считать квоты отдельно, иначе «эвиденс-страта»
   снова молча разбавится нулями (это и произошло в v4.4: 6 из 7 mint-top
   строк holdout были нулевыми).
3. Пиннуть ОДНО чтение на весь гейт-цикл: замороженные колонки при сборке +
   ассерт согласования со свежим sidecar'ом на гейте (строки с
   неразрешившимися сторонами — из эвиденс-страты в карантин счётчиком, не в
   молчаливый минус). Иначе g4 сравнивает разные поверхности (18 vs 10).
4. Дизъюнктность: pair-level ассерты как в v4.4 + срез side-флагов
   (`holdout_side_overlap`/`gate_side_overlap`/`burned_side_overlap`) при
   вырезании holdout — рецепт пре-гейта слайс-1, колонки есть в каждой строке
   пула.
5. Для позитивов 1.n+1 (real-real dup с граф-эвиденсом): фиксировать
   `cos_to_common_max` в экспорте (сейчас None для pool-строк — модель видела
   0.0) либо считать его при сборке; иначе у половины граф-блока значения
   вырождены.
6. Representation-ассерт по §D расширить на эвиденс-страту: K=30 + непрерывность
   cos-банда ≤0.005 внутри dup-с-эвиденсом материала (сейчас §D покрывает
   только классы-пробы сьюта).
