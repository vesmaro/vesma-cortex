## 3. Что изменилось против фриза-1 (row-level)

Изменена ровно **одна сборка из 43** и **два блока из 188**:

- `metrics_id=43` (край окна, 2026-11-01T00:00:20Z): `usage_reported`
  false → true. Окно этой сборки цензурировано краем данных, поэтому
  её `l0_dead` был и остался `null` — мёртвость не сдвинулась, сместился
  только coverage.
- Блоки `43:0`, `43:1`: `touched_in_window` false → true (тот же бэкфилл).
- `usage_reports` в сайдкаре: 39 → 41 строки (одна сборка, два
  отчёт-события). Точная дата прихода отчётов неизвестна — в таблице нет
  временной метки; границы: после фриза-1 (01.11 00:25 UTC) и до фриза-2
  (10.11 06:59 UTC). Остальные 4 цикла без отчётов — `metrics_id`

## 4. Диагностика застоя `assemble_metrics` (главный находинг)

Двигатель жив и пишет, но сборки не пишутся:

| Таблица сайдкара | Последняя строка | Строк с 01.11 |
|---|---|---|
| `verb_metrics` (все surface'ы) | **2026-11-10 07:02 UTC** — минуты до фриза | 70 648 |
| `assemble_metrics` | 2026-11-01 00:00:20 UTC | 0 |
| `turn_usage` | 2026-10-29 15:48 UTC | 0 |
| `awareness_events` | 2026-10-08 01:25 UTC | 0 |

Трафик с 01.11 по surface: `background` 69 889 (всё ok), `cli` 620,
`mcp` 142 (всё ok), **`rest` — 0 строк**. Исторически injection-петля
сессий ходила через rest-поверхность; её полное молчание при живом
background/cli/mcp-трафике говорит скорее о том, что **ни одна сессия
харнеса с 01.11 не проходила через сборку** (петля не вызывается),
чем о поломке записи (поломка давала бы rest-строки с error). Механику
вызова петли проверить движковой стороной — это вне ML-зоны; до
разбора **следующий недельный фриз заморозит тот же срез**, и каденс
линии не накапливает данные.

## 5. Открытые вопросы — обновления против базлайна

- **Q3 (5 циклов без отчётов) — сузился.** Все 4 оставшихся цикла без
  отчётов (18, 22, 26, 27) — **последние в своих сессиях**
  (last-in-session, проверено по сайдкару). Восстановившийся цикл 43 —
  тоже last-in-session, но его отчёт пришёл позже (сессия была жива ещё
  после фриза-1). Рабочая гипотеза: отчёт пишется следующим ходом
  сессии; сессии, закрывшиеся сразу после сборки и не возобновлявшиеся,
  недоотчитывают безвозвратно. Это меняет трактовку coverage: часть
  «недостачи» — свойство хвостовых сборок, не сбой харнеса.
- **Q2 (разреженный режим завышает мёртвость)** — без изменений: новых
  окон нет, базлайн 66% остаётся верхней оценкой разреженного режима.
- **Q1 (`in_cache_prefix` без наземной истины)** — без изменений,
  6/188 по proxy. Вопрос к TL/MLC открыт.
- **Q4 (L+3/L+2 не собираются)** — без изменений (Plane B).
