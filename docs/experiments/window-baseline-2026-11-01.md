## 2. Базовые числа (prereg §2–§4.1)

### 2.1 Доля «мёртвых» блоков — главный базлайн L2

Окно мёртвости T = 3 последующие сборки или 30 минут (что раньше), скоуп
— окно, не одна сборка; поток сборок глобальный (ts, id). Сигнал —
usage-контакт с block_id, передаваемый на ту же память внутри окна
(отчёт может назвать только блоки своей сборки; реинжекция несёт
сущность дальше).

| Метрика | Значение |
|---|---|
| Решённых блоков (окно закрылось) | 180 / 188 (8 цензурировано — край данных, <3 последующих сборок) |
| **Доля мёртвых (решённые)** | **66.11%** (119/180) |
| Коррекция `re_requested` (та же память перезапрошена после выхода из окна в пределах T) | 11 блоков → **скорректированная доля 60.00%** |
| Состав решённых окон | 159 окон закрылись по таймауту с 0 сборок внутри (101 мёртвых), 21 окно содержали ≥1 сборку (18 мёртвых) |

Интерпретация: трафик сайдкара разреженный — 88% решённых окон закрылись
таймаутом, не накопив ни одной пересборки; живость блока почти целиком
несёт собственный usage-отчёт сборки (58 из 61 живых). Это честный базлайн
разреженного режима, не плотного диалога. Доля мёртвых ≥15% — порог L3
выполнен и с запасом, но на n=43 цикла это сигнал, а не вердикт.

### 2.2 usage-coverage (join-полнота)

**88.37%** (38/43 assemble-циклов имеют ≥1 usage-отчёт). 5 циклов без
отчётов — «хвост» сессий, где харнес не вернул отчёт. Пол L3 (≥80%)
выполнен; по мере накопления смотреть на устойчивость.

### 2.4 Дубликаты в W2 recall-блоках (до арбитра W1–W3)

- Внутри одной сборки (pairwise по `dup_group`=sha256(norm(content))):
  **1 блок из 188 = 0.53%** — точные нормализованные дубликаты внутри
  окна почти отсутствуют.
- Межсборочная повторная инжекция той же памяти: 88/188 = 46.8% блоков
  делят `dup_group` хотя бы с одним блоком другой сборки — это
  реинжекционный фон (та же память пересобирается в новые окна), не
  внутреокновый мусор; пригодится для cache-оси L2.

Ограничение: без эмбеддингов (stdlib-only) похожесть = точное совпадение
нормализованного контента — консервативная нижняя оценка дубликатов.

### 2.5 Прочее (срез данных)

  25 блоков (13.3%).
- `in_cache_prefix` (proxy по рециркуляции в предыдущей сборке): 6/188 —
  см. открытый вопрос Q1.
- Возраст памяти в окне: до 101.5 дня (память старше TTL сайдкара 90д —

## 4. Открытые вопросы / ограничения данных

- **Q1 — `in_cache_prefix` без наземной истины.** Сайдкар не хранит
  позицию блока относительно cache-breakpoint (align-статы — агрегаты
  сборки). Экспортёр пишет честный proxy (память реинжектирована в
  предыдущую сборку на ординале ≤ текущего; метод объявлен в манифесте),
  6/188 срабатываний. Для настоящего флага нужно аддитивное движковое
  поле или переопределение признака — вопрос к TL/MLC (аддендум ADR 0007).
- **Q2 — разреженный режим искажает мёртвость.** 88% решённых окон
  закрылись таймаутом с нулём пересборок. При накоплении трафика доля
  таких окон упадёт; до тех пор базлайн 66% — верхняя оценка. Возможная
  уточняющая метрика — мёртвость среди окон с ≥1 пересборкой (18/21 =
  85.7% на текущем срезе, n слишком мал).
- **Q3 — 5 циклов без usage-отчётов** (coverage 88.37%): откуда хвост —
  крэш сессии или отчёт не отправлен — по сайдкару неразличимо. Если
  пол ≥80% начнёт таять, смотреть в харнес (G0b-петля).
- **Q4 — L+3/L+2 метки не собираются** (харнес не отдаёт ответ/tool-call
  в петлю с привязкой к блокам). До Plane B иерархия меток ограничена
  L+1/L0/re_requested — этого хватает базлайнов L2, не L3-качества прокси.
- **Ограничение n:** 43 цикла против пола L3 2000 — все выводы среза
  предварительные; следующий фриз по каденсу сравнит дельты.
