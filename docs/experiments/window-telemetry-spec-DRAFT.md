# Телеметрия состава окна модели (Layer 0 «динамический контекст») — СПЕКА-DRAFT v0

- **Статус:** DRAFT v0 — СКЕЛЕТ ПРЕДСЕДАТЕЛЯ для MLC раунда 8 (диспетчи
  членов заблокированы провайдером 31.10; комитет позиционируется против
  этого скелета при восстановлении — независимость вердиктов сохраняется:
  раунд позиций идёт ПОСЛЕ, не вместо). Владелец санкционировал Layer 0
  31.10 («телеметрия первая, единый пакет с W1-W3 в vesma»).
- **Санка-рамка:** телеметрия ТОЛЬКО НАБЛЮДАЕТ — окно не меняет, ничего не
  покидает локальную машину, не читает чужие сессии (firewall-класс
  D1-монитора). Урок, который возвращает эту спеку: fusion REJECT — не
  обучать куратора до измерения сигнала.

## 1. Цели (falsifiable)

1. Измерить фактический состав окна модели: доли классов (токены/байты),
   динамику по ходу сессии.
2. Собрать датасет для будущей curator-линии (L3): запрос → блоки →
   вердикт использован/выброшен (прокси-метки + expert-выборка).
3. Дать базлайны для L2 (rules-curator v0): против чего мерить успех.

## 2. Таксономия состава окна (классы съёма)

| # | Класс | Комментарий |
|---|---|---|
| C1 | системный префикс харнеса | НЕ наш контур — мерим для полноты, рычага нет |
| C2 | память-recall (assemble_context) | наш главный рычаг; внутри — подпорт C2a дубликаты (до/после арбитра W1-W3), C2b отработанные/устаревшие |
| C3 | tool-outputs | с CCR-следом (сжато/несжато) |
| C4 | диалог (прошлые ходы) | кандидат эвикции №1 |
| C5 | текущий запрос | не эвиктируется |
| C6 | прочее/неразобранное | честная корзина |

Каждый класс: токены, байты, число блоков, cache-статус (стабильный префикс
vs хвост — CacheAligner-семантика).

## 3. Точка съёма и sampling

- **Точка:** момент сборки блока (assemble_context return) + срез ответной
  фазы модели (какие блоки реально читались — прокси релевантности §4).
- **Sampling:** MLC-позиция (варианты: все вызовы в наших сессиях — объём
  мал; каждый N-й в проде —成本). Прототип харнес-стороны: все.
- **Схема события:** `CORTEX-WINDOW` (append-only, локально;
  secret-scan на записи; поля: session, turn, class_census {class: tokens},
  blocks[{id, class, tokens, age_turns, recall_score, ccr_state}],
  relevance_proxies{}, env_pin, schema_version). Тексты памяти — НЕ пишутся
  (хэш + длина + класс), data-contract.

## 4. Прокси релевантности (для датасета L3) — MLC-вопрос

Кандидаты (ML-нога детализирует): блок процитирован/перефразирован в ответе;
блок — источник tool-call; блок повторно запрошен recall'ом в следующих
ходах; expert-выборка (владелец НЕ ресурс — прототип комитета-серебра на
выборке сессий TL/ML-ногами).

## 5. Метрики-базлайны (для L2/L3) — MLC-вопрос

Кандидаты: доля C2a (дубликаты) в recall-блоке; доля «мёртвых» блоков
(ни разу не релевантных за N ходов); суммарные токены хвоста на запрос;
cache-hit стабильность префикса; no-harm на качество ответов при эвикции
(принцип арбитра: воздержание дёшево, потеря контекста дорога).
