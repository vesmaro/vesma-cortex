# Record-quality фаза 1 — пример-прогон на живом strict-сторе (выборка 200)

- **Статус:** выполнен 2026-10-28; информационный прогон (не гейт).
- **Скорер:** `cortex.quality` ревизия `record-quality-phase1/v1`
  ([формула](../specs/record-quality-phase1.md)); валидатор —
  `vesma.canon_validate`, движок **6.6.0** (пинованный чекаут release/6.6.0).
- **Метод** (data-contract §6): живой стор открыт строго read-only
  (`file:…?mode=ro` + `PRAGMA query_only=ON`), sqlite3-backup в
  `/tmp/record-quality-phase1-sample-20261028T090134.db`, живое соединение
  закрыто, скоринг — по копии. Выборка — **200 новейших** строк
  `memories` (`ORDER BY created_at DESC, id`), детерминирована на момент
  прогона. Ни одной строки контента этот документ не содержит — только
  счётчики, распределения и id-префиксы; `detail`-строки нарушений не
  покидают память зонда.
- **Воспроизведение:**
  `python3 scripts/record_quality_sample.py --limit 200` (стор
  `/var/home/abyss/.vesma/data/vesma.db`, движок — соседний чекаут
  `../vesma/src`; оба пути перекрываются флагами `--store` / `--engine-src`).

## Наблюдения (вход для решения о ML-фазе 2)

1. **Конверт-дисциплина чистая**: за выборку — ни одного
   envelope/lineage/section/status/language/title-нарушения. Серверный
   минтинг и клиентские пути пишут канон аккуратно.
2. **Единственный класс промахов — даты в теле** (канон §5): относительные
   и усечённые формы в телах session_context. Это тот самый «остаточный
   промах», о котором говорит коррекция АрхКома: он формализуем кодом
   (что фаза 1 и показывает), а не требует модели.
3. Доля in-scope 0.685 — легаси-строки без конверта остаются вне скоупа
   по canon §9 и в score не попадают (NO-DATA, не 1.0).
4. Для ML-фазы 2 (слияние с №8, условна) этот прогон сам по себе —
   аргумент «против»: остаточные промахи одного класса и без ML видны
   адресно; решение остаётся за B0-телеметрией по реальным промахам.

## Гигиена прогона

- Живой стор: только backup-API чтение, ни одной записи/блокировки;
  контейнеры не трогались.
- Дерево движка: `sys.dont_write_bytecode` на окно импорта; `__pycache__`
  дерева не пополнялся (пиннуто тестом `test_engine_pycache_hygiene`).
- Замечание окружения: в user site-packages машины присутствует чужая
  инсталляция `vesma 6.4.0` — она затеняет плоский `sys.path.append`;
  лоадер скорера сажает пинованный корень в `sys.path[0]` на окно импорта
  и ассертит идентичность модуля (спека §3).
