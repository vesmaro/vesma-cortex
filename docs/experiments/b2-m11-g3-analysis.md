### 3.1 Формальное серебряное правило cross-lang дубликата (расширение §A)

Пара A,B с lang(A) ≠ lang(B) — **duplicate** ⇔ выполнены ВСЕ предикаты:

1. **Двустороннее сохранение слотов**: существует биекция слотов
   S = {(имя, v_A, v_B)}, где v_A/v_B — значения ключевых фактов
   (числа/даты/имена/версии/суммы) по §8 policy v1.1, и каждый слот A имеет
   равный слот в B и наоборот (равенство на канонической форме значения).
2. **cos-банд**: cos ∈ [0.55, 0.86] (измеренный замороженным эмбеддером,
   формула сборщика).
3. **Конверт-инварианты**: tag_jaccard = 1.0; type_match = 1.0;
   tag_count_delta = 0.
4. Спорное → NOT dup (§8.3).

Операционализация без LLM-разметки — **генераторная бухгалтерия слотов**:
пара строится из таблицы слотов, обе стороны порождаются из ОДНИХ значений,
слот-карта пишется в манифест сборки (дайджест, не сырой текст). Два
подсемейства:

- **T (verbatim)**: факт-токены копируются в обе стороны без перевода —
  предикат 1 проверяется строковым containment в обе стороны
  (детерминированный ассерт).
- **V (free)**: слоты могут вербализоваться (как в v4.2-экзамене:
  «one meter sixty») — предикат 1 проверяется равенством по слот-карте
  генератора (детерминированно); char-ликаж логируется монитором, НЕ
  ассертится (в экзамене 10/15 строк с нулевым ликажем — требовать его
  для всех dup нельзя).

LLM-разметчик допустим только как офлайн-черновик шаблонов, замороженный
до сборки; лейбл = функция построения (policy §4), ассерты сборки
проверяют измеримое.

### 3.2 Класс-контракт генератора (что гарантировано, что ассертится)

Гарантии генератора: один скаффолд-шаблон на семейство-пару; дубликат и
сиблинг порождаются из ОДНОГО шаблона (alignment §D: класс → генератор-параметры
→ и трейн-инстансы, и пробы).

Ассерты сборки (иначе сборка не запечатывается):

- **dup (T)**: containment каждого слота в обе стороны ≥ 1 вхождения;
  ch3c ≥ 0.01 (ликаж гарантирован); cos ∈ [0.55, 0.86]; bld ≤ 60.
- **dup (V)**: равенство слот-карты; cos ∈ [0.55, 0.86]; bld ≤ 130
  (покрыть экзаменационную меду 56 и хвост 129); ликаж-монитор в run-log.
- **sibling (v4.2-рецепт, добор при необходимости)**: НИ одного общего
  слот-токена (ассерт), cos-банд попарно согласован с dup-бандом той же
  ячейки (±0.005, §D), tagj = 1.0, lm = 0.
- **Квота/паритет ячейки**: в каждом cos-бине [0.55,0.65)/[0.65,0.75)/
  [0.75,0.86] — n_dup(v4.2-рецепта) ≥ n_sibling в бине (паритет ≥ 1.0
  против замороженных 144) и K ≥ 30; непрерывность cos ≤ 0.005 (§D-б).
- **Скаффолд-антиколлапс** (§D): ≥ 20 скаффолдов, ≤ 5 % строк на скаффолд.

## 4. Q3 — совместимость с замороженным

**Дефолт-рекомендация: экзамен v42-276 (fp `5fce766b…`) и пороги g1–g6 НЕ
меняются; фикс целиком train-side через ADDENDUM-2, ратифицируемый ДО
прогона.** Обоснование: все три красные страты — дефекты состава трейна
(§2), ни одна не требует изменения экзамена или фиче-контракта. P-trans НЕ
вне скоупа по §A строке (i): карантин строки (i) касается МИТОВ пула
(реальные store-пары), а синтетическая translated-страта в экзамене живёт
со времён v4.2 и прод-артефакт B2-v42 (BA 0.9662) держит её — значит
держать её обязан и любой наследник; снимать страту с экзамена = терять
именно ту гарантию no-harm, ради которой g3 существует.

Арифметика коридора (пол 0.9449): починка одного P-trans даёт BA ≈ 0.9135
(sens 142/144, spec 132/132 → (0.9861+1.0)/2 = 0.9931 только если fp тоже
убиты). Точно: при починенном P-trans и сохранении 21 fp — BA 0.9135
(красный). Починка P-trans + fp ≤ 12 → BA ≥ 0.9449; при починке и 2 fn
P-para-light (sens 1.0) допускается fp ≤ 14. Значит рецепт обязан снять
минимум ~9–12 из 21 fp — целевые страт-пороги добора: N-fact-edit spec
≥ 0.95, N-near spec ≥ 0.90.

**Флаг владельцу (явно, с ценой вопроса)**: даже зелёный g3 НЕ меняет
вердикт ревизии 1.n — g4 красный структурно (эвиденс-страта holdout 18
строк все NOT-dup, все позитивы ZERO-эвиденс по построению, 0/200 сплитов
на граф-фичах, full ≡ ablated байт-в-байт; аттрибуция +2 пп на такой
популяции невозможна в принципе при любом качестве графа). Варианты:
(1) 1.n+1 = новый прег v4 с популяцией «dup с граф-эвиденсом»
(auto-dedupe ≥ 0.92 обеих сторон, кандидат §7.1 отчёта retry) — тогда
сравнимость с 0.9662 сохраняется частично (v42-276 остаётся g3-поверхностью,
ноadopt пойдёт по новой популяции); (2) принять, что ревизия 1.n остаётся
REJECT, граф-блок остаётся в watchlist, ADDENDUM-2 выпускается как
maintenance-корпус без adopt-претензий графа. Рекомендую (1) при готовности
владельца ратифицировать прег v4; (2) как fallback без цены.

## 5. Q4 — почему fact-edit всё ещё красный после переноса razor-блока
