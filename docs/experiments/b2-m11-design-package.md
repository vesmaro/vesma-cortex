## 0. TL;DR

Ревизия 1.n+1 = **maintenance-ревизия**: чиним g3 (перегенерация
translated-dup + два добора), добавляем гейт флоры g1b, собираем новый
sealed holdout v4.5 и — главное решение АрхКома — **закрываем g4-as-designed
как неприменимый** (популяция «дубликат с граф-эвиденсом» пуста в сторе по
построению: перепись показала 0 из 3 654) и заменяем его **g4′** — recall на
реальных пере-сохранениях (новая страта A корпуса) при spec-поле на
hard-негативах. Вопрос владельца «какая реальная пара считается
дубликатом» закрыт данными: **ни одна real mint-пара** (семантика
`relates_to` = «связано, не дубликат» подтверждена на всей поверхности);
реальные дубликаты стора — 68 пере-сохранений без единого ребра. Граф-блок
остаётся в watchlist с дрейф-монитором; reopen — по механизму, не по сроку.

## 1. Ответ на вопрос владельца о dup-метке (закрытие АрхКомом)

Под ратифицированным серебром (§A: двусторонний энтейлмент + ключевые
факты; спорное → NOT dup):

| Популяция | Число | Вердикт серебра |
|---|---:|---|
| Эвиденс-пары пула (рёбра/минт, cos ≥ 0.92) | 3 654 | **0 dup** (3 648 disputed → NOT dup, 6 карантин кросс-язык) |
| Реальные дубликаты живого стора | 68 (64 кластера) | все dup, **все с нулевым граф-вектором** (0 рёбер, 0 общих соседей) |
| Рёберные пары зоны минта | 1 296 | все NOT-dup (117 тяжёлых при cos ≥ 0.97: медиана 38 razor-токенов) |

«Дубликат» и «граф-эвиденс» — **непересекающиеся множества**, и это не
случай снапшота, а семантика записи: auto-dedupe минтит ребро «связано,
не дубликат» на парах, которые движок уже различил; истинные дубли —
пере-сохранения, которые движок рёбрами не связывает. Проверка TL по коду
(`manager.update` принимает `content`) показала: окно дрейфа (правка тела
связанной пары до копии при сохранённом ребре) существует — поэтому
дизъюнктность = факт снапшота с механизменным reopen-условием (A2.9), не
вечный закон. Следствие для границы компетенции: детекция пере-сохранений
и защита от ложного схлопывания — кортекс; схлопывание (merge/supersede) —
консолидация движка.

## 2. Решение АрхКома (сводка)

- Принял направление 1.n+1 = maintenance-ревизия через ADDENDUM-2 (позиции
  TL и PA совпали; NA/DE — письменно, критика отработана в протоколе).
- Принял страту A (реальные пере-сохранения, кластер-целостный сплит) как
  новый позитивный класс — поправка PA против моей исходной редакции:
  классификатор, не видевший реального пере-сохранения, может пройти
  g1–g3 и не решать продуктовую задачу.
- Отклонил: синтетику с store-идентичностью (C — тренирует противоречие
  семантике записи: «ребро ⇒ dup» в проде = тихая потеря данных),
  owner-gold на 117 рёберных парах (B — ожидаемый выход ≈0),
  зомби-триггер watchlist (F — переформулирован в дрейф-монитор).
- Переиздал NA-вариант «прег v4 с популяцией dup-с-эвиденсом»:
  владелец не может волей создать популяцию — reopen только через
  механизмы A2.9 (правки тел / кросс-языковой минт / движковое сшивание D).

## 3. Дизайн корпуса v4.5 (композиция)

База: v4.4-r2 (4 097, fp `bb1ca943…`) без пересборки унаследованных
страт + добавки (все формулы и ассерты — в ADDENDUM-2):

| # | Добавка | Квота/правило | Ассерты сборки |
|---|---|---|---|
| 1 | translated-dup (T+V, слот-бухгалтерия) | паритет ≥ 1.0 с sibling 144 в каждом cos-бине [0.55,0.65)/[0.65,0.75)/[0.75,0.86], K ≥ 30 | containment слотов / равенство слот-карты, cos-банд, bld ≤ 60/130, ≥ 20 скаффолдов |
| 2 | class-7 same-language (однофактовая правка, короткое тело) | паритет ≥ 1.0 по ячейкам ch5j [0.80–0.95) при cos ≥ 0.985, lm=1, K ≥ 30/ячейку | lang-группа объявляется каждой строкой |
| 3 | N-near tag-clone | cos [0.78,0.92] банды ±0.005, K ≥ 30/банд, паритет ≥ 1.0 против позитивной массы ячейки | bld ≤ 60, tagj = 1.0 |
| 4 | **страта A** (реальные пере-сохранения) | train ≥ 30 пар; holdout 2–3 полных кластера | кластер-целостность, fp снапшота, дизъюнктность |

Доля dup трейна после добавок пересчитывается сборщиком (формула 40.5 %
v4.4 сохраняется как цель состава, не как жёсткая константа — ассерты
паритетов управляют составом). Sibling-блок 144 и razor-блок v4.2 не
трогаются.

## 4. Sealed holdout v4.5

Свежий 10 % из нового материала (v4.4-й сожжён): стратификация
label × evidence-флаг × страта; mint-top делится на evidence/zero;
одно чтение термина «эвиденс-строка» (`edge_ab=1 ∨ common_neighbors≥1`)
на весь цикл с ассертом согласования sidecar'а; дизъюнктность pair-level
+ срез side-оверлап-флагов; `cos_to_common_max` фиксируется в экспорте.
Детали — ADDENDUM-2 §A2.5.

## 6. Watchlist и движковая линия

- **Дрейф-монитор** (A2.9): перепись-зонд воспроизводим; reopen при ≥ 30
  dup-пар с ненулевым граф-вектором (механизмы: правки тел, кросс-языковой
  минт, сшивание D).
- **Фича-запрос D** движку vesma (сшивание точных пере-сохранений) — в
  бэклог движковой сессии отдельной строкой: ценность самостоятельная
  (пользователю не нужны дубли-кластеры в сторе), кортекс от него не
  зависит и бэкфилл не закладывает в популяцию.

## 7. Позиции на ратификацию

1. **Замена g4 → g4′ + закрытие g4-as-designed** с reopen-условиями A2.9.
   *Рекомендую принять* — популяция старого g4 пуста по построению;
   повторный прогон без замены гарантированно повторяет REJECT.
2. **Пороги g4′**: recall = 1.0 на страте A holdout (2–3 кластера, ≈2–7
   пар — ноль промахов на самых лёгких позитивах); spec hard-негативов
   ≥ 0.90 (зеркало g2). *Рекомендую принять.*
3. **Страта A в корпусе** (кластер-целостность; holdout 2–3 полных
   кластера; K ≥ 30 в трейне). *Рекомендую принять.*
4. **ADDENDUM-2** целиком (A2.1–A2.6, A2.8–A2.10): слот-бухгалтерия
   cross-lang серебра, доборы по ячеечным паритетам, g1b. *Рекомендую
   принять.*
5. **Переформулировка цели линии** (PA, смена формулировки, не признание
   невыполнения): «dup-вердикт, в котором связи памяти защищают от
   ложного схлопывания; детекция пере-сохранений — за классификатором
   без граф-претензий; схлопывание — за консолидацией движка». *Рекомендую
   принять — механизм уже работает так.*
6. *(Не блокирует)* **Фича-запрос D** движковой сессии. Решение по удобству.

## 8. Риски

- **g3 может остаться красным** после доборов (NA-арифметика требует снять
  ≥ 9–12 из 21 fp): паритетные ассерты закрывают оси промаха; прецедент
  b2p-v41 — красный сьют = корпус-фикс; второй FAIL того же ассерта =
  эскалация владельцу (урок round-4).
- **g2 на новом материале**: добавки заведомо жёстче (translated-dup в
  экзаменационной геометрии, реальные пере-сохранения); пороги не
  ослабляются — честный риск по прегу.
- **Дрейф стора**: страта A растёт (пере-ингаляции); снапшот сборки
  фиксируется fp, рост disclosed в манифесте.
- **Малая n страты A в holdout**: 2–7 пар — порог «ноль промахов»
  статистически груб, но семантически верен (cos ≡ 1.0).

## 9. План после ратификации

DE: билд v4.5 по ADDENDUM-2 (ассерты сборки → seal holdout v4.5 у TL) →
ML: обучение full+ablated, sanity 9/9 + g1b → single-shot гейт-раннер
(g1–g6′) → вердикт. Оценка: сборка+обучение+гейт ≈ 1–1.5 дня (масштаб
v44-r2: сборка ~минуты, обучение ~50 s/модель, гейт ~5 s; доминирует
генерация и ассерты). При ADOPT → M3 engine-волна → M4 релизный поезд
(окно 25–26.10, коридор 28.10 — удерживается при ратификации 22–23.10).
