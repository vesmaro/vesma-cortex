  (vesma-cortex), вердикт ADOPT 2026-10-30 (см.

  GCW-оформление РЕФЕРЕНС, финальная форма переавторяется в нативных

## 1. Что интегрируется

**Choice-арбитр** — выбор члена кластера дубликатов при консолидации
(примитив 1-из-k с воздержанием: `keep ∈ {1..k} ∪ {ABSTAIN}`).

| Компонент | Пин/значение |
|---|---|
| Модель (LightGBM booster + пороги) | `merge_arbiter_v2.json`, sha256 `60d1fe733937accf936776327f8f259fc2116aa6ffd011e81cd448a283bceefd`, τ_hi 0.90 / τ_m 0.50 |
| Фиче-контракт | 34 фичи: 13 frozen pair (`cortex.features.pair`, импорт без реимплементаций) + направленные/edit-регионы + envelope (created_at ISO-8601 UTC → epoch-сек + null-флаг) + **e_cos** (mean-over-others cos nano на norm1) + **zeps-блок** (7 eps-флагов) |
| Эмбеддер | nano, sha256 `3b752e06…`, 384-dim; конвенция norm1; env ort 1.30 |
| Зона-эшелон (refusal-нога) | `(cos ≤ 0.85 ∧ char5 ≤ 0.05) ∨ (zeps ≥ 3 ∧ char5 ≤ 0.20)` — ПАРНЫЙ cos кандидата; refusal-only, keep-сторона осей не читается; отказы маркируются происхождением zone-v1 |
| Симметрия | member-фичи агрегируются mean-over-others; строки фичи байт-инвариантны к перестановке предъявления |

## 2. Производственный контур (порядок предикатов, §5.1 + ADDENDUM-6)

1. **CH-0** (sha-тождество тел) → tie-break-код keep-oldest, fold;
2. **CH-5** (¬CH-0; различие стирается нормализацией) → keep-oldest, fold;
3. **CH-2** (тела и заголовки тождественны, метаданные {tags, record_type,
   language} различаются) → **отказ** (fold запрещён);
4. **ЗОНА v1** → **ABSTAIN** (отказ);
5. **остаток** → модель {keep | ABSTAIN}: keep = argmax e_i при
   e(1) ≥ 0.90 ∧ e(1) − e(2) ≥ 0.50, иначе ABSTAIN.
ABSTAIN = схлопывание не производится (асимметрия: лишняя копия дёшева,
FP-схлопывание необратимо). Арбитр получает кластер ТОЛЬКО после серебряного
воротила is-dup (v42 не трогается).

## 3. Требования к движковой стороне (W1–W3)

1. **Минт lineage_marks** (ратифицированные kind'ы): `same-message-other-envelope`,
   `merged-by-arbiter` (с ref на выжившую запись), `split-from`. Сегодня в
   сторе 0 пометок — арбитр v1 исполняется как **advisory-выбор + ручное/
   отложенное схлопывание** до готовности исполнителя.
2. **Исполнитель консолидации:** вердикт арбитра ≠ системное действие
   (policy §8.3): keep-запись остаётся, остальные получают могилу/ребро по
   семантике стора + пометку `merged-by-arbiter`.
3. **Реестр имён:** артефакт `vesma-cortex-merge-v2` (наследник
   `vesma-cortex-merge-v1`) — внести/верифицировать по ADR 0001/0002 до
   первого прод-использования.
4. **Операционная дисциплина** (handback cortex-operator): 6 режимов
   жизненного цикла; holdout запечатан — **экзамен v2 потрачен**; любая
   перекалибровка = новый prereg-цикл с новым holdout (CORTEX-E-PIN =
   событие перекалибровки); run-log append-only; provenance или «не было».
5. **Данные для воспроизведения:** корпус (600 + 200 + 89 кластеров,
   corpus_fp_v2 `c44c5491…`), снапшот D0 `f82da814…` (правило
   рематериализации §3.1 прега), training-скрипты ветки
   `feat/merge-arbiter-corpus-draft` (репозиторий vesma-cortex).

## 4. Границы
