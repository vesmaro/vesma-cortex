# Протокол оператора cortex — ранбук жизненного цикла модели

> **Статус:** действующий ранбук: как исполняется жизненный цикл артефактов vesma-cortex —
> корпуса, препрег-прогоны, артефакты, провенанс, перекалибровка. Границы — [ADR
> 0002](../decisions/0002-duty-registry-v2.md), продуктовые контракты —
> [чартер](../charter.md).

## 1. Роль и границы

Оператор — «руки протокола». Каждая волна жизненного цикла требует одной и той же дисциплины:
корпус с гигиеной → аддендум до прогона → single-shot прогон по запечатанному holdout →
артефакт с манифестом → провенанс. Роль существует, чтобы дисциплина не зависела от того, кто
запускает волну: замороженный протокол решает, оператор исполняет его точно и приносит числа.
Каждый апгрейд артефакта здесь — prereg-прогон с юридической силой (commit-order как
доказательство); ему нужен выделенный исполнитель, а не память о том, «как было в прошлый
раз».

Оператор **не выносит вердикт** ADOPT/DECLINE — числа докладываются дословно по замороженному
правилу препрега, вердикт выводит гейт-инстанс (владелец / TL / АрхКом; DECLINE — нормальный
честный исход, чартер §5). Оператор **не трогает engine-сторону**: `VesmaProvider`, бандл,
обработка `CORTEX-E-*`, флаг, волны W5d/W6, переименования пакетов — движковая сессия (ADR
0002); артефакт оператор производит, но нигде не устанавливает. Принцип
**advisor-not-executor** на обоих уровнях: модель — советчик дедупликации (guard-подсказка, не
автономное слияние, чартер §2), оператор — исполнитель протокола, а не источник продуктовых
решений.

## 2. Шесть режимов

| Режим | Суть | Жёсткая граница |
|---|---|---|
| `corpus` | экспорт/пересбор датасетов, синтетика, верификация | стор строго read-only; сеть только в генераторе; в репу — счётчики и фингерпринты, не raw-строки |
| `preregister` | фиксация фингерпринтов; препрег/аддендум в canon до прогона | commit-order — доказательство; пост-фактум правок нет |
| `run` | обучение, селекция, оценка | HP-поиск и early-stop только на train; holdout-оценка single-shot |
| `artifact` | ONNX-веса + манифест | веса не в git; нет манифеста — нет артефакта |
| `provenance` | цепочка «что задеплоено и откуда» | провенанс или «этого не было» |
| `recalibrate` | смена весов / ротация эмбеддера | полный prereg-цикл заново; пин в бандле не патчат |

**`corpus`.** Выгрузка из стора — `uv run cortex export-corpus` при контрактном read-only URI
(`file:...?mode=ro`; записывающий хендл — нарушение протокола). Синтетика — только через
[scripts/gen_synth_corpus.py](../../scripts/gen_synth_corpus.py), единственное место встречи
LLM-колбэка с сетью (в `src/cortex` сеть запрещена AST-tripwire); ключи — только из env.
Прицельные выгрузки B2 — [scripts/b2_targeted_export.py](../../scripts/b2_targeted_export.py).
Гигиена заморожена: секрет-скан ДО экспорта, фингерпринты после; после сборки —
[scripts/verify_dataset.py](../../scripts/verify_dataset.py). В репу — только счётчики и
фингерпринты: ни одной сырой строки стора (`/data/` в gitignore).

**`preregister`.** Перед любым прогоном, касающимся holdout, корпусный (`corpus_fingerprint`)
и лейбл-фингерпринты фиксируются в препреге и манифесте данных; препрег или аддендум
коммитится и пушится в vesma-canon (main) ДО прогона — commit-даты и есть доказательство.
Изменение протокола = аддендум первым, прогон вторым (аддендум 3
[B1-калибровки](../experiments/calibration-b1-domain-diversity.md)); пост-фактум правки
запрещены: изменилось после запечатывания — пересборка корпуса той же процедурой, событие
раскрывается в отчёте.

**`run`.** Обучение и селекция — `uv run cortex train`, `uv run cortex select`; дешёвый контур
— `make smoke` (N-лестница — `make smoke-n`). HP-поиск и early-stop — только на train. Оценка
single-shot: `uv run cortex eval` читает запечатанный holdout ровно один раз и дописывает
запись в run-log (лог коммитится — tamper-evidence); второй вход на тот же
`corpus_fingerprint` отклоняется кодом (`RunLogRefusalError` в
[src/cortex/eval/runner.py](../../src/cortex/eval/runner.py)) — это СТОП, не предупреждение;
stage2 требует явного флага `--i-know-this-is-single-shot`
([scripts/stage2_run.py](../../scripts/stage2_run.py)). Метрики — дословно по препрегу v2
(чартер §5): типизированность 100 %, sensitivity ≥ 0.90, specificity ≥ 0.90, Brier ≤ 0.25,
строго лучше baseline (косинус 0.92) по balanced accuracy, record-quality полнота 100 %.

**`artifact`.** `uv run cortex export-artifact` → ONNX-веса + манифест: `name`, `version`,
`sha256`, `embedder_pin`, `corpus_fingerprint`, `features`, `feature_set_sha256`, `size_bytes`
([inference-v1](../specs/inference-v1.md)). Веса не входят в git (`/artifacts/weights/`,
`*.onnx` — в gitignore); манифесты и run-log — входят. Нет закоммиченного манифеста —
артефакта нет.

**`provenance`.** «Что задеплоено и откуда»: манифест + sha256 от весов до корпусного и
лейбл-фингерпринта; кросс-чек ONNX `metadata_props` против манифеста —
`name == "vesma-cortex"`, совместимый мажор, `feature_set_sha256`, `embedder_pin` формата
`nano:sha256:<hex>` (inference-v1 §4). Нет манифеста и sha256 — «этого не было».

**`recalibrate`.** Смена весов или ротация эмбеддера — событие перекалибровки. `CORTEX-E-PIN`
от движка (пин ≠ живому fingerprint) — громкий триггер, а не то, что глушат: полный
prereg-цикл заново под свежим аддендумом → новая версия артефакта + манифест. Патчить пин в
бандле запрещено; engine fail-open (`CORTEX-E-*` → детерминированный провайдер) не заменяет
перекалибровку. В семье артефактов (ADR 0002 R2) пин живёт в каждом артефакте отдельно — смена
эмбеддера инвалидирует только его duty.

## 3. Пять абсолютных правил

1. **Holdout запечатан.** Лейблы holdout читает только eval-раннер, один раз на
   запечатанный фингерпринт. Физическая изоляция ассертится кодом (train-дерево =
   train-манифест, `assert_no_pair_overlap`; id-манифест —
   [data/stage2/b1/holdout-ids.json](../../data/stage2/b1/holdout-ids.json)) — её не обходят и
   «не проверяют на глазок».
2. **Аддендумы ДО прогона.** Изменения препрега пушатся в canon до прогона; commit-order —
   доказательство (аддендум 3 B1-калибровки запечатан в canon до прогона).
3. **Run-log append-only.** Каноническая single-shot запись не переписывается. Утраченный
   stdout восстанавливается только по identity-ассертам (sha256 весов и фингерпринты побайтово
   равны канонической записи) с отдельным recovery-логом — прецедент «Отклонение протокола» в
   [calibration-ds1000-a5](../experiments/calibration-ds1000-a5.md), recovery-лог
   `artifacts/runs/a5-ds1000-recovery.jsonl`.
4. **Провенанс или «не было».** Нет манифеста + sha256 — артефакта нет; нет run-log записи
   — прогона нет; каждое отклонение и восстановление раскрываются в отчёте.
5. **`CORTEX-E-PIN` — событие перекалибровки,** а не инцидент на подавление (коды
   `CORTEX-E-*` — [inference-v1](../specs/inference-v1.md); дисциплина fingerprint весов —
   ADR-0021 движка, чартер §4).

## 4. Профиль исполнителя

Роль исполняет TL-сессия vesma-cortex либо назначенный ею агент — **без web- и
agent-каналов**: канал делегации или сети в руках оператора — способ обойти prereg-гейты
(«сходи посмотри holdout») и путь утечки стора; сеть допустима только внутри штатного
генератора корпуса с ключами из env. Вся работа — через штатную тулингию репы
(`uv run cortex …`, `uv run python scripts/…`, `make smoke`, `make test`); ad-hoc скрипты
против стора запрещены. Сомнение в правиле — стоп и эскалация владельцу/TL, а не вольное
прочтение.

Каждый отчёт о прогоне несёт, без исключений:

| Поле | Что указывается |
|---|---|
| Таблица критериев | критерий / требование / факт / исход по замороженному правилу |
| Артефакт | sha256 весов + путь манифеста |
| Фингерпринты | корпусный (`corpus_fingerprint`) и лейбл-фингерпринт |
| Run-log | путь к логу прогона |

Без этих полей отчёт о прогоне неполон и гейтом не принимается.

## 5. Перечитывай, не помни

Перед каждым типом прогона перечитываются источники — работа по памяти о прошлом прогоне
запрещена: [чартер](../charter.md) (рамка, гейты, критерии),
[data-contract](../specs/data-contract.md) (фингерпринты, run-log),
[inference-v1](../specs/inference-v1.md) (артефакт, коды `CORTEX-E-*`), замороженный препрег в
canon (decision rule); по вопросам границ — что duty, что движок, что вердикт — [ADR
0002](../decisions/0002-duty-registry-v2.md) и актуальная волна
[roadmap-v2](../roadmap-v2.md).

## 6. Будущие формы

Оболочки обсуждаются отдельно — протокол первичен: **thin CLI wrapper** (`cortex ops <mode>`,
режимы как подкоманды штатного CLI; явная форма вызова, решение отдельное) и **harness-skill
форма** (навык интеграционного пака vesma; координация с integration-сессией). Пока их нет,
каноническая форма роли — этот файл; пример операционной дисциплины —
[xpu-walkthrough.md](xpu-walkthrough.md).
